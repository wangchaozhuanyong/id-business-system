# ID 业务管理系统 · 独立新版

从本目录开发。这里拥有独立的 Git 根目录、npm 清单、前端资产、启动入口和业务规则；没有关联旧仓库的 Git 历史或远端，也没有旧后台入口、旧版 API 或数据库连接。

开发与维护先读 [统一工程规则](docs/ENGINEERING_RULES.md) 和 `AGENTS.md`。本机当前不启动网站、Docker或数据库；可运行 `node test/check-ui-contract.mjs` 完成无数据库的统一回归。以下为获准运行环境的命令参考（Node.js 24或更新版本）：

```sh
npm run dev:local
npm test
```

[本机业务版](http://127.0.0.1:4348/)初次使用时库存、客户和订单为空。保存的数据和操作记录写入 `.runtime/local-business.sqlite`。数据内容加密保存，数据库与同目录的 `.key` 文件需成对保留。保存时检查版本。客户/租户的不同普通资料可按事务内原快照分别保存；同一资料冲突时停止覆盖并保留填写。订单、库存、资金及批量联动继续执行事务与版本约束，具体规则见统一工程规则。

苹果 ID 余额可登记充值和更正。苹果内购订单与已确认的余额扣款一起保存。客户实际退款与 Apple 待回款分别登记，确认到账后才增加原付款 ID 余额。银行卡实际回款也与客户退款分开记录，按原代付币种登记。

苹果隐藏邮箱支持登记主邮箱、单条登记子地址及 CSV 批量导入。已接入独立 Vendure 的连接测试、同步、收件读取、后台查询和查询码重置契约。[公开查询页](http://127.0.0.1:4348/mailbox-query)按主码或子码显示授权范围内的脱敏结果。查询与重置已使用模拟 Vendure 验证。

启用收件服务后，登记及导入先核对主邮箱及其版本，通过 Vendure 登记已在 Apple 开通的地址，回读同一主邮箱下的编号后再入库。批量写入遇到部分回执时，新版保留输入并列出未确认条目。按相同内容重试时，已在同一主邮箱登记的地址会复用，整批核对通过后一起入库。买家查询码仍由收件服务签发和管理。

早期已录入但尚未接入收件服务的隐藏邮箱，可从原记录的「更多操作 → 接入收件服务」补接。补接核对原记录、主邮箱和版本，保留库存编号、录入人、领用和操作历史。

苹果隐藏邮箱的「历史入库」供管理员补录同一主邮箱下已经注册 GPT 的地址。粘贴表格或 CSV 后先预检，填写隐藏邮箱、已核实的注册时间，已售时再填现有客户的微信、套餐、开通时间、到期时间和付款方式，备注可保留来源行号。一次保存登记邮箱使用、GPT 账号和已售订单。新登记的未售账号冻结待核，已售订单保存为待补全，后续按原凭据补齐收支。相同历史可通过预检复用。

Claude Pro／Max 的手工续费邮箱可留空，订单按独立编号保存并进入客户历史和订单统计。账号关联、快捷续费及续费提醒使用已记录的邮箱。成品交付从所选库存账号带出邮箱。

管理员可在「Claude 账号 → 历史入库」预检并登记自有账号。已开通资料保留原套餐和周期，养号资料保留已知注册时间，死号保存后进入死号页。新登记的非死号资料待核对后可按普通库存流程使用。导入以 Claude 登录邮箱去重，保留批次和操作记录，Google 邮箱及客户订单独立管理。

启用统一员工登录及独立 Vendure 后，管理员可从「管理快捷 → 邮箱提取」选择苹果隐藏邮箱。提交前和保存时分别核对可用库存、主子邮箱绑定及买家查询码。提取批次支持复制当前待使用条目的地址和查询码、逐条归还及登记实际使用。查询码按需读取，未写入本机库存、批次或审计。真实 Vendure 及实际邮箱仍需联调。

启用时需要在 `.runtime/local-apple-relay.json` 提供独立回环环境的 `adminUrl`、`apiKey` 和本机编号到 Vendure 编号的 `primaryBindings`、`aliasBindings`。按查询码查找还需要该环境的 `shopUrl`。配置文件须为当前用户的私有文件，权限 `0600`，并在启用员工登录后重启本机服务读取。应用专用密码在 Vendure 测试环境配置，系统登记页不接收密码。管理员可确认同一主邮箱最近 200 封收件记录中的单封归属，也可通过「检查历史邮件」读取该主邮箱的整组匹配统计。批量修改仍需可核对的逐封目标和版本契约，真实邮箱仍待联调。

本机业务版只监听回环地址。首次使用登录功能时，在此目录的终端运行 `npm run setup:admin`，为 `ppfzj1314@gmail.com` 设置密码，然后刷新页面。初始化前业务使用「本机操作员」身份，启用后记录实际登录账号。超级管理员可以新增、停用员工及调整角色，普通管理员管理业务，普通员工只读库存和订单。

独立本机测试站 4371 的启动器显式启用网页首次设置。首次打开即可为固定管理员邮箱设置密码，提交后用同一套本机会话登录。设置前业务接口要求登录，账号建好后首次设置入口关闭。该入口仅用于回环测试站，普通启动命令保持原有初始化方式。

订单详情的「成本与汇率」可以登记手工汇率快照。统计按各单快照分别换算并扣除客户退款、计入实际回款。外部自动汇率及充值服务单独接入。通过 `npm run dev` 可在 [设计预览](http://127.0.0.1:4347/) 查看虚构示例。

工具箱支持按账号保存个人网址和话术，在线工具保留 2FA、抖音解析。插件管理提供邮箱查询与邮箱池、网站监控。数据中心供管理员按站点查看访问统计，以及邮箱、账号、订单和客户报表的谷歌表格同步状态。数据源接入和验收见[在线工具说明](server/tools/ONLINE_TOOLS.md)。

本机启动默认关闭自动报价和代充上游。测试环境确认后可用 `npm run dev:local -- --finance-provider exchange-rate-api-open` 启用对应报价源，或传入 `--codexdaichong-url` 指定独立回环上游，代充桥接密钥由现有环境变量 `ID_RECHARGE_BRIDGE_SECRET` 注入。代充由新版员工会话验证，需先完成管理员初始化。正式供应商、独立代充服务和设备尚待实际联调。

正式站连接线上代充后，后台默认每分钟读取成功任务并自动入单，业务库按来源任务去重。已有同步范围以保存的检查点为准，首次启用从启用时间开始。「订单管理 → GPT 订单 → 代充订单同步」可查看进度、查找指定任务并按需重读。隔离运行可用 `--recharge-order-sync` 显式启用，正式站可用 `--no-recharge-order-sync` 停止定时读取。

浏览器代充的账单金额可能来自估算。同步按任务成功终态记录开通，收到可核实的实扣回执后才记实际金额。辅助资料暂时不可用时，成功单先入库，后续回执补齐原单。卡池合计用量在业务订单侧汇总。租户卡号、充值码批次和同步进度随现有 SQLite 快照备份。
