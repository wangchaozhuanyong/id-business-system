# 外围事件组件：隔离候选

这份代码仅在隔离分支开发和验证，没有接入正式网站启动入口，没有替换现有充值扫描或隐藏邮箱自动查询，也没有修改 Vendure 仓库或充值核心。用户已授权外围开发、必要依赖和受管远端隔离验证；生产配置仍另行确认。

## 已实现的边界

- `recharge_cdc.py` 独立使用 MySQL 行日志；只在 XID 提交后发送有限任务键和表类别。Session、银行卡及原始行不输出、不持久化。失败不推进位点，重启按同一来源/位点重放；源改变、日志被清理、字段映射失败或 DDL 均停止，不静默跳过。
- 首次启动在记录日志位点之后分页读取启动边界以来的任务；先确认快照再接增量，重复由现有任务来源去重处理。初始 `sinceEpochSeconds` 必须来自现有订单同步检查点，不得随意取零导入历史订单。
- `committed-jobs.mjs` 复用现有 `orderSync.run({ apply: true, jobKeys })`，每批最多6个。409忙碌等待后重试；全部批次和范围通知成功才回执。账单、码、卡及归属补全事件重新核对未完整任务。没有定时读取业务的循环。
- `vendure-mail.mjs` 消费已有 `POST /storefront-realtime/mail-events`，查询码只在正文传输。首次/恢复核对一次，心跳不查信，按事件ID去重而不按游标大小丢弃乱序提交；授权失效、格式错误、网络失效或业务读取失败立即结束。该模块尚需外围调用者接入现有绑定校验和生命周期清理，不能直接作为公开代理。

## 验证方式

本机仅运行无数据库测试：`node --test modules/external-events/*.test.mjs` 和 `python3 -B -m unittest discover -s modules/external-events -p '*_test.py'`。依赖在本工作树 `.runtime/cdc-venv` 安装，三个包使用精确版本与SHA256锁，不改主应用依赖。

`External Event Isolation` 工作流在 GitHub 临时 MySQL 8.4 服务执行合成测试：未提交与回滚不通知、19任务单事务、确认前崩溃重放、确认后重启、迟到账单、敏感字段不外发、DDL停止。该服务不接生产网络、不挂生产卷，没有真实凭据。`cdc_isolation.py` 拒绝本机执行。验证结果不能证明生产环境具备相同复制条件。

## 接正式环境前的具体待办

1. 只读核验 MySQL 版本、server UUID、ROW/FULL行映像/FULL元资料、InnoDB表、日志保留与位点、网络出口及唯一订阅编号。本候选只允许已测试的 MySQL 8；不自动更改任何数据库设置。
2. 提交独立服务的受管配置：只读账号只给目标表 SELECT、复制订阅与查看位点所需权限；私有网络或校验证书的TLS。私密配置文件0600由受管秘密系统提供，日志仅固定状态码；运行目录在所属项目内，不复制生产密码到备份。
3. 由主应用管理订阅进程，接入 `pendingJobs`、范围通知和成功回执；复用现有订单业务检查点，增加运行状态与停止清理。覆盖本地归属变化唤醒以及进程之间接续，确认完整后再替换后台扫描。
4. 隐藏邮箱消费端接入当前 `lookupQueryCode` 和本地绑定复核，连接受管 Vendure 服务验收授权撤销/别名改绑与失联；无生产写入的可用性预检先行。上游接口来源为 Vendure 的 `IcloudMailStreamController`，不新增另一个仓库的API。
5. 对生产复制设置、账号、运行配置及外围启用提交具体差异后确认。仅在确认后整合正式发布，失败时停止新组件，不自动退回定时刷新。

参考实现协议：[python-mysql-replication](https://github.com/julien-duponchelle/python-mysql-replication)。生产接入前仍须按实际版本核验依赖与复制能力。
