# 外围事件订阅

充值事件与隐藏邮箱通知接入。用户已批准必要依赖、远端隔离测试、生产只读复制账号、FULL行元数据、现有邮件事件接口接入及审查完成项正式发布。线上启用以项目 backups/ 的发布回执为准。

## 充值

- Python仅读取六张InnoDB表的MySQL 8 ROW日志，要求FULL行映像与FULL元数据。只在事务提交后发送任务键和类别，原始行、Session及银行卡不输出、不持久化。
- 沿用原入单边界，先记录日志位置再读取启动快照，业务受理和活动回读成功才确认位置。确认前故障重放；来源变化、位点失效、映射错误及DDL停止并要求核对。
- Node主应用管理子进程、私有凭据管道、串行受理和退避重连，每批最多6个任务。本地归属、码、卡及汇率资料变更唤醒待补全记录；静置没有业务查询计时器。
- 检查点仅存来源和位置，权限0600。生产连接限定回环转发并验证MySQL CA，独立账号要求TLS，不复用付款账号。
- 发布入口按三个精确SHA256锁构建Python依赖包，随确定main提交生成新制品，不改原充值镜像或203个锁定源文件。

## 隐藏邮箱

复用既有POST事件接口，查询码只在正文传输。首次和恢复核对一次，心跳不查信，按事件ID去重。父应用复核本地绑定和授权，同能力共享连接，最多6个来源、40个查看者。到期、停用或改绑关闭旧连接，通知只有不透明版本。

私有Caddy仅给原POST匹配器追加事件路径；受管主站已验证上游空请求返回预期400，无需改动其他仓库。历史格式不支持通知时明确提示，保留手动查询，不用定时查询兜底。

## 验证与发布

本机只运行无数据库单测与拦截网络的浏览器检查。External Event Isolation在GitHub临时MySQL验证事务、回滚、重放、TLS、最小权限、动态持久化元数据及DDL停止，无生产连接。

生产条件由event_prerequisites.py和event_gateway.py准备；后者默认仅验证，--apply才启用。账号或密封凭据已存在即停止，不覆盖、改密或回滚。正式入口仍为production-website-release.yml，要求最新main、质量检查、确定制品、金丝雀和生产回读。真实付款及真实收信端到端另列证据，不用合成测试冒充。
