# 列表字段核对与修复

修订：`20261104-columns-9`。依据为用户本轮粘贴的完整需求，以及此后已明确确认的订单独立、Apple ID 移至账号管理等修订。仅修改虚构资料的设计原型。

## 原因

录入字段、详情字段与表格列定义由不同函数维护，之前只完成了部分表单，扩展列表没有同步完整字段。因此 Google 的 2FA、Apple ID 的密保生日等主要是根本未定义成列，不能通过旧的隐藏设置找回。同时扩展页没有接上已有的列设置入口。旧 core 回退页面还存在默认隐藏电话、设备、2FA 等配置，本轮也已取消。

## 列设置与长字段

- 主表搜索／筛选工具栏右侧有“列设置”，与国家／来源等“本表设置”分开。
- 默认全部显示。设置窗口列出完整字段、显示列数，提供“恢复全部列”；邮箱／订单号等关键标识和操作列固定保留。
- 隐藏偏好按数据表隔离，切页返回仍保留；原型刷新重置，不接持久化存储。
- 每条记录一行，每字段独立一列。宽表在表格内部左右滚动，字段不会因为屏幕宽度不足而被自动删除。
- 标记为长文本的字段保持单行，点击查看完整内容，可复制原值。未填写字段明确留空或显示未填写，不使用脱敏星号。
- 归属人电话依据原文补入 Claude 原型表单、保存快照、详情、列表和快捷续费预填；未知历史值显示未记录。本轮没有新增正式数据库字段。

## 实际验证

浏览器已验证 Google 默认 16 个资料列、Apple 默认 18 列，均不含额外选择框。Google 2FA 可隐藏并恢复；Apple 生日可隐藏并恢复；恢复 Apple 不改变 Google 的设置。实际编辑虚构 Apple ID 的三项密保与生日，保存后四项值进入列表；横向滚动可看到生日。完整 2FA 内容查看及复制回读一致。归属人电话保存后同时出现在 Claude Max 订单和专属表。

其余库存、客户、租户、订单、专属、银行卡、代理等主表已核对列名及可见入口，无页面级横向溢出。空列表仍保留列名和列设置。390px 设置抽屉按实际可用宽度显示，完成与恢复按钮可操作；深色效果已查看。

新增 9 项库存／Apple 字段契约测试与 4 项客户／订单列契约测试；连同已有归还、余额、订单和预览服务共 45 项测试通过。共享核心的隐藏、恢复和复制使用实际页面验证，未把表格 stub 当作核心交互证据。

证据：`columns-browser-review.json`、`columns-check-results.json`、`columns-served-hashes.json` 与 `screenshots/columns-9-*.png`。旧版本验收只证明各自当时的范围，不再作为字段完整的依据。
