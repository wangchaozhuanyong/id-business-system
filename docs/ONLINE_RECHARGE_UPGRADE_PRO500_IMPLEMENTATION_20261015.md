## 当前结论

代码适配和本地静态、单元、构建及离线页面验证完成。
真实 Pro 账号、准确档位返回和实际升级扣款尚未验收；用户当前没有可提供的已开通 Pro 账号。
Pro 500 未核实标识时只能做付款前调试，普通自动付款在预检停止，不会猜一个上游 ID 后扣款。
原地升级窗口无法证明保存卡身份或本次扣款结果时，会明确停止或保留原单待核对。
因此本轮不能表述为真实 Pro 500 充值、全部升级组合或线上发布已经成功。

## 已实施

- 前后端套餐、兑换码、查询、筛选、配置、任务和账单贯通 `pro_500`；旧 `pro_5x`／`pro_20x` 及历史码保留。
- 自动分类首次开通和升级；支持矩阵覆盖 Plus 到三档 Pro、低档 Pro 到高档 Pro。同档、降档、账号错配及档位不明停止。
- 官网 Pro 选择支持实际 100／200／500 控件，并限定 Pro 卡片范围，不误点 Plus；未知目标不再回落 Plus。
- 同时适配 Checkout 与原地“确认套餐变更”窗口，按官网周期价格、折抵、税费及今天应付读取精确 Decimal 字符串。
- 已保存卡按品牌、唯一尾号及可见有效期核对；证据不足不扣官网默认卡。无须 CVC 时不强制预取，官网要求时沿原临时通道补充。
- 升级不随机绑定未使用的地址或姓名，不额外取消／恢复续费；首次开通原有策略保留。
- 受租约保护地持久化付款账号、旧／目标档位、实际卡及报价；每个新任务只允许一次付款提交。
- 付款成功、计卡、账单和原单核对均验证匹配的原付款证据；仅有通用 Pro、报价或订阅变化不能虚构扣款账单。
- 明确零应付与实际扣款分开；成功零金额升级不计卡次数、不造付款账单。
- 内部记账异常仍保留完整付款证明，原单可继续核对；严格标识字段不再被银行卡脱敏规则误改，日志及凭据脱敏保留。
- 第三方通道没有证实新档位或升级能力时提前拒绝，不猜供应商参数或暗中切换通道。
- 管理台显示可信的首次／升级、原／目标档位、官网币种与应付、待核对原因，未知金额显示未知而非 0。
