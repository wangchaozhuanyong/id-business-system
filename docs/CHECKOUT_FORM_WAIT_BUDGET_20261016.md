# 比特充值表单就绪与整轮等待预算

用户明确要求实施网页卡顿方案。本轮仅调整比特充值的付款前准备：激活已核实原页后，等待卡号、有效期和安全码三个可信控件均唯一、可用且可编辑，再开始填写。控件未就绪时只观察，不刷新页面、不重建结算、不发送付款。

表单就绪、银行卡与账单填写、账单指纹核对、官网重新计税及填后回读，共用现有本轮结算阶段剩余预算。沿用已有等待设置（默认两分钟）和上级准备总时限，任何单控件或后续核价均不能重新开满一轮。等待期间沿用已有阶段与耗时回传，无新增接口或配置。

预算到期返回原有付款字段未就绪／最终报价未就绪分类，保留原窗口与记录；取消信号沿用原任务。人工报价确认使用自己的既有五分钟时限；确认后的付款与只读核实逻辑不改变。未知原单、付款证据、唯一控件、可信来源及防重复付款校验保持。

本轮不包含此前单独定位的 Link 邮箱区域填写问题。没有新增数据库、迁移、依赖、环境变量或管理端修改，不启动本机网站、Docker 或数据库，不执行真实付款。

验证分别记录代码／纯单元检查、远端完整连接器回归、合并与空闲连接器同步、真实官网核价和取消复验。合成延迟回归不等于已在真实官网制造网络故障；实际结果以工作树 `.runtime/checkout-form-budget-20261016/` 为准。
