# 监控中心改版 · 2026-11-12

状态：代码与本地验证完成，进入用户授权的正式发布流程。设计及浏览器回归采用隔离合成资料；正式提交、部署回执和线上只读验收另记于项目内发布记录。没有发送真实测试通知或启动本机网站／数据库。

## 目标与导航

将分散在插件管理、系统设置和原监控中心的页面，集中到“监控中心”的两个子导航。

| 子导航 | 页内内容 | 常见工作 |
| --- | --- | --- |
| 网站监控 | 运行状态、告警记录、访问统计、访问记录与 IP、网站检测 | 查看异常，筛选并确认告警，查看四个站点的流量，核对访问与检测结果 |
| 监控通知 | Telegram 渠道、通知规则、投递记录 | 配置接收渠道，核对测试回执，调整规则，查询投递结果 |

管理员从网站监控子导航进入运行状态；原 `#/monitor`、`#/plugins/websites` 和 `#/settings/monitoring` 链接保留。后台仍使用既有权限，监控通知仅超级管理员可管理，普通管理员查看运行监控，员工继续使用网站检测。

## 页面方案及实现

- 运行状态：四项紧凑概览，状态和分类筛选，全宽监控项目表。完整检测依据与处置入口放入原详情抽屉，未知和未接入保留原语义。
- 告警记录：独立页签，查询条件放在表格上方。支持关键词、全部／24 小时／7 天／30 天、处置状态和级别。服务端先筛选全部保留记录再分页；保留确认、原任务和事件登记功能。
- Telegram 渠道：发送设置与接收渠道明确分区。接收编号、配置／回执状态、测试按钮逐行对应，保存集中在表单底部。代充原设置、导入及接管沿用原操作流程，手机通过既有“更多操作”菜单展开。
- 通知规则：分类筛选加全宽规则表，列出名称、分类、接收方、级别和开关。固定表头，底部保存按钮留在桌面视口内；分类切换与刷新保留未保存规则，刷新保留列表阅读位置。
- 投递记录：复用告警的查询布局，按关键词、时间和投递状态筛选。Telegram 已接收与人工阅读、告警确认继续区分。
- 访问统计：保留上一轮装修站、大马通、模钥商城、闪铸商城的站点切换、来源口径、趋势及明细、空状态和失败处理。
- 手机使用紧凑记录卡片、成组筛选和可横向浏览的页签；使用既有深浅主题与共享组件。所有用途说明放在对应标题或标签旁的 ⓘ 内，默认收起。

## 查询约定

在原 `GET /api/local/system-monitoring` 上增加只读参数：`q` 最多 100 字，`days` 为 0、1、7、30，`priority` 为告警专用 P0/P1/P2。旧请求兼容。关键词仅查已有可见字段：事件编号、名称、接收用途和脱敏任务尾号。告警按发生时间，投递按完成时间，未完成投递按创建时间。

没有新增依赖、数据库字段或表，没有修改认证、付款、检测规则、通知发送和代充执行核心。
