日期：2026-11-10。状态：代码完成、本地离线验收通过；未提交、推送或上线。与前一轮录入记录表调整保存在同一个任务工作树中，原工作区未改动。

## 原因与调整

左侧嵌入页在页签上方额外设置了整页内边距；页签与右侧地址标题又使用不同高度与字号。iframe 按自身宽度触发响应式间距，也会比宿主页面更早进入窄屏规则。

- 两侧共用 `bit-workspace-heading`，顶部栏为 76px，标题／页签使用一致的 15px 字号和 24px 行高。
- 左侧嵌入页取消额外外层内边距，顶部栏和内容区分别使用主题内边距；底色统一为内容区底色。
- 嵌入页读取宿主现有的两项面板间距令牌，窗口缩放时同步，不复制一套新主题或硬编码深浅主题颜色。独立打开继续使用自身主题规则。
- 登录／IP 资料库切换、地址查询、分页、复制、连接设置和登录草稿沿用原实现。没有新增接口、数据库表、字段、依赖或迁移。

## 后续修复：地址已保存但列表仍显示正在保存

此前在用户的线上页面只读核对到：保存请求已返回 200、没有待完成写入，但列表仍显示 0 条及“正在保存地址…”。点击列表刷新后显示未使用 9 条、已使用 1 条，共 10 条；没有重新生成地址。随后通过完整拦截的离线环境复现相同缺陷。

原因是实时版本通知使保存后的 GET 缓存请求作废，地址模块将该异常直接忽略；同时为保护表单，全局通知刷新处于等待状态，旧列表和写入提示因而残留。

本次修改：

- `frontend/bitbrowser-addresses.js`：保存回执成功后立即显示成功信息，再读取列表。读取被版本通知作废时，仅在同一视图、同一筛选且查询缓存仍登记的情况下重新读取，最多三次；不会重发生成、导入、标记或删除写入。
- 持续变更或读失败时保留已有列表，明确显示已保存结果与刷新失败原因，保留手动刷新入口。查询被替换或会话缓存被清理时不继续重读，不让迟到数据恢复到当前页面。
- `test/bitbrowser-address-refresh.browser.mjs`：新增真实共享请求缓存与实时通知链路的浏览器回归。服务端业务规则仅在内存中运行，所有请求被隔离拦截。
- `docs/DESIGN_SPEC.md` 与本记录：补充保存和刷新状态的交付规则。

没有修改接口、数据库、权限、登录或支付逻辑，没有新增依赖或迁移。
