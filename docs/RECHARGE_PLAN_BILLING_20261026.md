# 套餐联动与账单永久排重

本次修改比特浏览器充值的套餐资源选择和账单分配。银行卡累计上限继续使用现有共享池规则与系统配置，不重新实现计数。

选择 Pro 5 倍或 Pro 500 后，锁定 CL/CLP，优先选择智利移动代理；银行卡列表及自动选择沿用服务端按套餐、状态和容量筛选的可用卡，无匹配时停止。

每笔充值通过原姓名匹配接口领取原子账单分配，绑定当前身份、草稿键、银行卡和地址。新账单姓名与地址均永久排重；同草稿重复读取不消耗第二份，任务原地恢复保留身份。明确失败后主动重试领取新身份。

姓名与地址生成继续调用现有 `recharge-billing-generator.ts`，算法未改。有限姓名词表耗尽时明确报错并停止，不循环复用。地址不足时在同一事务补充100条并清理安全的已用明细；首次分配纳入现存历史指纹，之后永久保留 HMAC 指纹。历史已经删除且没有任何明细的资料无法追补指纹。

## 数据和兼容

新增 `IdBusinessV2RechargeBillingAllocation`，记录永久姓名/地址指纹、幂等键、拥有者及当前分配关联；`IdBusinessV2RechargeAddressUse.addressReference` 保留原地址编号，地址外键允许清理后为空。

独立迁移 `20261026010000_recharge_billing_uniqueness` 只建表、加列、回填原编号和调整外键，不删除现存业务数据。未来按用户单独确认的范围自动清理明细，任务、订单、使用记录和审计保持存在。运行中、未知结果、付款待激活、未绑定草稿和矛盾付款证据均保护。

既有调用端须刷新页面领取分配编号，旧页面缺少编号会收到明确刷新提示。保留最新 main 的原生直连付款、共享卡容量、人工核对与失败恢复。没有新增公开端点、依赖或应用环境变量。
