# 充值结账页调试流程（2026-11-17）

## 目的

调试必须与真实充值走同一条支付流程，只差最后一步：不点提交。历史上调试另写了一套旁路填卡逻辑，导致「调试能跑、真实充值卡在某一步」的假象。

## 现行流程

1. 会话校验用 API 请求（`context.request`），不要用页面导航——Cloudflare 只对 document 导航强制核对 `cf_clearance` 与出口 IP 的绑定。
2. 打开结账链接后，Stripe 支付区是懒加载的，需要滚动到 Payment method 并轮询等待卡号框出现。
3. 卡号填完之后，账单地址区才会渲染，必须先等它出现再填。
4. 调试入口统一调用 `completeStripeCardPayment(page, card, address, { dryRun: true })`：
   - 填卡、填免税地址、读应付金额全部照真实流程执行
   - 在点击「升级/订阅」之前返回 `dry_run_stopped_before_submit`
   - 账单地址取自系统免税地址池（`pickBillingAddressForCheckout`），不读银行卡记录
5. 结果为「未知」时，用访问令牌调用 `verifyAccountPlan` 核实账号套餐：
   - 已升级 → 判定成功
   - 仍为 free → 明确报「提交后触发人机验证（hCaptcha），付款未成立，账号未扣费」

## 验收对照

| 环节 | 期望日志 |
|---|---|
| 会话 | `[Session] Cookie 校验通过` |
| 建单 | `CHECKOUT_SOURCE: api` 或失败后回退 `ui` |
| 表单渲染 | `[调试] 等待支付表单渲染...` 后出现卡号框 |
| 填卡 | `[Stripe] ✅ 卡号/有效期/CVC 已填写` |
| 免税地址 | `[调试] 已选取美国免税账单地址: …` |
| 停提交 | `[Stripe][调试] 已完成填卡与账单地址，按要求停在提交前（未点击付款）` |
| 金额 | 免税后应付低于含税金额（例：PHP 9990 → 982.14 为 Plus；Pro 200 为 9990 → 8919.64） |

## 已知外部依赖

- 出口 IP 质量决定表单能否渲染；弱 IP 会返回 `Checkout could not be completed`，与代码无关，需更换线路重试。
- 埃及线路暂未配置时，`pro100`/`pro500` 的路由会判定不可用，发布预检会失败；此时应把路由临时指向可用国家或补上埃及代理。
