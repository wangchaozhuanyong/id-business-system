# 线上代充代理池格式识别

ChatGPT 充值 → 代理池的新增输入支持单条和批量，每行一条，最多 500 条。粘贴或离开输入框后自动规范格式，点击“保存到代理池”才写入；直接点击保存也会先校验。

| 输入 | 保存给执行器的格式 |
| --- | --- |
| `Socks5://host:1080:user:pass` | `socks5://user:pass@host:1080` |
| `host:1080:user:pass` | `socks5://user:pass@host:1080` |
| `user:pass@host:1080` | `socks5://user:pass@host:1080` |
| 完整 HTTP／HTTPS／SOCKS5 URL | 保留协议，规范地址与凭据编码 |

没有协议时默认 SOCKS5，HTTP／HTTPS 代理应明确带协议。账号国家和 session 后缀保持不变；`{session}` 占位符继续供现有执行器替换，不自动把固定会话改成随机会话，也不改变供应商的粘性或一次一换设置。特殊字符密码进行 URL 编码，保留其实际值；支持括号包围的 IPv6 地址。

空行忽略，不同写法规范后去重。任意行无法识别时整批不发送，提示原始行号，不显示原始代理、密码或提取链接内容。提取 API 链接不作为代理保存，也不会自动访问这些链接。

输入框和独立宿主服务端使用同一个纯解析函数。宿主在既有管理员及同源校验后，对原新增代理接口校验并规范整批资料，再转发给固定上游；保留 `proxies`、`proxy_url`、`proxy` 三种原有请求入口。没有新增接口、权限、表、数据库字段、迁移、依赖或环境变量，不修改固定上游源码和付款执行流程，不需要重启充值执行器。

保存失败保留输入；保存期间防止重复提交，成功响应不会清掉用户后续输入。代理原文仍只在既有输入和保存链路中使用，不进入新增日志、错误或会话草稿。

检查包括纯解析规则、服务端边界 HTTP 集成，以及桌面／手机深浅主题的离线浏览器流程：粘贴转换、混合批量去重、错误整批拒绝、保存失败重试、慢响应保护。HTTP 集成沿用远端隔离 CI，本机不启动网站或数据库，不导入用户真实代理或测试真实支付。部署结果另记录在项目 `backups/proxy-import-format-20261107/`。
