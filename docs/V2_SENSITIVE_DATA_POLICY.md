# V2 敏感资料展示与搜索策略

## 1. 目标

敏感资料的“能否访问”“如何展示”和“能否搜索”是三个独立能力：

- 基础权限决定账号是否可以访问该类资料。
- 角色展示策略决定字段在具体业务位置是不显示、脱敏、点击查看、审批查看或完整显示。
- 搜索只在服务端使用 HMAC 盲索引匹配，不依赖页面展示值；页面脱敏后仍可使用原始内容搜索。

任何展示策略都不能绕过基础权限。多角色账号按所有有效角色中的最高可见级别合并，避免低权限角色
覆盖已有工作权限；审计日志始终只记录脱敏值。

## 2. 数据分级

### 必须纳入策略的资料

| 资料                         | 存储                 | 默认展示         | 原因                         |
| ---------------------------- | -------------------- | ---------------- | ---------------------------- |
| Apple ID 账号                | 加密 + 哈希 + 盲索引 | 脱敏             | 可直接定位和登录外部账号     |
| Apple ID 密码、密保          | 加密                 | 仅点击或审批查看 | 认证凭据，禁止列表内完整展示 |
| ID 手机号                    | 加密 + 哈希 + 盲索引 | 脱敏             | 可识别个人并用于账号验证     |
| 员工账号手机号               | 加密 + 脱敏快照      | 脱敏             | 员工个人联系方式             |
| 客户手机、微信、QQ、WhatsApp | 加密 + 哈希 + 盲索引 | 脱敏             | 客户联系方式与个人信息       |
| 订单网站账号                 | 加密 + 哈希 + 盲索引 | 脱敏             | 外部平台登录标识             |
| 完整礼品卡号                 | 加密 + 哈希 + 盲索引 | 按业务位置配置   | 可兑换资产，审计中必须脱敏   |

### 不做字段脱敏的业务资料

订单号、平台订单号、客户名称、业务名称、国家、状态、业务周期、日期、金额、成本、利润、备注和
内部操作人不做字符级脱敏。这些字段是日常核对、财务追溯和责任追踪的核心条件；应通过页面权限、
导出权限和审计控制访问范围，而不是把关键业务信息变成不可核对的掩码。

客户名称在当前内部系统中作为业务识别名称完整展示。若未来开放给外包或跨组织账号，应新增独立的
数据范围权限，不能复用联系方式脱敏策略代替租户隔离。

## 3. 角色规则

### 管理员

- 业务账号、联系方式、网站账号和礼品卡号在允许的业务页面完整显示。
- 密码和密保不在列表或详情中直接展开，必须点击查看，并写敏感访问审计。
- 审计日志、通知预览和操作日志始终脱敏，管理员也不能配置为完整值。

### 员工

管理员在“角色权限”中按“字段 + 使用位置”设置：

- `不显示`：接口返回空值。
- `仅脱敏`：接口只返回掩码。
- `点击查看`：默认返回掩码，员工点击后直接查看并记录审计。
- `审批查看`：默认返回掩码，批准后在 15 分钟授权窗口内查看并记录审计。
- `完整显示`：允许业务页面直接显示；密码和密保禁止使用此模式。

角色必须先拥有字段对应的基础权限，展示策略才会生效。旧角色未设置新策略时继续兼容原有“直接查看
/审批查看”配置，保存角色后转为新的字段场景策略。

## 4. 使用位置

策略按实际会显示敏感字段的位置配置，包括 ID 资料管理、客户资料管理、续费与售后执行、业务历史
记录、导出文件和审计日志。每个字段只开放真实使用的位置，避免出现配置项已保存但页面没有对应行为。

## 5. 脱敏搜索

搜索请求仍提交员工输入的原始查询词，但服务端不使用页面掩码查询，也不把解密明文写入数据库：

1. 写入或历史回填时，将规范化内容拆成连续 2 元和 3 元片段。
2. 使用服务端 `HASH_SECRET` 和字段命名空间生成 HMAC 盲索引，数据库只保存不可逆令牌。
3. 查询时按相同规则生成令牌，通过 GIN 索引筛选候选记录。
4. 需要消除片段碰撞的列表在服务端解密候选值后二次核对，再按展示策略返回完整值、掩码或空值。

因此搜索与展示互不依赖：员工看到 `13****8000` 时，仍可输入原手机号中连续 2 个以上字符进行匹配；
响应中不返回盲索引或未经授权的明文。不同字段使用独立命名空间，手机号令牌不能用于匹配礼品卡号。

## 6. 接口与数据库

- 角色创建和修改接口新增 `sensitiveDisplayPolicies`，角色启动数据新增策略目录和中文模式标签。
- 客户手机号、微信、QQ、WhatsApp 均提供受控查看能力；每次实际查看继续写审计。
- 新增 `id_business_v2_sensitive_display_policies` 表，唯一键为角色、字段和使用位置。
- 账号手机号、客户联系方式、礼品卡号新增盲索引字段；客户微信和 QQ 从历史明文迁移为加密存储。
- 员工账号手机号使用 `users.phone_encrypted` 加密保存、`users.phone_masked` 默认展示；当前系统不提供
  员工手机号录入、搜索或完整查看接口，个人资料接口只读取脱敏快照。
- 新权限 `apple.order.view_website_account` 单独控制订单网站账号。

## 7. 上线顺序

1. 备份数据库并确认 `FIELD_ENCRYPTION_KEY`、`HASH_SECRET` 与现网加密配置一致。
2. 部署 migration `20260814020000_sensitive_search_blind_indexes`、
   `20260814030000_sensitive_display_policies` 和
   `20260814031000_sensitive_contact_search_indexes`。
3. 部署兼容新旧数据的 API。
4. 本地或受控环境执行 `npm run backfill:v2-sensitive-search-indexes`；生产环境执行
   `npm run backfill:v2-sensitive-search-indexes:production`。命令可重复执行，直至缺失索引和客户
   微信、QQ 历史明文计数均为 0。
5. 部署管理端，逐个员工角色确认字段与使用位置策略。
6. 验收管理员、员工、无基础权限员工的展示、点击查看、审批查看、搜索、导出和审计结果。

历史回填会读取并重新加密敏感值，必须使用与生产数据匹配的密钥；密钥不匹配时应停止发布，不能用空值
覆盖或跳过失败记录。

员工账号手机号由增量 migration `20260815120000_encrypt_user_phone` 增加密文与脱敏字段。生产固定
migration 命令会紧接结构迁移执行 `backfill:user-phone`，逐条验证已有密文或使用现网密钥加密历史值，
随后清空旧明文并验证数据库禁止明文约束；不需要也不允许另行使用临时生产命令回填。
