# 独立比特浏览器注册连接器

此模式在操作人的 Mac 上控制已安装的比特浏览器，通过官网可见表单完成注册。服务端仍管理任务、邮箱验证码、加密密码与账号同步；不会在 Mac 上启动网站或数据库，也不会导入或重启充值执行器。

## 安装与启动

前提：比特浏览器已开启本机 API，管理端已保存对应地址和 API 密钥；本机已有 Python 3.11+ 的 Playwright 虚拟环境。脚本优先复用当前项目 `.runtime/bitbrowser-recharge-assistant/venv`，隔离 worktree 缺失时通过 Git common-dir 查找主项目同一路径，最后查找已安装的 `~/Library/Application Support/IDBusinessV2AutoRechargeConnector/venv`。只复用 Python 与 Playwright，不安装、升级或修改充值依赖，不加载充值执行器。

在项目目录运行，把来源替换为实际管理端的精确 HTTPS 来源：

```sh
sh scripts/start-auto-registration-connector.sh --allowed-origin=https://管理端域名
```

连接器只监听 `127.0.0.1:55324`。它要求精确 Host 和允许的 Origin，默认拒绝本机开发来源、通配符、跨来源回调及重定向。健康标识为 `id-business-v2-auto-registration-connector`，版本 `1`。

管理端启动时只传本次任务编号、短期启动凭据和固定回调地址。密码通过 HTTPS 领取，保留在当前进程内存；不进入启动参数、页面 URL、日志或本机文件。相同任务重复启动只确认已有执行，不再注册。

## 官网流程与人工接管

每次任务新建独立比特窗口，不附加充值窗口；使用服务端本次解析的固定代理，不读取充值的默认代理、动态换 IP 或重试设置。任务未配置代理时明确报告本机直连。窗口关闭账号同步、Cookie/存储同步和密码保存服务。

只在官方来源、唯一可见的对应表单内自动填写邮箱、密码和邮箱验证码。密码提交必须先得到服务端持久化确认；确认失败时不会提交。人机验证交给官网自己的脚本和操作人处理，不读取挑战 token，不运行求解器，不修改指纹或验证请求。当前服务端不提供姓名、生日，个人资料页需要本人在原窗口真实填写；连接器等待并观察后续创建结果。以后仅在明确取得本人资料且控件能可靠识别时才可自动填写，不会虚构生日，也不设置双重验证。

只有同窗观察到官方创建接口返回有效、无错误的 JSON，并在官网会话中取得完整邮箱一致的身份与凭据，才向服务端回传结果。服务端还须独立核实、加密保存并同步主台账；页面变化、超时或身份不一致均不能记为注册成功。

自动化结束保留比特窗口；发生可能已创建但回传未确认的情况，不自动换邮箱或重试。重启连接器不会自动恢复旧任务，需要先在管理端核查原任务和账号结果。

## 纯测试

```sh
cd apps/api/src/id-business-v2/auto-registration/worker
python3 -B -m unittest test_browser_registration_connector.py
```

测试使用合成数据与假浏览器，不连接网络或数据库。真实官网验收、远端持久化检查和正式发布须分别登记，纯测试通过不代表已经成功注册。
