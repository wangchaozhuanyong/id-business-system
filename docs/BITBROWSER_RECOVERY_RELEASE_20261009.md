# 比特浏览器恢复修复独立发布

用户于 2026-10-09 明确要求本窗口修复单独发布，替代此前不提交、推送和部署的限制。
范围仅为自动充值的原窗口恢复、JSON 登录页面同步、连接与核价等待补修，以及移除软件最高付款限制。
不包含其他窗口的自动注册、线上代充、共享样式、依赖及发布控制候选。

## 最终行为

- JSON 会话身份核实后，继续等待官网实际账号菜单；未同步时在原预算内只刷新原标签页一次，再核对账号。
- 官网网络故障先恢复页面；确需更新动态代理时关闭并核实原进程退出，以同一窗口 ID 重新提取 IP。首次在内最多 10 次，自动准备至核价总预算 10 分钟，可取消。
- 任务再次执行复用当前操作人与账号的原窗口；资料被删除、身份不符、原单记录不完整时停止。已有订单只恢复原单，付款发出或结果未知不自动重试。
- 原窗口及报价的读取、刷新、填写和迟到回执均受剩余预算约束，取消保留已核实的原订单事实。
- 删除最高付款输入和软件金额上限比较，兼容忽略旧上限字段；保留完整官网报价、锁定币种、人工确认与防重复付款。服务器历史缺失/关闭确认标记也不自动确认。

## 只读预检与发布阻挡

2026-10-09 的 [只读预检 run 37927472232](https://github.com/wangchaozhuanyong/id-business-system/actions/runs/37927472232) 在 preflight 阶段失败，受控错误码为 `API_ADMIN_WORKSPACE_SQLITE_BACKUP_REQUIRED`。
线上仍为已验证基线 `0a03fa28e6b844a18833d5c63f1de700f091fc64`；本次没有停止服务、切换生产版本或付款。

非空注册工作区需要受控 SQLite 一致性备份和可信静止证明。现有数据库 `pending/running=0` 不能单独证明可以安全停止 API：

- 上游 Outlook 批量入口先在内存中受理，再由后台提交任务，数据库中可能尚无记录。
- 取消接口只修改数据库状态，未等待执行线程结束；已取消任务还能被删除，所以数据库可能没有活动记录，但线程仍在执行。
- 已发布工作区健康接口没有内存批次、后台队列或执行器排空证明；仅以数据库计数和写锁停机，可能丢失已受理批次或打断现有执行。

因此保留原安全门禁，不清空或删除原卷、不绕过检查、不强杀任务。未完成的发布控制草稿已撤回，本窗口没有引入注册业务、数据库或发布控制修改。
