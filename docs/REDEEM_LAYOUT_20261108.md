# 兑换开通页面布局

## 范围

整理独立打开和管理后台嵌入的「ChatGPT 兑换开通」页，保留固定上游
`codexdaichong@f4d7761e0036892e6dd68ec64c5447b513ca37da`。仅修改外围 HTML、样式和标题说明挂载；
不改兑换码验证、账号解析、套餐锁、任务提交、付款、重试、接口、数据库或环境变量。

## 页面结构

- 页名与说明按钮同排；页签、当前状态和发票助手组成统一操作栏，手机自然换行。
- 「验证兑换码」与「填写账号并提交」使用相同宽度、边距和标签轨道，标签始终位于控件左侧。
- 账号使用说明和资料获取入口收进第二步标题右侧的说明按钮；校验结果保留在输入框下方。
- 目标账号、确认套餐和充值提交收在同一操作区；手机改为单列，按钮保留 44px 触控高度。
- 查询及使用说明页签沿用相同边界；嵌入模式使用宿主标题，避免重复页名。

## 验证方式

`test/redeem-layout.browser.mjs` 使用请求拦截和虚构资料，不启动本机网站或数据库，不提交充值任务。
覆盖 1440、1024、768、390、320px 的深浅主题，另覆盖后台嵌入的桌面和手机状态；检查控件对齐、
无横向溢出、空表单禁用、说明展开不移动内容、资料获取入口、验码后状态、账号校验及切页保留输入。
共享布局和慢加载／连续切页／失败恢复沿用 `test/shared-layout.browser.mjs` 与
`test/recharge-layout-transitions.browser.mjs`。

项目使用原生 ESM，未定义独立 typecheck、lint 或 build 命令。语法使用 `node --check`，
生产静态资源由 `modules/recharge/codexdaichong/assets.mjs` 从确定提交生成；完整隔离套件在远端 CI 运行。
真实兑换码、账号授权与付款不属于页面布局验收。
