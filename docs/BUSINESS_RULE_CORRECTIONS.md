## 1. 用户最新确认的租金口径

租金发放页只方便记录“有没有发租金”。租金成本已计入费用，不需要再次记录金额或币种。

- 发放记录包含：对应账号、收租对象、期间、待发放／已发放／失败／取消状态、发放时间、备注与操作历史。
- 一批多条逐项处理，可以只有部分完成。失败项可继续处理，不重记已经完成项。
- 发放登记不执行转账，不新增订单成本，不改变 50 MYR 的 KYC 认证成本和 100 MYR 的代付服务费，也不重复扣利润。
- 成本由费用设置及订单费用快照管理。缺实际成本、汇率、收付款证据时仍待核算，但不能因为没有登记发租金就把完整订单算作资料缺失。

此口径取代此前“租金金额／币种必填”和“租金是否包含未确认”的设计。

## 2. 七项页面规则

| 规则               | 页面中的体现                                                   | 必须保护的事实                                                 |
| ------------------ | -------------------------------------------------------------- | -------------------------------------------------------------- |
| 注册时间与录入时间 | 主档、详情和导入预览分别显示；注册时间可未知，录入时间系统只读 | 养号只用实际注册时间；未知不自动填今天，不判为可用             |
| 资产类型人工确认   | 新增明确选择，批量预检逐行展示最终类型并允许修正               | Gmail 地址可以是 Apple ID，域名识别只能给建议                  |
| 独立订单状态       | 代付、资料完整性、订阅、退款、账号运营分别展示                 | 部分退款不自动终止订阅，冻结不改写付款成功                     |
| 续费新增单         | 客户邮箱直接创建新单；仅 Claude 专属可带当前资料并续接到期     | 不要求通用原单关联、邮箱分类或重复的实际开通字段；历史单不覆盖 |
| 银行卡稳定编号     | 手工尾号匹配共享池，同尾号时明确选稳定 ID；自动任务沿用 cardId | 尾六位只是显示／搜索，开卡费依据稳定卡 ID 只计一次             |
| 逐项租金发放       | 对象、账号、期间、发放结果、时间、备注，不录金额               | 发放记录只影响操作台账，不重复记成本                           |
| 分离业务操作       | 归还、更正、更正撤回、退款、撤单各有独立确认和历史             | 不清除真实注册／付款／退款／后续续费，不借撤单释放库存         |

## 3. 本轮验证用例

1. 新录入旧 Claude 账号：录入时间为当前时间，注册时间为旧日期，养号按旧日期计算；未提供注册时间时显示未知并禁止提取。
2. 在 Apple ID 页面录入 Gmail 地址，最终资产仍为 Apple ID；导入时逐行改类型后重新预检，不静默改回识别建议。
3. 一笔订单同时保留付款成功、资料待补全、订阅有效、部分退款及账号冻结，任一状态变化不覆盖其他状态。
4. 客户邮箱不在本地库存且没有历史订单，也能直接提交独立续费单；GPT 无原单续费操作。Claude 专属快捷续费新增订单并更新当前到期，旧单不覆盖。
5. 输入共享池两张卡相同尾号时不自动选卡，人工选定稳定 ID；充值任务带来的稳定 ID 原样进入订单，重复订单不再重复计开卡费。
6. 选择两个账号生成租金发放批次，不填写金额／币种；只登记其中一条已发放，另一条仍待发放，批次部分完成，订单成本不变。
7. 更正撤回检查原版本及后续变化；退款限制累计金额；已有实付、实收、退款、任务或续费的订单不能直接撤单；有使用来源的资料不能当作未使用归还。
8. 页面保持紧凑分栏、左侧标签、标题说明图标；桌面与手机、深浅主题、关闭重开与切页返回均需抽查。
