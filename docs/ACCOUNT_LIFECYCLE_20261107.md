# GPT／Claude 账号使用、续费与回收

适用项目：本目录的独立新版 ID 业务管理系统。仅处理人工录入的系统自有 GPT／Claude 账号；客户提供账号不转为库存。此记录是源码实现与隔离验证记录，不表示已部署或已操作真实账号。

## 操作入口和结果

账号管理 → GPT 账号／Claude 账号 → 已使用 → 更多操作，或进入详情“账号使用与回收”。管理员可选择：

| 操作 | 结果 | 历史资料 |
| --- | --- | --- |
| 原客户续费 | 提交独立续费订单，账号仍为已使用 | 原订单及费用快照保留，追加续费关联与记录 |
| 恢复可用库存 | 结束本轮客户占用，进入可用库存，标注“回收复用” | 账号编号、注册资料、密码、订单、付款、KYC、领用和审计保留 |
| 停止复用 | 结束本轮客户占用，仍在已使用，标注“不再复用” | 全部历史保留，不推荐直接续费或再次交付 |
| 回收后成品交付 | 明确选择该可用账号，分配给当前所选客户，进入新一轮使用 | 原客户资料和订单继续可查，不覆盖原付款及认证人 |

到期只显示“到期待处理”，不会自动变成可用。停止复用后若改变决定，仍需重新核对并执行“恢复可用库存”。这些操作只登记系统内使用关系，不执行平台退订、真实退款、密码更改或自动联系客户。

## 回收前核对

填写原因，确认账号控制权、原客户访问已处理、执行任务及付款结果已核对。订阅未到期时必须明确勾选提前结束。异常账号不能直接恢复可用；存在关联执行任务、未知付款结果或多个未结束客户归属时阻止操作。

普通“未使用归还”仍只处理已提取且本轮尚未使用的资料。历史使用账号必须通过专用入口回收，不能通过改状态、删订单、改成客户自有来源或伪造回收字段绕过。旧批次及使用关联不删除，回收后重新提取但未使用的账号可按原归还流程处理。

## 续费与资料展示

选择客户后，仍按该客户最近订阅时间推荐邮箱，不提高当前产品旧邮箱的优先级。已明确对应系统库存的邮箱，还需核对产品、唯一库存身份和当前客户。已回收、已停止复用、归属待核对或已转给其他客户的邮箱保留历史展示，但不自动推荐为可续费邮箱，手填也不能绕过服务端校验。

没有匹配系统库存的客户邮箱可独立建立续费订单，不自动创建库存。原有明确库存关联的订单不能通过普通更正替换账号、产品、业务类型或客户。管理员结束使用后，原关系从当前订阅与续费提醒中退出，原订单记录仍保留。

可用库存列表及详情展示使用情况、当前客户、库存用途和最近回收时间。Claude 详情展示历史 KYC、认证人、电话、租户及来源订单，并将回收后的当前 KYC 标为“待重新核实”。历史订单表每项独立列、单行显示，包含付款方式、账号／尾号、原代付金额、确认状态和原订单入口。历史认证不等于当前认证仍然有效。

## 接口与存储

- 新增 `PUT /api/local/inventory/account-lifecycle`，复用现有管理员权限、同源校验、加密文档、事务和审计。
- 请求携带库存文档版本、订单文档版本、账号版本和唯一操作编号；相同编号及内容重试返回原结果，不重复回收。任一资料变化返回冲突，要求显式重新核对。
- 在现有加密库存账号文档新增 `accountLifecycle` 与 `accountLifecycleEvents`；订单沿用既有 `accountId`、`accountSource`，续费追加使用关联。没有新增数据库表、SQL 字段、环境变量、依赖或迁移。
- 库存读取及保存响应附带从现有订单推导的 `accountSummaries` 和订单版本。历史不明时不按相同邮箱猜 KYC 或客户归属。
- 同一保存事务内校验归属、确认交付并追加生命周期记录；服务器内部生成的字段不接受普通库存保存伪造。
- 抽屉按账号与操作分别保留当前会话草稿。版本冲突保留原因，显式重新核对后重置确认项；迟到响应不清除新操作草稿。
