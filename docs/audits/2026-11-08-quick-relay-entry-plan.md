# 快捷邮箱录入增加苹果隐藏邮箱：设计方案

实施补充：本方案已在后续授权中落实，当前行为、文件、验证与未完成范围见 [续做交付记录](2026-11-08-follow-through.md)。下文保留原规划／诊断证据。

日期：2026-11-08。状态：只读核查与方案完成，未修改功能、权限或线上资料，未提交、推送或部署。

## 本轮用户要求

- 快捷操作的邮箱录入页增加苹果隐藏邮箱录入入口。
- 快捷操作以后主要供员工账号完成业务，员工一般不进入其他管理栏目。
- 本轮只规划录入流程与后续衔接，权限单独开发，不现在修改菜单可见性、角色、接口授权或数据范围。

## 当前源码核查

所属项目为独立新版 `id-business-independent-redesign`，分支 `codex/customer-email-product-isolation-20261108`，HEAD `43aed364f063c8e1572f72a13c99119edfa5d2ac`。本轮保留全部既有未提交修改。

1. 快捷入口实际路由是 `workspace/mail-submit`，当前页面名为“邮箱提交”。`frontend/inventory-prototype.js` 的 `submissionPage()` 从 `mailboxWorkflowTypes()` 获取可录入类型。
2. `mailboxWorkflowTypes()` 在正式数据模式下排除 `relay`。这会使快捷页不出现隐藏邮箱入口，与离线示例模式的表现不同。其同时服务提取等路径，后续不能简单删除全局过滤便宣称完成。
3. 单条隐藏邮箱已经由 `assetEditor()` 转交 `appleRelay.openAliasEditor()`；批导也由 `importEditor('relay')` 转交 `openAliasImport()`。已有管理模块支持主邮箱搜索、登记、预检、导入、草稿、保存及结果回读，应复用。
4. 当前主邮箱选择来自库存中的主邮箱集合；后续员工入口需要独立核对可选主邮箱的数据范围，不能把管理员主邮箱全集直接当作员工可选项。
5. `server/apple-relay/local-service.mjs` 对隐藏邮箱登记调用 `requireAdministrator()`。只增加前端按钮不会让员工可用，本方案不改变该校验。员工启用留待后续权限阶段。

业务依据沿用 `docs/APPLE_RELAY_REVISION.md` 与现有 `server/apple-relay/alias-registration.mjs`：必须关联真实、已接入且正常的主邮箱；登记的是已在 Apple 开通并转发到该主邮箱的地址，收件服务登记不等于在 Apple 自动创建隐藏地址。

## 入口与页面布局

在“快捷操作 → 邮箱提交（用户所称邮箱录入）”现有录入区中增加“苹果隐藏邮箱”，沿用同一 `submission-grid`，与其他已启用邮箱类型等宽排列；容器不足时自然换行。

该区提供两个入口：**单条录入**、**批量导入**。新增主邮箱、授权密码、连接测试、主查询码重置、历史邮件归属修复等仍属于管理模块。

录入、预检、结果查看全部在当前页的右侧抽屉完成。员工流程不依赖点击“主邮箱管理”跳到其他栏目；不要把一个当前不可见或未来无权访问的管理路由作为必经步骤。

建议流程：选择苹果隐藏邮箱 → 单条录入／批量导入 → 选择已配置主邮箱 → 填写并核对地址 → 保存／导入 → 当前页展示本次结果 → 继续录入。

## 单条录入抽屉

标题“新增苹果隐藏邮箱”，用途说明收进标题右侧说明按钮；标签在控件左侧。底部固定“取消”“核对并保存”，保存中防重复提交，失败保留可重试输入。

| 内容 | 规则 |
| --- | --- |
| 所属主邮箱 | 必填，可按地址／稳定编号搜索并明确选中。只有一个可用项时可自动带入并保持可见；多个时不擅自猜测归属 |
| 隐藏邮箱地址 | 必填，填写已有地址；沿用现有邮箱合法性、重复检查及主邮箱关联验证，不只接受某个固定域名 |
| 查询码有效天数 | 沿用现有默认 30 天和现有校验，不新增另一套有效期配置；文案说明它控制查询码有效期，不是 Apple 地址寿命 |
| 备注 | 选填，宽度充足时与短字段合理同排，长内容跨列 |
| 录入人、录入时间、编号 | 系统记录，不允许手填冒充其他人员 |

隐藏邮箱沿用自己的字段模型，不套用谷歌邮箱的独立密码、2FA、绑定电话等资料。主邮箱应用专用密码和主查询码不进入该录入表单。

主邮箱前提按现有业务处理：管理员先完成主邮箱收信连接配置，录入人员再选择它；没有可用主邮箱时在当前抽屉说明“暂无可用主邮箱，请联系管理员配置”，保留输入与重新读取入口。不临时创建无父级的孤立隐藏邮箱，不将任意文本编号当作有效主邮箱。

## 批量导入抽屉

- 先选所属主邮箱，一批属于同一个主邮箱；沿用现有有效天数、粘贴列表及 CSV 文件入口。
- 支持“邮箱,备注”及现有表头规则。沿用现有限制和重复检测，先预检，再确认导入；更换主邮箱或导入内容后，旧预检结果失效。
- 展示行号、地址、备注及可导入／重复／格式错误／失败原因，明确返回新增、跳过与失败统计，失败行可修正重试。
- 保存回执不明时先核对原批次与地址，沿用原服务的回读／复用机制，不整批盲目重建，也不静默更换主邮箱。

## 保存后与管理页的关系

- 管理页、快捷单条与批量入口共用登记服务、子邮箱编号、主子关系及库存资料，不新增员工专属邮箱库或另一套表单校验。
- 只有服务端和收件服务确认后的结果才表示登记成功，失败保留草稿；保存成功仍停留快捷页。
- 本次结果采用紧凑表格：隐藏邮箱、所属主邮箱、登记结果、录入时间、操作。提供“复制邮箱地址”“继续录入”；成功回执中的主邮箱信息只显示本次已选择的必要信息。
- 查询码复制、收件读取、提取归还继续沿用各自业务入口，不因新增录入按钮自动授予这些能力。
- 本次结果不依赖后台完整库存列表才能查看。未来“我的近期录入”按实际登录身份查询，不能仅在前端过滤管理员收到的全量数据。

## 后续权限阶段的衔接，仅登记、不实现

本次确认的是“快捷操作为员工主要工作入口”的产品方向，不在这一轮设定或实现完整权限矩阵。

后续权限开发应一起覆盖：员工可见快捷功能、单条与批导操作授权、可选主邮箱范围、本人与他人记录的读取范围、子查询码和收件操作的独立授权、直接访问 URL／接口的校验，以及身份切换后草稿和缓存清理。默认不依赖员工进入管理或系统设置栏目，例外功能届时单独配置。

入口、表单与保存服务可以复用，员工收到的主邮箱选项与提交结果应只含所需数据；保留现有人员审计。不得为了让新按钮可用而取消管理员检查、向员工下发主邮箱秘密，或提前放开整个库存写入接口。

阶段区分：①当前方案；②后续录入入口与共享流程实现，在现有授权范围内验收；③单独开发员工权限与数据范围后，再验收员工实际可用。不能把管理员使用新入口成功当作员工验收通过。

## 拟修改落点与验收

后续实现优先复用 `frontend/inventory-prototype.js` 的录入入口和类型选择、`frontend/apple-relay-prototype.js` 的编辑／批导抽屉、`frontend/prototype.css` 的现有网格和共享布局；登记继续复用 `server/apple-relay/` 的既有主子邮箱逻辑，不在本轮新增接口、表或字段。

录入入口与提取类型的过滤分别核对，避免展示新增卡片时顺便改变员工提取范围。批导、单条、管理页按同一组验证：主邮箱为空／不可用、搜索选择、单条重复、跨主邮箱冲突、批量预检及部分失败、服务失败和回执不明、保存后原页回填、关闭重开草稿、来源人员、桌面／手机深浅主题。权限验收留到单独授权的后续任务。

本轮实际仅阅读相关入口、现有主子邮箱表单、登记服务与设计文档，并新增本文；未启动本机网站、数据库或 Docker，未调用真实邮箱服务，未进行功能或权限测试。
