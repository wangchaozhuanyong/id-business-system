# 租户归属规则接入记录

日期：2026-11-08。状态：代码完成、无数据库本地验证完成；未提交、推送或部署，未修改线上资料。

## 范围与行为

- 普通租户录入、列表新增抽屉及 Claude 录单快捷新增统一复用订单的员工选择控件和现有 `GET /api/local/auth/order-owners`。
- 新增默认当前登录人。管理员和超管可搜索选择启用的系统员工；员工归属规则固定自己，服务端拒绝指定其他人员。既有模块访问权限保持原样：当前普通员工没有租户录入页面访问权，本次没有扩大该权限。
- 新租户保存 `ownerId` 员工编号和 `owner` 姓名快照，服务端按实时目录确认姓名、角色及启用状态，不信任客户端提交的归属文字。
- 业务归属、录入人和修改人分别记录。租户新增时即使客户端省略或伪造录入、修改字段，服务端仍写入实际操作者；修改时保留原录入字段。
- 按订单已有规则，已保存租户的归属只读保留。历史租户不按姓名自动补绑，未知录入人不补造。租户资料的保存不更改历史订单归属。
- 员工目录刷新、失效选择提示、保存失败、关闭和切页保留草稿。快捷新增后自动选中新租户，订单原归属和输入保持独立。

## 后续修订：管理员独立转交租户归属

用户审查确认租户归属与订单归属应独立，随后授权补充管理员转交租户归属。此轮基于已发布的 `60031f804f2a51eaf6c3d14ef6479a078d4871f8`，工作树为项目内 `.codex-worktrees/tenant-owner-transfer-20261108`，分支 `codex/tenant-owner-transfer-20261108`。原工作区保留，不修改员工模块访问范围。

- 租户列表“更多操作”和租户详情增加“转交归属”，使用现有右侧抽屉、员工选择与会话草稿。管理员／超管选择启用员工，必填转交原因；历史文字归属可经明确选择补绑编号，不根据姓名猜测。
- 新增 `GET /api/local/tenant-owner-transfer?tenantId=...` 读取当前归属和交接历史；同路径 `POST` 只接受 `tenantId`、`ownerId`、`version`、`tenantVersion`、`reason`、`operationId`，按现有会话及同源规则校验。保存时在既有事务内读取最新资料和员工目录。
- 新增纯规则模块 `server/tenant-owner-transfer.mjs`，由 `server/local-business.mjs` 将归属、修改人、版本、交接记录和审计同事务提交。原录入人、订单、银行卡及付租记录保持；不会让新单自动继承租户负责人。
- 租户既有加密 JSON 记录增加 `ownerTransfers`，保存前后员工编号／姓名快照、操作人、原因、时间及操作编号。普通资料保存不能伪造、改写或删除该历史；有交接历史的租户可停用，不能通过普通保存删除整条资料。无新增数据库表、列、依赖或环境变量，无需结构迁移。
- 业务文档和租户版本同时检查；相同归属、停用／不存在的员工及员工越权均拒绝。操作编号持久化用于丢失回包重试，已记录操作回读同一回执，不重复转交或审计。未知结果先核对原操作，不能通过“读取最新”跳过核对建立新操作。
- 关闭保留输入；读取最新保留目标及原因但重新建立核对依据；旧回包不清除其他租户草稿，并更新列表上的当前归属。
