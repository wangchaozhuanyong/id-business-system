## 必须单独批准的原因

本候选 `AGENTS.md` 的自动充值核心边界禁止“以……辅助功能改变……状态或资源占用行为”。已批准例外只覆盖套餐选路。当前原版仅有普通删除码操作，没有与兑码竞争互斥的原子撤销和可恢复回执；外围删除列表记录或隐藏按钮不能闭环。

## 拟批准范围

1. 在原版 `mysql-store.js` 增加专用未使用码失效方法，在 `server.js` 增加仅供可信服务访问的资格核对、原子失效与原操作回读接口。保留现有充值执行路径。
2. 新增只用于幂等失效回执的附属表。具体 migration 在执行前形成可审阅差异；只新增，不修改或清空旧表。回执绑定稳定操作编号与原码，不记录 Session、银行卡或客户密码。
3. 原子操作在同一 MySQL 事务内锁定原码，确认本系统可追溯发放、套餐一致、未交付、未使用、无任何历史充值任务或人工待核对关联后，置为永久不可用并落回执。存在历史尝试的码先保守阻止归还，不按失败或 unused 猜测付款结果。
4. 与既有 `markCdkUsed()` 的条件更新竞争同一码锁；最多一方成功。已受理任务不取消、不改写；失效成功的旧码不恢复、不原样转交另一人。
5. 更新原版精确差异清单、补丁和批准后哈希；继续核验全部原版追踪文件，不能把整份文件从核验中排除。

此例外不包含付款、换卡、Session、Checkout 步骤、重试、任务停止、订阅变更或外部通知；不包含提交、推送、部署和生产迁移。
