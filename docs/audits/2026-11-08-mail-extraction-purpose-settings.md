# 邮箱提取用途设置

2026-11-08。状态：代码完成、本地离线验证完成；未提交、推送或部署，未修改线上资料及权限。

## 用户可见变化

- 在“快捷操作 → 邮箱提取”的“提取用途”下拉右侧增加“设置”按钮，与控件同排，复用现有按钮、标签和内嵌控件布局。
- 右侧抽屉支持添加、编辑和移除用途，沿用共享项目编辑器；至少保留一个用途，拒绝重复、无效或未完成编辑的项目。
- 未配置时沿用“注册 Claude、注册 GPT、业务备用、其他”。保留“其他”选项原有的具体用途输入逻辑。
- 仅管理邮箱提取用途；账号提取仍沿用自己的既有选项，不混用配置。
- 删除用途只影响后续选择，不改写任何历史批次、库存用途、实际使用或归还记录。旧提取草稿选中的用途被删除时，明确要求重新选择，不静默换成首项。
- 抽屉关闭后保留用途草稿，保存失败保留输入；版本变化拒绝旧草稿覆盖，用户可显式“重新读取”最新清单。读取失败和迟到读取不清除后续输入。

## 保存及兼容

复用现有库存文档的 `tableSettings`，新增配置条目 `mail-extraction: { purposes: string[] }`，序列化形式仍是既有键值数组。正式数据模式调用原有 `PUT /api/local/inventory`，操作沿用已有审计动作 `inventory_table_settings`；通过现有加密库存持久化通道保存，不新增前端浏览器存储。

服务端新增纯校验，拒绝空清单、重复配置条目、重复用途、控制字符及越界值。旧库存没有该条目时兼容原默认选项。采用现有文档版本检查与保存事务，不建立新的配置服务或数据库表。

无新增 HTTP 接口、数据库表／列、环境变量或 migration。部署该功能时前后端应一同包含新校验文件；不需要执行数据库结构迁移。历史批次不回填、不重命名。
