## 已确认的问题与改造范围

### 第一批：列表页首合并

宽屏可使用一行；空间不足时按控件组自然换行，不能按视口宽度机械认定全部页面都能合并。

| 客户流失 | 两个短页签后，280px 搜索单独占 72px 行 | 左侧客户流失／待核对，右侧搜索 |
| 续费管理 | 状态页签与搜索、产品筛选、提醒设置分开 | 左侧状态，右侧搜索、产品、提醒设置；提醒周期随设置就近呈现 |
| 客户数据、租户数据 | 使用中／已停用单独一行；搜索及新增在第二行 | 左侧状态，右侧搜索、现有设置／列设置、新增；客户和租户各自保留功能 |
| GPT、Claude Pro、Claude Max 订单 | 四个页签与搜索、列设置、数据统计、录单按钮分开 | 左侧状态，右侧搜索及操作，录单主按钮最靠右 |

### 本轮不需要为紧凑而改动的区域

苹果 ID 余额、邮箱分类、操作记录已经将搜索与按钮放在同一工具栏；不再重复改版。现有统计摘要带、业务表单、实际预览和结果区按内容保留。空结果后页面剩余背景属于内容自然高度，不拉长表格或加入装饰填满。明确占位页仍保留入口，不因空白引入新业务。

## 统一设计与实现约束

1. **使用三种结构**：简单列表一行“页签｜搜索”；操作较多列表一行“页签｜搜索、筛选、操作”；复杂库存两行“页签＋主要入口／搜索＋筛选＋批量操作”。按容器可用宽度切换，不按页面各写一个断点。
2. **尺寸**：桌面控件继续 36px，手机继续 44px；简单页首目标约 60px。搜索建议 280—320px，空间足够时靠右；按钮间隔 8—10px，分组间隔 12—16px。最终复用已有共享令牌和内距，避免新建第二套主题皮肤。
3. **边线与对齐**：合并后仅保留一条区域分隔线；页签下划线贴合区域底边。搜索、下拉、按钮按实际控件垂直居中；不通过负边距、固定空白、额外高度掩盖问题。
4. **换行**：页签保持单行可横向滚动；空间不足时将搜索／操作组作为明确分组换到下一行，控件组内部允许必要换行。长文字、错误和帮助浮层不得遮挡操作。管理员／员工可用入口变化不能留下空操作行。
5. **状态**：第一页、末页、空结果以及刷新中保持页首结构稳定；搜索词、选中页签、筛选、排序和页码继续使用既有会话草稿。合并只移动原有控件，不增加第二套输入和事件处理。
6. **功能范围**：不修改任何必填规则、订单归属、邮箱匹配、币种目录、金额规则、权限判定、API 或数据库。

## 实施落点与顺序

原因在结构：`commerce-prototype.js` 的 `tabs()` 和 `toolbar()` 常被串接为两个块；`mountPageContext()` 只把原页首按钮归入指定槽位，不会把下方搜索自动合并。单纯减小 `.toolbar` 的 padding 仍会多占一行。

- 先扩展现有共享列表工具区／动作槽，使用 `frontend/prototype.css` 中相关共享布局完成一行及自然换行规则。通用 `.toolbar` 同时被表单、详情和抽屉使用，不能全局一刀切缩小。
- `frontend/commerce-prototype.js` 优先接入客户流失及第一批同类列表，保留既有输入 ID、事件与草稿；再接入 `inventory-prototype.js`、`apple-relay-prototype.js` 的相关变体。
- `frontend/local-auth.js` 和 `operations-prototype.js` 接入员工、系统登录日志及邮箱池；网站监控复用已有候选。
- `frontend/finance-collection.js`／相关样式只归位工具区，不触碰报价、采集计划或账务快照。
- 同步扩展已有共享布局／列表边界离线验收，覆盖本轮列出的使用变体；不要为单个截图建立页面专属补丁。

建议实施三批：①客户流失及同类简单列表；②汇率、邮箱池和复杂库存；③共享回归及逐页验收。每批完成后以相同数据、相同视口进行前后比较，再报告代码及验证状态。
