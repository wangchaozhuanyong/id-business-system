## 1. 财务历史闭环

执行生产写入前，由业务负责人提供并确认：

- 财务启用和历史切账日期；
- CNY、MYR、USDT 资金账户及各自期初余额；
- 加卡供应商钱包期初余额；
- 系统外历史开支、手续费、退款和损耗；
- 可核对的汇率来源、日期和证据；
- 历史资料完整性确认说明。

自动回填已经执行，后续不得在没有新预览指纹的情况下盲目重跑。剩余执行顺序固定为：只读预览、
生产备份、核对或补录期初资料与历史开支、逐源对账、负责人确认。只有预览证明仍有未处理来源时，
才冻结新预览指纹并幂等重跑回填。历史确认前，
经营分析不得将累计利润描述为完整经营利润。已经生成的财务凭证只能冲销再重记，禁止原地修改。

完成门禁：

- `history_status = completed`；
- 自动回填预览显示没有遗漏的历史来源，或重跑结果有完整审计；
- 原币、汇率、汇率来源和人民币折算证据齐全；
- 每张凭证借贷平衡并能追溯到来源业务；
- 期初账户、供应商钱包和历史开支由负责人逐项确认。

## 2. 生产权限与认证

缺口。新增真实员工后，必须逐账号完成本地用户、Supabase Auth 身份、角色和会话映射。

验收至少覆盖管理员、财务和普通员工三类职责；如果当前没有对应员工，记录为“角色尚未启用”，不得
创建虚假生产账号。逐项核对菜单、读写权限、敏感字段权限、会话撤销、首次改密、MFA 和 IP 白名单
