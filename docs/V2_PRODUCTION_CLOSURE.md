## 1. 财务历史闭环

执行生产写入前，由业务负责人提供并确认：

- 财务启用和历史切账日期；
- CNY、MYR、USDT 资金账户及各自期初余额；
- 加卡供应商钱包期初余额；
- 系统外历史开支、手续费、退款和损耗；
- 可核对的汇率来源、日期和证据；
- 历史资料完整性确认说明。

自动回填已经执行，后续不得在没有新预览指纹的情况下盲目重跑。剩余执行顺序固定为：只读预览、
生产备份、核对或补录期初资料与历史开支、逐源对账、负责人确认。只有预览证明仍有未处理来源时，
才冻结新预览指纹并幂等重跑回填。历史确认前，
经营分析不得将累计利润描述为完整经营利润。已经生成的财务凭证只能冲销再重记，禁止原地修改。

完成门禁：

- `history_status = completed`；
- 自动回填预览显示没有遗漏的历史来源，或重跑结果有完整审计；
- 原币、汇率、汇率来源和人民币折算证据齐全；
- 每张凭证借贷平衡并能追溯到来源业务；
- 期初账户、供应商钱包和历史开支由负责人逐项确认。

## 2. 生产权限与认证

`production_smoke_readonly` 是自动发布巡检账号，不要求创建 Supabase V2 身份，也不计入真实业务员工
缺口。新增真实员工后，必须逐账号完成本地用户、Supabase Auth 身份、角色和会话映射。

验收至少覆盖管理员、财务和普通员工三类职责；如果当前没有对应员工，记录为“角色尚未启用”，不得
创建虚假生产账号。逐项核对菜单、读写权限、敏感字段权限、会话撤销、首次改密、MFA 和 IP 白名单
防锁死门禁，并检查审计日志。

当前 22 个模块的入口矩阵：

| 访问门禁                   | 模块                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 已登录用户                 | 仪表盘、我的账户                                           |
| 仅 `admin`                 | 业务监控、数据治理、员工账户、角色权限、安全中心、系统监控 |
| `apple.account.view`       | ID 录入                                                    |
| `apple.activation.view`    | 开通记录                                                   |
| `apple.balance.view`       | ID 加额、加卡记录、ID 报损记录                             |
| `apple.exchange_rate.view` | 汇率记录                                                   |
| `apple.order.create`       | 订单录入                                                   |
| `apple.order.view`         | 订单管理                                                   |
| `apple.renewal_task.view`  | 续费操作                                                   |
| `audit_log.view`           | 审计日志                                                   |
| `customer.view`            | 客户记录                                                   |
| `data.analytics.view`      | 经营分析                                                   |
| `data.dictionary.manage`   | 选项设置                                                   |
| `finance.view`             | 财务记账                                                   |

上述只是页面入口门禁，写入、敏感资料和调整类权限仍需按真实职责逐项选择，不能只凭“页面能打开”
判定验收通过。

## 3. 真实业务闭环

使用有明确测试标记且可冲销的数据，依次验收供应商付款、礼品卡加卡、ID 入账、订单匹配、订单完成、
手工续费和退款。核对供应商余额、ID 余额、开通记录、成本、利润、不可变财务凭证和审计日志。

测试完成后通过退款、撤销或冲销恢复，不直接删除财务记录。

## 4. 数据治理双人演练

第一轮只恢复专门创建并软删除的测试客户或测试订单，不执行真实历史硬清理：

1. 管理员 A 创建确定性预览并填写备份证据；
2. 验证管理员 A 不能审批自己的任务；
3. 管理员 B 核对预览哈希并批准；
4. 授权执行人分批执行；
5. 重放同一幂等键，确认不会重复处理；
6. 核对任务、审批、检查点、逐项结果和审计编号。

## 5. 托管数据库恢复

正式演练必须使用兼容 Supabase Auth、Vault、`pg_cron` 和 `pg_net` 的隔离环境。恢复后比较备份时点
行数和备份后新增数据，并验证登录、权限、订单、客户、ID、财务和数据治理接口。记录恢复耗时、
数据缺口、RPO、RTO 和操作手册。普通 PostgreSQL 的业务表恢复不能替代完整 Supabase 恢复证据。
