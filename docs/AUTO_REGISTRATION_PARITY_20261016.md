## 修复查实的诊断盲区

原 v1 把响应中的非空 `error`／`errors`、未知页面名称和非字符串页面类型混成 `unknown`。因此已保存的 200 响应观察不足以确定具体拒绝原因，也不能反推新门禁误拦。

新任务使用 `flowEvidence.version=2`。只有邮箱提交阶段且 JSON 是对象时，增加封闭的 `responseDetails`：

- 错误信号：没有错误、单项错误、错误集合、两者都有，沿用既有真假判断。
- 两类错误字段各自的数据结构。
- 错误类别：仅既有明确白名单，其他代码只记“其他”。
- 页面结构：缺少页面、页面不是对象、缺少类型、类型不是文本、已知类型、未知类型。

页面分类与错误信号分别记录。即使返回已知密码页，只要带有非空错误，仍停止并记录“官网响应携带错误”。非法 JSON、非官方来源、错误 HTTP 状态及未知页面继续阻断密码提交。

不记录原始页面名称、错误消息、响应正文、密码、验证码、Cookie、Token 或授权链接。摘要只进入既有加密任务记录，不进入邮箱事实、账号主台账或同步指纹。API 类型和两处任务详情只显示中文白名单标签。
