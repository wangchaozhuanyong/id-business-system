## 人工门禁

以下操作涉及账号持有人、真实岗位或真实金额，禁止用虚假生产账号、虚构金额或代替用户保管 MFA
恢复码完成。

### 1. 管理员改密和 MFA

- [ ] 所有启用身份的 `mustResetPassword` 均为 0；当前仍有 1 个管理员需要首次改密。
- [ ] 两名启用管理员分别在“我的账户”绑定 MFA，并各自离线保存恢复码。
- [ ] 两名管理员分别退出并使用动态验证码重新登录一次。
- [ ] 两名管理员均绑定后，由当前管理员在“安全中心”开启全局 MFA 和“管理员强制 MFA”。
- [ ] 验证另一台设备的会话撤销后立即失效，并在审计日志中留下记录。

不得在管理员尚未全部绑定时直接开启强制策略，否则会造成管理员无法登录。

### 2. 员工角色确认

当前 `yuangong` 角色有 11 项权限，包括完整礼品卡查看和供应商资金管理，但没有订单创建、订单修改、
客户创建、客户修改或余额加卡权限。业务负责人必须先确认该角色属于以下哪种岗位，再修改生产权限：

- 录单操作员：按工作需要授予订单、客户、续费和余额操作权限，不默认授予供应商资金管理、完整卡号
  或财务权限。
- 加卡资金操作员：保留供应商资金和完整卡号权限，不默认授予订单修改或财务关账权限。
- 只读员工：移除资金管理和完整卡号权限，只保留必要查询权限。

- [ ] 业务负责人确认 `yuangong` 的岗位类型和权限清单。
- [ ] 由管理员在“角色权限”保存最小权限，并确认在线会话立即失效。
- [ ] 一名真实员工重新登录，逐项验证菜单、读取、写入和敏感字段边界。

### 3. 真实业务闭环

使用业务负责人提供、带明确试运行备注且可以冲销的低金额真实业务，按以下顺序执行：

1. 供应商付款；
2. 礼品卡加卡和 ID 入账；
3. 首次订单匹配并完成；
4. 已售 ID 售后续费；
5. 退款、撤销或冲销；
6. 核对供应商钱包、ID 余额和成本、开通记录、订单利润、资金账户、财务日记和审计编号。

- [ ] `supplierPayments` 至少出现 1 条经业务负责人确认的真实证据。
- [ ] `refundedOrders` 至少出现 1 条经业务负责人确认的真实证据。
- [ ] 原业务和冲销业务均能从财务日记追溯，且完整性审计仍为 0 异常。

## 三个业务日试运行

每天开始营业前：

1. 检查 `id-business-v2-mysql-backup.timer` 为 `active`，且 S3 最新成功备份不超过 35 分钟；
2. 检查生产 live/ready；
3. 确认操作员使用个人账号，不共享管理员账号。

每天结束营业后：

1. 执行 `npm run audit:v2-data-integrity:production`；
2. 对账资金账户、供应商钱包、ID 余额成本、已完成订单和当日利润；
3. 检查异常登录、敏感资料查看和高风险操作审计；
4. 记录当日业务负责人、核对时间、差异和处理编号。

## 立即停止条件

出现下列任意情况时，停止新增业务写入，保留现场并先生成保护性备份：

- 数据完整性审计出现任意违规；
- 供应商钱包、ID 余额、资金账户或财务日记无法对平；
- 生产接口持续返回 5xx，或业务提交结果无法确认；
- 管理员账号、MFA、会话撤销或敏感数据权限出现异常；
- 最新有效 S3 备份超过 35 分钟，或最近一次隔离恢复验证失败。

禁止通过直接改数据库、删除财务记录或重复提交来“修正”现场；只能使用业务撤销、冲销或既有恢复
流程。
