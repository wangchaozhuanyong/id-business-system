# 订单边界与苹果 ID 余额：最新业务修订

本文件以用户本轮补充为准，取代本目录中与其冲突的“首次开通、账号来源必选、订单邮箱分类、通用原订单关联、通用续费起算确认”等旧设计。当前仍为离线原型与规划，不代表正式接口、数据库、支付或部署已完成；旧验收记录只证明各自旧版本。

2026-11-04 比特充值补充见 [BIT_RECHARGE_REVISION.md](BIT_RECHARGE_REVISION.md)：下述订单录入的“成品交付”不适用于比特工作台。比特只处理客户自有账号续费，保留后台无需兑换码的自动充值及仅登录后人工操作，兑换码／Vendure 在此基础上扩展；目标邮箱从授权 JSON 识别，不强制关联邮箱或账号库存。

2026-11-07 账号生命周期补充见 [ACCOUNT_LIFECYCLE_20261107.md](ACCOUNT_LIFECYCLE_20261107.md)：系统自有 GPT／Claude 库存的原客户续费会核对并保留库存身份，只追加独立订单与历史，不再次扣占库存；回库必须经过专用操作，原历史资料不删除。本补充替代下文“续费不查找或修改同邮箱库存”的绝对表述，客户自有且未匹配库存的邮箱仍可独立录单，不强制关联旧单或创建库存。

## 1. 三类资料独立

| 功能     | 自己负责的资料                                       | 与其他模块的边界                                                         |
| -------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 邮箱管理 | 邮箱库存、提取、实际使用与归还                       | 提取邮箱后可人工注册，再独立录入账号；不强制账号引用邮箱主档             |
| 账号管理 | GPT／Claude 等可用账号及使用状态                     | 不要求账号的邮箱先存在邮箱库存；成品交付时可提供一次性搜索选择能力       |
| 订单管理 | 客户、订单邮箱、套餐、支付与费用快照、订阅周期和退款 | 邮箱直接记录在订单中，可完全不存在于前两类资料；同邮箱可反复形成不同订单 |

成品交付可保存本次明确选择的库存资料编号和交付快照，用于防止同一库存重复售出；这不把订单邮箱变成账号主档的强制外键。以后客户以相同邮箱来续费，仍是新订单，不因邮箱相同而再次占用库存或强制关联原单。

## 2. 提交订单只有两种业务类型

| 类型     | 邮箱账号输入                                                   | 不需要的字段                                                           | 提交后的行为                                             |
| -------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------- |
| 续费     | 选择客户优先匹配其最近可续费邮箱，也可手填；无历史也能提交 | 首次开通、账号来源、邮箱分类、关联原订单、原到期起算选择及通用续费确认 | 建立独立新单；明确匹配系统库存时核对当前客户并追加历史，不重复占用 |
| 成品交付 | 搜索对应产品的可用库存，包含首次可用及人工回收账号 | 账号来源、邮箱分类 | 提交成功确认库存已使用并保留本轮交付记录，同一轮不能重复分配 |

新订单创建、库存确认使用及苹果余额变动在正式实现中须原子完成。校验或保存失败不先消耗库存、余额；结果不明时先查原提交，不盲目重做。撤单不能顺便恢复已真实交付的库存。

## 3. 套餐、币种与表单

- GPT 内部可售套餐为 **Go、Plus、Pro5x、Pro20x、Pro50x**；Claude 保留 Pro、Max 5x、Max 20x。
- 上述内部订单套餐不等于每个自动执行／公开兑换入口已经支持全部套餐；实际可用项须按既有能力和接口契约核对，未接入套餐不能冒充可自动充值。
- 币种选项同时显示代码和中文：USD 美元、CNY 人民币、MYR 马币、PHP 菲律宾比索、CLP 智利比索、IDR 印尼盾；存储和计算仍采用受控币种代码。
- 金额区按用途分组：代付币种在代付金额上方，售卖币种在售卖金额上方；宽屏两组并排，窄屏整组换行。每行字段标签仍在控件左侧。
- 周期单独一组，只保留“订阅时间（本次实际开通时间）”和“到期时间”；不再重复一个“实际开通”字段。
- 普通新单默认按本次订阅时间计算月周期，北京时间下月同日同分钟到期，月末夹取。到期可按实际账单修正，已有订单继续使用其已保存的到期时间。
- 银行卡可以重新选择当前使用的新卡，不因同邮箱历史订单而锁定旧卡。稳定银行卡 ID 与尾号区分、开卡费只计一次的规则保留。
- 移除订单邮箱分类后，费用采用明确的配置和订单成本快照，不按邮箱外观猜分类，不要求读取邮箱库存才能完成核算。当前设计将邮箱成本改为可选手工金额与币种快照，默认 0 CNY，由操作者在成本核对时确认；既有 100 MYR 代付服务费、50 MYR KYC 认证成本和内购折扣继续采用费用配置。

## 4. Claude 的续费入口

订单管理的快捷续费仍仅向 Claude 开放。工作台「续费管理」集中提醒 GPT、Claude Pro、Claude Max；Gemini、Grok 等对应订单模块启用后再参与。默认提前 3 天。提醒设置可填写天数和小时数，例如 3 天 12 小时，少于 1 天时只显示小时。点击续费复用「提交订单」并预填客户和账号，确认开通的新单关闭同一账号的原提醒；拒续费只停止该单提醒，可从已处理恢复。

「客户资料 → 租户数据」按已明确关联租户和订阅账号的确认开通订单计算续费提醒。租户页共用独立设置，默认提前 3 天，可填写天数和小时数。以北京时间比较到期时间，按同一租户、账号、订阅系列的最新周期归集。进入提醒窗口或已经到期的账号列入「待处理」，按到期时间排序。同一周期关联多名客户时，详情同时展示租户联系方式、相关客户和对应订单。

管理员完成联系或核对后，可标记本次提醒已处理。系统在既有加密业务文档和审计中记录处理人、时间、关联编号及原到期时间，后续周期继续按实际到期时间提醒。标记只记录跟进结果。租户页设置及处理记录沿用现有版本校验，无需数据库迁移。

「数据管理 → 客户流失」按客户编号归集，缺编号的订单按同渠道联系方式核对。曾开通且当前没有有效订单时进入列表，重新开通任一产品或账号后自动退出。归属有歧义时进入待核对。原有链接继续有效。

Claude 专属的快捷续费可以带入当前账号、客户及运营资料，按当前到期时间续接一个自然月；提交仍生成可独立查看的新订单，旧单及费用快照不覆盖，专属视图再更新当前到期。专属快捷入口携带的上下文不是通用订单录入的必填关联。没有系统历史的 Claude 客户也能直接提交新单。

## 5. 苹果 ID 余额

**账号管理 → 苹果 ID 余额**登记账号、App Store 账单地区及美元余额。新增账号与期初余额同时保存，正余额生成期初流水，零余额建立钱包。已有账号由管理员核实账单地区，地区选项依据 [Apple App Store 地区](https://support.apple.com/en-us/118205)。充值入口登记实际到账金额和依据，保留操作人、时间及变动前后余额。

**系统设置 → 代付国家 → 苹果内购代付价**独立维护地区、产品、套餐的美元价格。缺价显示「待核算」。新单按地区、状态、是否使用或占用、以及所需余额推荐，优先推荐最接近且足够的余额。订单填有更高的预计实付时按较高额匹配。

草稿不占用。保存待付款订单后，占用一条苹果 ID。核实未付款并撤单后释放；未核实付款结果时保留占用。确认实际付款时，同一事务保存订单、绑定及实付扣款。同一订阅账号续费使用原绑定，邮箱忽略首尾空格及大小写并核对客户。到期、退款、撤单保留绑定。有可交叉核对的历史订单和余额分配记录时识别旧绑定，有歧义时待核对。

**数据管理 → 苹果 ID 管理**查看每个 ID 最新一期、到期时间、预计金额及历次订单，可从当前使用记录发起续费。余额流水的桌面表格允许换行，窄屏用逐字段卡片。

### 退款与更正

**2026-11-04 用户已明确退款口径，原“待财务答复”事项关闭。** 银行卡退款登记客户实际退款及银行卡实际回款，用于核算退款后的收益／亏损。苹果内购退款时先填写客户退款金额，再填写本次苹果 ID 回款金额；Apple 实际到账后，按这笔已登记金额回增原付款 ID 余额。

退款弹窗及到账处理按以下目标设计；当前原型的客户退款和 Apple 实际返还入口尚未通过待回款记录衔接，本节不代表该功能已经开发：

| 页面／操作       | 字段及行为                                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 客户退款登记     | 客户退款金额、币种（沿用原售卖币种）、退款时间和原因；只登记已实际退给客户的金额，累计不超过原实收                                                            |
| 苹果内购追加字段 | 原付款 Apple ID 自动带出；另填“本次 ID 回款金额（美元 USD）”，表示本次将退回的金额，不是退款后 ID 的总余额，也不按客户退款金额推算；允许明确填 0 表示无需回款 |
| 待回款记录       | 保存本次 ID 回款金额，并关联退款记录、原订单和原付款 ID；金额大于 0 为“待回款”，此时不增加可用余额                                                            |
| 确认回款到账     | 按已登记金额回填，核对实际到账后增加原 ID 余额并写流水，状态改为“已回款”；重复点击、重试和迟到提交不重复入账                                                  |
| 金额不一致       | 先显式更正待回款金额并保留原值、原因和版本，再确认实际到账；已回款记录不能通过修改退款表单覆盖                                                                |
| 银行卡回款       | 沿用原银行卡资金回款能力，按实际金额及代付币种登记；客户退款支出与银行卡回款分别核算，不默认两笔金额相同                                                      |

例：ID 余额原为 250 USD，订阅支出 20 USD 后为 230 USD；本次退客户 100 CNY，填写 ID 回款 7 USD。登记退款后 ID 仍为 230 USD，并显示待回款 7 USD；确认这 7 USD 已到账后，余额为 237 USD，同一笔再确认不加钱。

退款后损益＝原实收－客户累计退款－（原成本－已实际收回的成本），各币种按订单采用的成本和汇率快照换算。待回款不作为已到账收入；Apple 回款按原成本依据／内购折扣核算成本收回，不把 USD 余额面值直接当作现金利润。未退回的手续费、KYC、账号或邮箱成本继续保留。

- Apple 已回款与未完成待回款的合计，不得超过本单更正后的实际扣款；新增待回款还须扣除已有待回款占额，避免多次退款重复安排同一笔余额。确认时核对原订单、原付款 ID、钱包和回款记录的版本与未入账状态。
- 更正实际代付金额或付款 ID 时先预览差额；涉及旧扣款退回的部分，需要明确的余额冲正确认，不能因编辑金额降低而静默增钱。
- 修改撤回用补偿流水反向记录本次已确认调整；检查余额与版本，不删除原扣款、返还或更正记录。
- 撤单、冻结、客户退款和未知付款结果都不自动回增 Apple 余额；需要核对实际支付事实后处理。

## 6. 必须覆盖的验收

- 客户邮箱不存在邮箱／账号库存，也能完成一笔独立续费订单；重复邮箱的新订单编号不同。
- 成品交付按 GPT／Claude 搜索未使用账号，保存成功只标记选中账号；保存失败、重复提交和并发不会误用或重复使用。
- 同一成品账号给当前客户续费开新单，不再次消耗库存，只追加关联与历史；不要求原订单或邮箱分类。回收、停止复用、已转给其他客户的账号不能通过手填邮箱绕过归属核对。
- GPT 显示五种套餐；普通订单无续费操作；Claude 快捷续费新增一单，专属到期增加一个自然月，旧单保留。
- 银行卡可换新卡；苹果内购续费须沿用原绑定，历史证据冲突时进入待核对。
- Apple ID 250→230 的扣款、重复提交、余额不足、确认余额退回、更正差额和补偿撤回可逐条核对，客户退款不混入余额事实。
- 苹果退款同时登记客户退款与 ID 待回款：退客户 100 CNY、ID 回款 7 USD 时，两笔金额独立保存；登记不增余额，到账后 230→237，重复确认不重复增加。补验 0 回款、金额更正、多个退款占额、不同 ID 和迟到提交。
- 双语币种、金额分组、左侧标签、单一订阅时间、桌面与手机、草稿和失败保留均需新版本实测。

苹果 ID 代付复用现有加密文档、订单事务和余额台账。新字段按需写入，旧记录在读取时核对。离线验收使用合成资料，生产发布与真实付款单独验收。
