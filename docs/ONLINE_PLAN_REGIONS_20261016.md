## 规则与启用

系统配置新增“套餐地区规则”，每档可独立选择代理国家和支付地区，并显示对应币种。

| 目标套餐 | 代理国家 | 支付地区 | 预期币种 |
| -------- | -------- | -------- | -------- |
| Plus     | 菲律宾   | 菲律宾   | PHP      |
| Pro 100  | 智利     | 智利     | CLP      |
| Pro 200  | 菲律宾   | 菲律宾   | PHP      |
| Pro 500  | 智利     | 智利     | CLP      |

“按套餐选择地区”默认关闭。代码发布本身不会启用；需在现有配置页明确保存开启。开启后的新充值与付款前调试采用上述规则。关闭时沿用全局配置，独立查询和续费操作继续使用原全局设置。

兑换码绑定套餐优先于客户端填写的套餐；管理员无兑换码时使用明确选择的套餐。服务端决定地区，不接受客户端伪造的代理国家或规则快照。银行卡继续共用原池，不按国家拆分。

每个新充值／调试任务在事务中固定规则来源、配置版本、目标套餐、代理国家、支付地区及预期币种；执行器、运行参数和地区查询读取同一快照。规则后续修改仅影响新任务。原单核对沿用原单资料；缺少原国家或支付地区时停止，不重新推算。

## 付款边界

- 无对应国家的启用代理时不创建任务、不预占兑换码，不回退其他国家或直连。
- 免费账号沿用开通流程。已知付费套餐仅在官网明确返回无有效订阅且带时区的到期时间已过时，才按重新开通处理；缺少到期证据仍停止。有效 Plus／较低 Pro 档继续原有准确升级核验；取消续费但仍有效不按过期处理。同档、降档、账号不符、档位不明继续停止。
- 有效订阅升级保留官网原订阅币种；与本次套餐规则不符时暂停，不自动取消或重建订阅。
- 官网最终应付、实际币种、准确套餐、账号和实际银行卡仍须通过原付款校验；后端也拒绝缺失报价或不符币种的提交。付款结果不明继续原单核对，不再次付款。
- CLP 仅接受明确的 `CLP`／`CL$`，不把单独 `$` 当作智利币种。金额保持整数比索字符串，兼容点／逗号千分位及零小数，拒绝混合分组、非零小数和矛盾金额；持久付款金额继续使用既有 Decimal。
- 智利结算等待官网计税后的实际总额稳定，不套用菲律宾税率或从“100／500”推算售价。账单地址继续来自原资料来源，填写时使用地址自身的国家，不按代理国家或支付地区自动改写。
- Pro 500 的未核实真实订阅标识保护继续保留，仅可付款前调试。未新增或猜测其官方标识。
- 智利第三方充值组合明确停止，不擅自换通道。现有官方银行卡通道及付款前调试支持地区规则。

官方多币种规则依据：[OpenAI 多币种说明](https://help.openai.com/en/articles/10421635-multicurrency-billing)。官网最终报价才是实际金额依据；当前交付不代表智利真实官网结算已验收。
