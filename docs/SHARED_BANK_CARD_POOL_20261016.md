# 自充设置与银行卡共享池

日期：2026-10-16（Asia/Kuala_Lumpur）。状态：代码完成，本地类型、构建、定向测试及合成页面验收完成；远端数据库迁移与生产验收待执行。本轮未提交、推送、创建 PR 或部署，未执行真实付款、订阅更改或外部通知。

## 功能

- “账号设置”改为“自充设置”，包含原 ChatGPT 账号、邮件验证码查询、代理 IP 管理，以及迁入的“充值订单”和“银行卡共享池”。订单数据和既有账单/任务记录保持原有分工。旧账号删除银行卡入口同步保护共享池任务和线上历史，避免删一套、另一套仍可调用。
- 共享池入口为 `/v2/account-settings/bank-cards`，充值订单为 `/v2/account-settings/bank-orders`。旧银行卡和订单 URL 保留重定向及查询参数、锚点。
- 以线上代充 `online_recharge_cards` 为权威卡池。比特浏览器与线上代充共用卡号指纹、启停状态、套餐范围、使用计数和占用状态；比特历史银行卡表保留为原订单外键与账单资料的兼容投影。
- 添加、导入和编辑银行卡均可勾选适用套餐。支持 Go、Plus、Pro 5 倍、Pro 20 倍、Pro 500 美元档；各充值方式只提供其已支持的套餐，未扩展线上代充的充值档位。
- 旧卡默认允许全部已支持套餐。限制为 Plus 的卡不会出现在其他套餐的匹配列表中；服务端对手填卡号、手工指定、自动分配、恢复取卡和线上付款提交再次校验。
- 比特充值可手选或点击“智能分配”；线上代充管理员提交可指定卡或留空按套餐智能分配。两者共用租约和原子条件更新，不按超时自动释放未知付款结果的卡。
- 安全码不进数据库、审计或会话草稿。共享池临时安全码沿用线上执行器内存；比特仍逐笔输入安全码。
- 共享列表框架增加分页区实际高度保留，解决窄屏页数变化或空状态导致整框缩短的问题。

## 两列的含义

- **连续明确拒付次数**：支付方明确拒绝付款时累计；成功后清零，达到“系统配置 / 单卡明确拒付上限”后退役。网络失败、超时或未知付款结果不算明确拒付，也不能据此释放卡片。
- **账单地址**：线上代充复用此卡已关联的付款地址。现在显示国家、城市和街道，未绑定时明确说明按地区分配；比特继续保留原有已核实账单地址规则。

## 接口和数据库

- 新增 `GET /id-business-v2/bank-card-pool/options?plan=…`：管理员读取当前套餐的启用、未占用且未达额度的脱敏卡片。
- 新增 `GET /id-business-v2/bank-card-pool/:id/payment-details?plan=…`：管理员为当前套餐取卡，校验套餐及占用并记录敏感读取审计。
- 线上代充既有银行卡创建/导入/更新接口支持 `allowedPlans`；任务创建既有接口支持可选 `cardId`。无新增数据库表、依赖或环境变量。
- 新增 JSON 列 `online_recharge_cards.allowed_plans`，通过独立增量迁移 `20261016150000_shared_bank_card_pool` 引入。没有修改纯净基线或删除旧数据。
- 迁移按卡号指纹去重合入完整比特卡；保留原卡号加密值、旧编号及订单外键，沿用停用状态，并合入旧比特已核实充值的不同账号使用数。达到当前配置上限的卡标为额度用尽；旧尾号标识缺少完整卡号/有效期时保留原历史记录，不变成可执行卡。
- 保留原执行任务和未知结果的占用。正式迁移前须确认两种充值均无运行中任务，核对同卡历史冲突及备份；发布后检查合并数量、限制、状态及原订单关联。不能把本轮合成测试当作远端 MySQL 并发或迁移证据。

用户授权修复审查发现的四项缺口，并明确银行卡支持任意支付币种，不给卡片锁定币种。本节是审查后新增修复的验证记录；上文为原方案的历史验证，不能替代本节或远端验收。

- 核对成功后，以已核实订单绑定的原付款任务为准，确认原卡账单姓名和地址、释放原任务占用并记录成功次数。正常及过期回调都使用同一结算入口；核对未成功不释放原卡，重复回调不重复计数，订单指向其他原任务时拒绝结算。
- 修正尚未发布的共享卡池增量迁移：明确处理为“银行卡未收到付款请求”及已有核实成功订单的历史任务不重新占卡；运行中和未解决的未知付款仍保留占用，不按超时释放。

- 比特充值切换支付币种保留卡片、有效期及账单地址，仅清理临时安全码；套餐切换仍重新选卡。充值订单候选卡不按币种过滤，切换订单币种不清除银行卡；快捷新增卡片标识不再显示币种字段，成功后自动选中。
- 历史卡表的必填币种字段保留兼容存储，仅作原始登记资料，不限制后续支付；本次任务币种、代理国家和官网报价一致性校验继续保留。
