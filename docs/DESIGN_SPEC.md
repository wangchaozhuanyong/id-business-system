# ID 业务管理系统 · 新页面设计规范

日期：2026-11-04。阶段：离线设计原型与正式接入规范。

本目录属于 ID 业务管理系统。设计依据为本次用户批准方案与补充需求文本，不参考旧网页的视觉外观。本文件描述目标设计及后续接入要求，不代表业务代码、接口、数据库或上线已完成。

加载、导航、缓存、搜索、草稿和动效按 [已核实的 e51 线上交互基线](INTERACTION_LIVE_BASELINE_20261104.md) 复用；本轮更新方案，不表示新设计已接入全部线上共享实现。

最新订单、独立模块与苹果 ID 余额规则见 [ORDER_BOUNDARIES_REVISION.md](ORDER_BOUNDARIES_REVISION.md)，与此前设计冲突时以该修订为准。

## 1. 原型边界

- 本阶段用于查看新布局、页面结构、表格、抽屉、表单和主要操作流程。
- 原型数据全部为明确标注的演示资料，交互仅修改当前页面内存；刷新后重置。不保存真实密码、手机号、卡号、密钥或业务资料。
- 原型不连接 API、生产数据库、Vendure、邮箱、比特浏览器、注册器、汇率供应商或支付渠道，不执行真实注册、同步、充值、退款、付租或消息发送。
- 图中的成功、失败、待核对及统计数字仅表达界面状态，不是实际业务结果。不得将原型演示作为付款或生产验收证据。
- 保留一套未来正式系统；原型不是第二套正式入口。进入实施阶段后接入现有 Vue 3、Element Plus、Pinia、NestJS、Prisma 和 MySQL 架构。

系统业务时间统一为**北京时间（Asia/Shanghai，UTC+8）**。所有页面、抽屉、日期输入、日期筛选、记录时间、导出、订单周期和统计日界线按此规则；正式系统使用服务器业务时钟，不随访问电脑时区或充值代理国家变化。生日等纯日期保留原日期，绝对时刻保持 ISO／UTC 传输与存储，不批量加八小时。原型继续使用固定的北京时间演示时钟；第三方原始聚合报表明确标注来源时区，不将已有分组改名冒充北京时间汇总。比特浏览器指纹的代理时区属于执行环境配置，独立于系统业务时区。

正式接入时，颜色、字号、边框、尺寸和状态令牌进入现有 `base.css` 共享层，不在页面复制皮肤。使用现有布局、按钮、表格、抽屉、加载和草稿公共实现；视觉升级与项目 UI 文档同步，不在各页叠加补丁。

页面、抽屉、分组、工具卡片和嵌入页的副标题及用途说明，统一收纳到标题文字右侧紧邻的 ⓘ 按钮。默认关闭，点击或用键盘打开，重复点击、点击外部或按 Escape 关闭。说明浮层不挤动内容，手机触控区至少 44px。已有宿主标题的嵌入页将说明合并到宿主标题右侧，独立打开时使用自己的标题说明。禁止在标题下方常驻同一说明或另占一行。字段使用说明同样收纳在字段标签右侧的 ⓘ 按钮内；校验错误继续在控件下方显示，状态、确认操作的影响和记录正文继续原位显示。

抽屉页签底线与后续卡片或首个可见表单内容至少保留 16px 间距；由共用 `.drawer-body > .tabs + .form-section` 处理，已有搜索和工具栏内边距不重复叠加。验收同时测量页签底线、卡片边框和首个实际内容节点。页签键盘焦点框收在控件内部，容器不额外显示原生焦点外框；按钮、输入和说明图标继续显示键盘焦点。

左侧导航滚动与主内容区分开管理。切页、搜索、分页或列表重新绘制时保留导航滚动位置和已展开分组，避免每次操作都回到导航顶部。

### 2.1 紧凑布局与标题

- 当前页面名称只在左上角顶栏出现一次，以紧凑标题和说明图标呈现；桌面前方显示上级栏目，上级栏目同名时省略，窄屏优先保留当前页名称。内容区移除独立大标题行，直接展示业务内容；公开兑换页使用简化顶栏，仍有唯一语义标题。
- 操作按任务归位：列表并入搜索工具栏或公共页签右侧；提取页并入确认提取的表单操作区；详情页并入资料分组或页签；充值入口动作并入来源切换栏。币种筛选和配置版本等原有控件随原动作一起迁移。空间不足自然换行，没有操作不保留空行。
- 原型通过共享 `mountPageContext()` 移动原有标题与操作 DOM，模块使用明确的 `data-page-actions` 槽；不以隐藏重复标题、空白占位或复制按钮处理。加载状态替换内容时，顶栏标题持续可见。
- 纯操作说明收进标题说明图标，不为短提示预留独立右栏。邮箱提交与账号提交复用 `submission-grid`：按各自启用的资料类型等宽同排，窄容器单列紧凑排列，按钮与类型标题就近；不沿用通用两列表单网格造成右下空格。
- 只有实际预览、汇率资料或任务记录保留右栏，按内容自然高度展示。左右面板使用一致的顶部内距；同类标题统一 15px／600／1.5 行高，标题行最少 28px、下方间距 16px。验收同时测外框顶边和实际标题文字，窄屏改为纵向排列；不以拉高空白侧栏伪装对齐。说明浮层在侧栏内容宽度内换行，卡片不裁切浮层。
- 表单按实际容器宽度排列：宽容器三列、中等容器两列、小容器一列。每个字段的标签仍在控件左侧，长邮箱、网址、代理和备注按需跨列。
- 产品、套餐、业务类型、日期和人员等短字段合理同排。订单金额区按代付、售卖分组：币种在对应金额上方，两组宽屏并排、窄屏整组换行；每行标签仍在控件左侧。订阅时间和到期时间单独组成周期分组。
- 订单采用全宽表单，费用规则收纳为横向摘要和按需展开说明，不用固定侧栏长期挤占输入区。分组只保留必要间距，避免每个字段另建大卡片。
- 不为减少滚动而缩小控件、字号、点击区或隐藏必填项；手机仍使用 44px 控件，允许合理的纵向滚动。

### 2.2 线上统一加载与切页方案

完整时序、固定源码及接入清单见 [线上交互基线](INTERACTION_LIVE_BASELINE_20261104.md)。该基线适用于所有业务页面、详情、抽屉、弹窗和手机卡片。

- 启动用同一中性会话门；路由代码加载保留当前页面和应用壳，顶栏反馈，失败只显示一个布局内错误。
- 首次无快照才显示匹配内容形状的骨架；clean 缓存回访同步显示。同参数刷新保留内容，超过 120ms 只显示区域细进度线；刷新按钮只禁用。
- 筛选、排序、分页和页签请求期间保留旧快照、旧页码及总数并只读，成功后一起替换；失败保留内容和重试。等待依赖、成功空结果和真正无权限分别表达。
- 复用现有事件驱动／服务端截止日缓存、SSE、请求取消与导航代次；意图预取只加载路由代码，不提前读取业务数据。
- 搜索沿用 300ms 防抖、中文组合输入和清空／回车立即提交；草稿沿用同标签页同身份内存、原版本与提交快照保护。关闭和切页保留输入，保存失败可重试，迟到成功不清后续编辑。
- 浮动下拉点击外部或按 Escape 收起；右侧抽屉点击遮罩、关闭按钮或按 Escape 收起。点击抽屉内部空白、选择下拉选项、从表单内拖动到遮罩不触发关闭；下拉打开时 Escape 先收起下拉。
- 收起只改变显示状态。表单按功能和资料编号接入同一 `state.drafts`，客户／租户、不同库存类型与不同记录分别保存。返回页面或重开抽屉恢复文本、选择项及勾选状态；确认弹窗点遮罩等同取消，不执行提交。
- 充值嵌入页通过同源共享草稿桥接保留明确列出的普通字段，不另建浏览器持久化缓存。整页刷新、退出登录或身份变化清理会话草稿；文件选择、密码／密钥、授权 JSON、验证码、兑换／查询码及单次付款确认不加入普通字段桥接。成功只清理对应提交快照，失败或后续输入继续保留。
- 首次内容最多三组 180ms／4px／20ms 间隔呈现，缓存仅首标题 120ms 淡入；表格和卡片直接显示。刷新、筛选不重播，快速导航取消旧动效，减少动态效果直接呈现。
- 正文按路由恢复阅读位置；左侧导航位置与展开状态继续遵守用户已确认要求，单独在 UI-03 验收。普通页面不新增 KeepAlive 或第二套缓存、会话及加载机制。
- 当前静态“状态预览”只证明视觉设计；正式页面接入和真实网络性能分别验证，不通过给原型添加假延迟模拟完成。

独立运行版通过 `IDDesignAPI.beginRegionRead` 共享 120ms 门槛、区域 `aria-busy`、同一区域的请求替换和刷新按钮状态。总览、苹果 ID 余额、员工与权限、邮件查询、比特登录、地址管理、ChatGPT 充值、兑换开通、网站访问统计、访问明细、邮箱池与费用规则重读已接入。首次读取可在区域内说明状态，有结果时只用细线；刷新失败保留可用内容。表单关闭和切页保留普通草稿，实际写入由保存操作触发；显式确认清除时，只能清除当时确认的内容。

2026-11-07 全局生命周期修复：普通页面继续按共享草稿重绘，成功读取的数据由同标签页内存快照复用。
ChatGPT 充值、兑换开通、比特登录三个嵌入运行时显式登记保留已连接的宿主区域，普通切页仅切换可见性，
不移动 iframe 或重载其文档；隐藏后暂停界面轮询并清理临时授权输入，运行中的任务继续受导航保护。
共享读取负责请求合并、保存后失效和身份清理，详情与实际验收见 [本轮修复记录](GLOBAL_LOADING_LIFECYCLE_20261107.md)。

## 4. 四类代表页面

### 4.1 邮箱管理

结构：顶栏唯一标题 → 库存/已使用/死号/解封中页签及主要按钮 → 搜索与筛选 → 单行数据表 → 分页。表格字段多时在表格内横向滚动，固定邮箱标识和操作入口；列设置管理显示字段。

| 类型         | 字段与分组                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| 谷歌邮箱     | 邮箱、密码、2FA 密钥、辅助邮箱、绑定电话、国家地区、应用专用密码、状态、来源渠道、注册时间、登录设备、备注 1、备注 2 |
| 苹果隐藏邮箱 | 保留现有主邮箱/隐藏邮箱、查询码、取信和注册能力的字段与稳定外部关联；补库存生命周期及操作记录                        |
| 微软邮箱     | 占位，第一阶段不编造完整业务能力                                                                                     |

谷歌邮箱必填：邮箱、密码、状态、来源渠道；未填写电话时须明确勾选“未绑定电话号码”。邮箱标识编辑时只读，其他字段可按权限修改。苹果 ID 已移至账号管理的“苹果 ID 余额”，保留邮箱、密码、密保 1/2/3、生日、电话、国家、设备、应用专用密码、状态、来源、注册时间及备注；新增余额列与变动记录入口，必填及无电话确认规则保留。

批量提交使用粘贴和 CSV：先预检，再显示类型、重复及逐行错误，确认后提交。格式检查与邮箱类型建议不等于验证邮箱真实存在；Apple ID 可使用 Gmail 地址，因此必须允许人工纠正类型。

“正常/冻结/封控中/死号/解封中”等账号状态与“未使用/已占用/已使用”等使用状态分开。库存、已使用、死号、解封中是稳定资料的视图，不复制到多个数据库。

上述字段在表格、列设置、筛选、录入、编辑、详情和状态操作中统一称为“账号状态”，用于表达账号是否正常；订单“待补全／资料完整”另称“资料完整性”，不与账号状态混用。

苹果隐藏邮箱的“主邮箱”页签单独显示“主邮箱编号”列，放在主邮箱地址之前；复用已有稳定编号，与隐藏邮箱记录的主邮箱编号及主邮箱详情一致，不使用行序号代替。

邮箱编号使用收件服务的稳定数字 ID：隐藏邮箱显示为 `y000005`，主邮箱显示为 `m000001`，至少六位数字，超出六位完整保留。列表、详情和搜索保持一致；内部关联仍使用原记录 ID。尚未接入且没有服务编号的记录显示“待接入”，不使用当前行号临时编号。

单条及批量登记隐藏邮箱只显示一个可搜索的“所属主邮箱”控件，按邮箱或短编号查找并选择。输入未匹配时清除原选择并提示，关闭重开保留输入；编辑已有隐藏邮箱时，所属主邮箱只读。

### 4.1.1 工作台账号提交

工作台在“邮箱提交”后增加“账号提交”（`workspace/account-submit`），作为账号管理的集中录入入口。首批为 GPT、Claude 和苹果 ID 资料三类；Gemini／Grok 继续占位，不显示可执行的提交入口。三类入口各提供单条录入和批量导入，复用库存表单、类型校验、草稿与导入记录。GPT／Claude 账号保存时按来源邮箱类型、地址、注册时间和领取记录核对邮箱使用；匹配明确时关联同一库存主档。

- 单条录入：按所选类型展示账号管理已有字段，账号邮箱与类型创建后保持稳定。GPT 保留邮箱类型、密码、2FA、国家、注册时间、设备、来源和备注；Claude 保留国家／城市、代理拆分及注册资料；苹果 ID 保留密码、密保、生日、电话、国家、设备、应用专用密码和备注。必填、无电话确认及注册时间校验沿用对应类型规则，录入时间由系统生成。
- 批量导入：支持粘贴与带表头 CSV，模板覆盖所选类型可录入字段；预检识别表头、额外列、类型、格式、必填、重复和逐行错误，不静默丢弃未知字段。先预览再确认，出现错误时整批不写入；确认前重验输入及重复项，避免陈旧预览和重复导入。
- 类型与草稿：从类型入口进入时限定本批账号类型，关闭重开保留该类型草稿；不同类型与邮箱提交的草稿、近期导入记录分别归属，不能串入普通邮箱类型或另一批数据。
- 苹果 ID 这里只录资料；余额、余额流水、已使用状态、养号和 KYC 派生结果不作为可导入字段。余额继续由独立流水能力维护，不能借资料导入增加资金。
- 保存与查询：单条或批量确认后进入同一账号管理主档，保留来源与导入批次，可从账号管理查看完整列和详情。本轮仍使用虚构内存数据，页面、接口、事务及数据库接入分别验收。

### 4.2 邮箱提取与账号提取

结构：类型与数量 → 用途与备注 → 确认提取 → 结果明细及批次记录。

- 邮箱提取选择邮箱类型；账号提取选择 GPT/Claude 等已开放账号类型。
- 用途包含对应注册目标及“其他”，选择其他后允许填写用途说明。
- 结果一条一行，支持选择、复制、逐项归还及批量归还；显示用途、提取时间和备注。
- 归还理由为“未使用”“死号”“解封中”，提交前显示本次影响资料和去向。
- “未使用”归还恢复本次库存占用；其他理由转入对应状态视图。操作追加历史，不删除原提取证据。
- 正式实现需在事务中分配，防止同时提取到同一条资料。数量不足明确提示，不静默减少。
- 已注册、已充值、关联有效订单或付款结果未知的资料，不能按“未使用”直接归还。
- 提取不等于已经使用。通过“提取与归还”中心查询多个批次、我的待处理、快捷粘贴归还和历史回执；批次详情支持登记部分使用、归还剩余项目。
- 邮箱用于注册后退出通用可提取库存，新账号的使用状态独立。正式订单只核对目标账号邮箱。已确认使用更新库存、使用依据与原批次；未确认订单、时间冲突或来源不明保留待核对，禁止直接归还。客户自有续费维持独立录单，不消耗同址库存账号。历史证据可通过“核对使用关联”复核和同步。已使用和健康状态分别展示。

### 4.3 Claude 专属

结构：状态页签与筛选 → 当前有效订阅表 → 续费、记录与付租抽屉。

邮箱账号、套餐、支付方式、卡尾号/ID、订阅时间、到期时间、订单状态、电话、验证状态、认证人、归属人等各占独立列，不要求订单邮箱分类。客户联系方式通过独立详情查看和复制；真实联系跳转属于未来接入，原型不联系客户。

- 套餐统一命名为 Pro、Max 5x、Max 20x，导航使用“Claude Max 订单”。
- 租户、归属人、认证人三者独立。租户是付租对象，主档保存姓名和电话；所属账号、开通日期及历史由订单和运营记录汇总。
- 专属页是订单、当前订阅与运营状态的组合视图，不能维护第二份可独立编辑的订单事实。
- 冻结和弃用保留状态发生时间；不自动退款或重写历史订单。
- 仅 Claude 提供快捷续费：带入当前账号和运营资料，可从当前到期续接一自然月，生成独立新订单后更新专属视图。通用客户续费不要求旧单存在，不增加原单关联或起算确认必填字段。
- 付租只记录“是否已发放租金”：按对象、账号及期间生成待发放批次，支持复制明细和逐项登记发放结果、时间、备注；不填写租金金额或币种，不追加成本，不自动转账。KYC 认证成本和代付服务费由费用设置管理。
- 养号小时数依据注册时间计算，默认 72 小时可用，阈值可配置；KYC 从对应有效订单读取。

### 4.4 比特登录与线上代充

比特浏览器以旧版 `e51dd9c9974c6292dbbc6572a5d844a672f0d0f1` 的「仅登录账号 → 授权 JSON」流程为基准。粘贴或导入授权后自动识别邮箱，核对分组和标签，打开本机比特窗口并核验官网登录身份。登录成功后保留窗口。

线上代充的 ChatGPT 工作区使用固定版本的 codexdaichong。在右侧内容区顶部用横向导航切换兑换、查询和后台运营视图。统一账号负责会话、权限和敏感操作授权。原项目负责兑换、任务、资源与支付业务。Claude 入口沿用既定页面。详见 [充值接入说明](../modules/recharge/README.md)。

工作台「兑换开通」参考 Vendure 的充值内容，按「自助充值／兑换码查询／使用说明」分为三个页签。说明提供操作四步、公开资料地址和虚构账号示意。保留验码自动锁定套餐、单个与批量查询和发票助手。

- 管理员或超级管理员新增 GPT／Claude 订单可搜索选择归属人员，默认当前账号，支持代员工录单。订单以稳定 ownerId 与姓名快照保存归属；录入人和审计仍由实际登录操作人确定。只允许选择仍启用的系统人员，保存时服务端重新核验。归属人展示于订单列表、详情与 Claude 专属；已有订单更正不更换归属。历史订单未存 ownerId 时沿用原来的录入／充值领取归属，不批量改写历史。此授权不扩大员工的订单管理权限。
- 邮箱分类只在邮箱／账号库存自身需要的资料中使用；不作为订单录入条件。国家、城市、来源、用途、套餐等按对应表独享，状态使用受控枚举。

## 7. 表格、表单与工具统一约定

- 一条数据一行，一个字段一列；不能在一个单元格叠放姓名和电话、标题和说明。
- 长内容单行呈现，提供完整查看和复制。列很多时用列设置和表格内部滚动，不压小文字、不遮住操作。
- 搜索、筛选和操作区宽度足够时同一行，不足时自然换行。第一页、末页与空状态保持页面框架稳定。
- 业务页面在权限校验后完整显示资料；底层继续加密，审计和日志不记录敏感原文。
- 标签始终位于控件左侧；必填星号紧跟标题右侧。窄屏允许减少列数、缩窄标签，但不改成顶部标签。
- 修改、提取、归还、状态迁移、删除、退款、续费、付租完成及充值提交等重要写操作先确认影响。
- 列表的“更多／更多操作”直接展开按钮旁的下拉菜单，选择后进入对应功能；不使用操作中转抽屉。邮箱、账号库存、订单、Claude 账号运营及员工入口统一遵守。编辑、详情和查询结果按各自功能展示，重置、状态迁移等继续保留必要确认与原有禁用条件。
- 隐藏邮箱列表的买家查询码直接显示完整值，并在同一单元格提供复制按钮；通过既有授权接口读取，不遮罩、不用“—”代替未读取状态。失败可重试，未接入收件服务明确说明；查询码不进入表单草稿或浏览器持久存储。
- 关闭抽屉与清空分开；失败保留输入，保存中防重复提交。正式实现复用项目会话草稿与提交快照生命周期。
- 顶部直接提供“个人工具”“在线工具”“话术文案”三个按钮，点击即打开对应右侧抽屉，不再经工具箱或抽屉内分类页签中转；完整内容与归属规则见第 7.1 节。手机将三个完整文字入口放在标题下方同一行。
- 轻工具在抽屉中使用，复杂工具进入工作区。第一阶段可演示个人工具名单管理；仅在用户主动点击已配置网址时打开新标签，不自动请求、同步、部署或执行其他外部任务。

第一阶段原型只在内存中展示完整名单及搜索、新增、编辑、删除、上下移动的管理示范，刷新重置，不代表已读取或迁移原有网址。截图没有给出的网址保持待接入，只有用户主动配置并点击有效网址时打开新标签；在线工具与话术的实际持久化、权限和执行能力在后续复用现有模块接入。原型名单、管理示范和真实业务接入分别验收，不把名单完整当作功能迁移完成。

## 8. 设计验收与产物状态

### 8.1 同类布局必须在共享层闭环

- 修复对齐、留白、溢出和闪跳前，先定位 `frontend/prototype.css`、`title-help.*`、`recharge-integration.css` 或充值 `shell.*` 的归属。共享选择器必须检查全部调用页面及变体，不以一张截图的局部覆盖作为完成。
- `.panel` 只负责卡片边框和背景，便于页签与表格贴合边框；表单、正文与底部说明必须放在 `.panel-body` 或已有的 `.form-panel`／`.panel-pad`／`.side-panel` 内，禁止把裸表单、说明或按钮直接放在 `.panel` 下。工具栏使用 `.toolbar`。共享内容横向内距由 `--panel-padding-inline` 管理：桌面 22px、1150px 及以下 20px、900px 及以下 16px；正文纵向内距桌面 20px、手机 18px。已带内距的内容区内，直接嵌套的工具栏、页签和表单分组不再重复叠加横向内距。
- 页首操作优先进入明确的 `data-page-actions` 插槽，其次复用现有工具栏、页签操作行或表单底栏；兜底必须生成带内距的工具栏，不能直接追加无内距的底栏。统计卡片允许金额单位在空间不足时换行，列宽不得被长内容撑破。
- 标题、搜索、筛选和操作按钮在空间足够时同排；字段标签在左侧。单行控件不得继承用于另一布局方向的尺寸或 `flex-basis`。并排表单组通过共享行轨道对齐，测量实际标签及控件，提示和错误不能令下一行错开。
- 充值导航使用可横向滚动的单行，刷新按钮保持可见；库存和详情页签重绘后保留横向位置，并使当前选中项完整可见。不得用多行导航挤占手机正文。
- 900px 及以下顶栏保持在视口上方，手机长页面无需回到顶部就能打开导航；为控件滚入视口预留顶栏高度。使用 `test/mobile-navigation-layout.browser.mjs` 检查菜单展开／取消、实际侧栏切页返回和阅读位置，不能只用修改 URL 的方式代替手机操作路径。
- 多页列表的每页条数、上一页和下一页保持可见，数字页码在中间区域横向滚动；重绘沿用共享横向位置恢复，使当前页完整可见，不能让卡片的裁切掩盖分页溢出。分页按钮桌面 36px、手机 44px，键盘焦点线收在按钮内部。使用 `test/design-list-boundaries.browser.mjs` 覆盖首末页、空结果、长名单及详情抽屉；窄屏先压缩顶栏间距，保留 44px 触控尺寸，避免短标题被挤成两行。
- 标题说明复用共享顶层浮层定位；限制在当前视口内，避免被卡片、抽屉或容器裁切，开关不得挤动正文。
- 嵌入内容先在不可见但可测量的区域获取实际高度，再切换可见内容；禁止默认占位高度进入可见帧。表格先保持表头及列内容可读，再在表格容器内横向滚动，不能压成逐字竖排。
- 没有汇率等辅助资料时，保留紧凑的状态说明，不保留空的固定宽度侧栏。不能为了填满空白而编造资料或增加功能。
- 本独立项目的共享布局回归入口为 `test/shared-layout.browser.mjs`。使用已有 Playwright：`ID_RECHARGE_QA_PLAYWRIGHT=/absolute/path/to/playwright/index.js ID_RECHARGE_QA_BROWSER_CHANNEL=chrome node --test test/shared-layout.browser.mjs`。测试服务使用内存资料，不连接业务数据库。新模块加入本测试覆盖清单后，再按桌面、平板、手机、深浅主题和实际使用状态验收。
- 不允许启动本机网站时，给共享布局、手机导航及列表边界三个脚本设置 `ID_LAYOUT_QA_OFFLINE=1`，通过浏览器请求拦截加载实际静态文件和隔离合成资料，不创建监听服务、不连接数据库。全站贴边回归另运行 `node test/site-spacing.browser.mjs`（默认离线模式，可沿用 `ID_RECHARGE_QA_PLAYWRIGHT`），覆盖全部导航页面、页签、代表性抽屉、320—1440px 和深浅主题；证据写入项目 `.runtime/site-spacing-20261107/`。几何检查不代替截图复核或真实业务验收。
- 充值切换另运行 `test/recharge-layout-transitions.browser.mjs`（沿用上述环境变量）：让新页面延迟返回后逐帧检查旧内容是否保留、是否出现临时撑高；再验证连续选择的最终页面和刷新失败保留。覆盖 1440／390px 深浅主题。可用 `ID_LAYOUT_QA_OUTPUT` 指向项目内目录保存逐帧几何记录与截图。几何通过不能代替肉眼确认黑线等绘制问题，未复现必须单列。

### 8.2 验收范围

以 1440px 桌面和 390px 手机为主要设计稿，并覆盖 1024、901、900、768px 断点。验证深浅主题、菜单、页签、抽屉、表单标签、重要操作确认、单行表格、空状态、长内容及键盘焦点。

真实验收应记录视口、状态、可见结果与限制；当前原型状态和浏览器实测结果以同目录交付记录为准。本设计文档不是测试通过证明。

后续进入业务 UI 实施时运行项目七项规则检查及相关类型、测试、lint、构建，使用实际路由验收。设计原型不能替代数据库并发、账务、权限、支付、迁移、生产或业务结果验收。
