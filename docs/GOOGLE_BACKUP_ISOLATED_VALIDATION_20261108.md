## 验证实现

1. `MysqlNativeBackupSource` 检查服务器 UUID、InnoDB 表和导出坐标；`mysqldump --single-transaction --source-data=2` 输出直接进入 gzip 和公钥加密，不产生明文导出文件。调用方须冻结 DDL；开始快照时的短暂全局读锁不等于生产性能已验收。
2. 实际读取服务器日志清单，拒绝已清理、缺段、倒序或服务器身份变化的增量范围；用 `mysqlbinlog` 原生读取连续日志，覆盖日志轮转。
3. 测试在源库提交两段事务，包含修改、删除、中文、加密字段和精确 Decimal；全量恢复及两段增量恢复后，分别与对应源快照逐表、逐字段、逐行和对象摘要比较。
4. 比较范围包含全部应用表、`_prisma_migrations`、列、索引、外键、CHECK、触发器、函数和事件。显式执行恢复后的完整性函数，检查 definer 可用性。
5. 数据库内附件及单独二进制附件恢复后核对 SHA-256。文件私钥不写入队列或 Google。
6. 真实 Linux `flock` 验证双进程互斥和释放。上传协议的掉线、断点恢复、重试、重复任务、校验和前序校验使用受控 Drive 模拟，不连接 Google。

解密 SQL 只出现在 CI 的私有恢复目录，导入后立即清理。任务结束只保留不含行数据、凭据或密钥的 `report.json`；不上传 SQL、备份文件或原始进程输出。
