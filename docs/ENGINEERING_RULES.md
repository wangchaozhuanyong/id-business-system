# 页面与数据交互统一规则

更新：2026-11-12。适用于本独立项目的新增页面、功能、抽屉、嵌入适配和共享组件。

本文件是当前工程行为的统一入口。用户最新明确要求优先；业务字段、导航、视觉尺寸以 `DESIGN_SPEC.md` 及已批准业务修订为准。`AGENTS.md` 管执行权限。带日期的基线、方案、报告用于追溯，不再构成另一套运行规范。旧 Vue 项目的路径、组件名和轮询方案不得直接带入本项目。

## 1. 设计、布局与反馈

| 规则 | 共享实现 | 必须验证的状态 |
| --- | --- | --- |
| 保留已批准导航、业务入口及布局；同类问题修所属共享层 | `prototype.css`、`tabs.css`、`title-help.*`，嵌入适配仅改外围 | 深浅主题、宽窄容器、手机和长内容 |
| 同一页名只出现一次；用途/字段说明放标题或标签右侧 ⓘ，默认收起 | `header()`、`titleInfo()`、`field()` | 点击、键盘、Escape、外部关闭；浮层不挤动内容、不裁切 |
| 工具栏不足时整组换行；按钮、搜索到分隔线 ≥8px，紧凑上下内距 12px | `--toolbar-padding-block`、`.toolbar`、`.list-controls` | 实际可见文字与控件几何；收起说明内的链接不参与工具栏同排测量 |
| 正文使用共享内距，字段标签在控件左侧；不以缩小点击区掩盖溢出 | `.panel-body`、`.form-panel`、共享表单行 | 320/390/768/900/901/1024/1440px；按需补宽屏 |
| 列表使用公共分页与菜单；默认20条，可选10/50条 | `IDPagination`、`openActionMenu()` | 首末页、空结果、长资料、详情；空表说明按可视表格宽度呈现 |
| 手机导航始终可达；切页保留阅读与侧栏位置；普通页不长期保留 DOM | `go()`、`navigate()`、`activePageRegion()` | 滚动后打开/关闭菜单、切页返回、快速连续切换 |
| 真实成功才反馈成功；局部提交、局部读取各有一个反馈归属 | `notify()`、`beginActionFeedback()`、`beginRegionRead()` | 失败保留内容，取消不执行，重复点击不重复提交 |

不得为追求测试通过隐藏业务控件、删断言或只覆盖截图所在页面。可见布局断言排除默认收起的说明内容，同时单独验证它确实收起并可打开。

## 2. 读取与刷新

**统一方案：提交后的版本通知（SSE）驱动相关范围失效，再局部读取。** 没有新版本时不重复读取业务列表，不整页刷新；页面首次加载、用户主动刷新/查询、业务实际到期和恢复遗漏版本按下列规则处理。

1. 先识别数据来源和范围（scope）。复用 `IDLocalData.queries`：同身份、范围、规范化参数下合并未完成读取；缓存仅在本标签页内存。不得新增第二套 localStorage 业务缓存或用固定 TTL 驱动页面刷新。
2. 首次没有快照显示真实加载状态；不能将未知计数画成0。回访有效快照直接显示。同参数重读保留内容，超过120ms由 `beginRegionRead` 显示不占文档流的细线。
3. 请求条件与已展示结果分开；新结果、总数、页码成功后一起替换。失败保留上次结果和重试入口，不把失败当空列表；缺依赖、无权限、成功为空分别表达。
4. 旧请求必须校验查询代次、当前路由/实体和身份。范围失效、清空、换参数、切页之后，旧响应不得覆盖新状态。`READ_SUPERSEDED` 不可当正常成功或清空已有内容。
5. 写事务提交后发布版本，回滚不发布。通知只含范围和版本，不带业务正文或凭据。个人范围沿用服务端账号隔离；管理范围沿用现有权限。
6. 浏览器比较版本；同版本、心跳和本页已确认保存版本不重读。新范围先失效，再让相关模块 `onDataChanges(scopes)` 或现有共享分派读取；共享基础资料按依赖刷新；仅页面使用的隐藏区域保留失效标记，回访再读。
7. 数据变更读取失败最多自动重试三次，之后保留手动重试；新版本另行处理。模块必须返回 `false`/拒绝 Promise 表示当前读取失败，不能吞错后让共享层误确认成功。
8. 断线只重连事件流，按退避控制；重新连接比较快照补上遗漏版本。不得恢复旧文档的“每15秒补偿查版本”。心跳维持连接，不查询业务列表。
9. 开着表单不阻塞旁边列表的新数据；保留输入、焦点和原始编辑版本。确认框、操作菜单、在途写入及后台标签页暂缓应用更新，解除后合并补上。
10. 业务到期是一次性截止时间事件，例如订阅开始/到期、提醒边界、报价失效、监控观察过期。计时显示可更新数字；不得借倒计时定时请求整个列表。

监控中心使用同一 `system-monitoring` 范围：持久化配置/事件版本与当前进程的观察版本共同识别变化；新观察和实际5分钟失效边界触发通知。服务器重启更换观察版本前缀。未变化的普通页面不会每分钟读取监控接口。

## 3. 搜索、切页与草稿

- **即时列表搜索**在输入上声明 `data-auto-search` 和稳定 `id`，复用 `search-input.js`。共享层300ms合并输入；中文组合期间不提交、不替换输入节点；组合结束后提交；清空和非组合回车立即应用并取消旧计时器。
- 原始输入与已应用条件分开。其他重绘保留尚未应用的输入；离页/关抽屉停止旧计时器，同身份返回恢复；身份清理取消全部。不得由各模块另建250/300/500ms搜索计时器。
- **已有显式“查询”表单**（如订阅筛选、地址筛选）仍按提交按钮/回车查询。选择器内部的本地选项筛选保留直接反馈；需请求服务器的客户检索使用同一输入防抖，并核对响应仍对应当前关键词。两类控件不标 `data-auto-search`，不擅自改变其业务交互。
- 导航使用 `IDDesignAPI.go()`，搜索/分页操作归属当前可见 `[data-page-region]`；禁止用文档中第一个同名隐藏控件驱动业务。
- 普通表单使用 `state.drafts`、模块 `preserveDraft()` 和 `readDraft()`，键含功能和实体；取消、关闭、切页保留普通输入。敏感临时授权、验证码、文件和单次确认按现有 `data-no-draft` 等规则排除，不扩大敏感资料留存。
- 提交捕获当时的资料、实体和原版本。成功只清相同提交快照；失败、晚返回及请求期间继续输入不能清后续草稿。列表刷新失败不能把已成功保存说成保存失败，也不能自动重发写入。
- 仅已登记的 ChatGPT 充值、兑换开通和比特登录保留连接中的宿主；隐藏暂停界面活动，任务状态由原执行器管理。普通页不加入无限常驻列表。
- 退出/身份失效沿用既有会话边界，清空共享读取、版本跟踪、待应用搜索、保留宿主和临时授权；不能把前一账号的异步结果交给后一账号。

## 4. 多人操作与重复提交

| 场景 | 必须遵守的协议 |
| --- | --- |
| 两人修改不同客户/租户的普通资料 | 复用 `contact-write.mjs`，在事务内按原快照合并单条记录；不覆盖别人的其他记录 |
| 两人修改同一资料 | 比较原始内容与版本；冲突停止覆盖，保留填写与差异；用户明确确认后才用最新资料替换当前填写 |
| 订单、库存、余额、银行卡、批量联动 | 保留现有事务、版本、库存及归属约束；不可套用普通资料自动合并 |
| 响应丢失/重复点击 | 客户端局部防重；通用保存复用同一 `X-ID-Operation`，服务端按操作人隔离并校验请求摘要，回执与业务同事务提交 |
| 不同请求复用了同一操作编号 | 拒绝，不能返回另一笔保存的成功 |
| 外部付款/充值结果未知 | 使用原任务与既有核验流程；不能因超时重新下单、付款或修改执行器行为 |

版本检查和幂等必须在服务端成立，按钮禁用只是界面保护。新实体/新命令需补自己的并发、原子性及重复执行用例；已有协议不能自动证明新接口安全。修改登录、权限、数据库结构或支付必须按 `AGENTS.md` 另行办理。

## 5. 性能规则

- 列表不得在每行内反复全量扫描同一客户、订单、邮箱或账号集合。复用当前快照派生索引；重复标识的歧义判断、原顺序和业务约束必须保留。
- 索引在快照替换/本地修改时失效；后端派生索引只在本次计算内使用，不跨请求缓存不同用户数据。
- 优先测实际输入、切页、列表与查询复杂度；不能用延长刷新间隔、假加载或隐藏功能掩盖卡顿。
- 绑定的监听、观察器、未完成读取与一次性计时器必须有离页/身份清理入口；持续切页要检查请求数和 DOM/监听是否稳定。
- 大数据验证至少覆盖1000/10000条合成资料。测试机耗时不能冒充线上速度或真实用户 INP。

## 6. 新页面交付门禁

开发前登记：路由/入口、数据范围、读取参数、即时搜索或显式提交、草稿键、原版本来源、写入防重、生命周期清理及外部依赖。优先复用以上共享实现，不复制一套近似机制。

完成后在本项目根目录运行：

```sh
node test/check-ui-contract.mjs
```

该入口只执行明确列出的无数据库单测和请求拦截浏览器检查；默认证据位于 `.runtime/ui-contract/`，可将 `ID_LAYOUT_QA_OUTPUT` 指向本项目内目录。需已有 Playwright/浏览器和已准备的锁定充值静态资产。缺依赖时报错，不自动安装大型依赖或启动网站。首次运行全部组；修复失败后可在同一证据目录执行 `node test/check-ui-contract.mjs browser` 等组名复查，结果会合并，未执行完全部组不会报告整体通过。

覆盖：版本/缓存/并发纯逻辑、真实DOM搜索与输入法、全导航静置请求检查、监控推送、共享布局、分页长名单、手机导航、充值慢切换/失败保留、页签、说明和操作反馈。导航静置用例动态读取当前导航，新注册页面自动进入检查；嵌入原版 API 的轮询不计作本机业务接口通过。

列表或共享布局修改必须继续运行对应专项（该入口已包含）：`site-spacing`、`mailbox-query-layout`、`shared-layout`、`mobile-navigation-layout`、`design-list-boundaries`、`recharge-layout-transitions`。新功能仍需补充真实成功、首次失败、重读失败、空结果、长资料、双客户端冲突、重复提交、离页迟到、草稿和身份切换案例。已有合成快照不能替代新功能真实接入验收。

本入口不改 CI 配置、不运行数据库测试、不提交或部署。`npm test` 包含数据库用例，与本地无数据库门禁不同；当前本机禁令下不能直接运行。所有通过结果必须附实际日志；失败不得记作完成。

## 7. 现存边界与未完成项

- 外部充值成功任务仍由 `server/preview.mjs` 的60秒导入扫描发现，原版活动界面保留其轮询；其全局数据事件来源尚未接通。当前锁定上游只支持已知任务订阅，不能据此保证其他窗口新任务实时出现。外围 CDC/提交后事件方案需明确接入权限和真实环境验收，不能改锁定执行器或删掉现有导入导致漏单。
- 谷歌、苹果主邮箱、微软邮箱的自动更新改为 IMAP IDLE → 同源POST事件流 → 既有查询。默认仍关闭；无邮件事件不查信，重连/回到可见页面核对一次快照，相同内容不重绘。共享邮箱连接，离页/关闭抽屉/换查询码/身份清理停止监听；到期、改绑或停用关闭对应订阅。保活不是业务刷新。代码与离线验收已完成，真实服务商和线上长连接仍待验证。
- 苹果隐藏邮箱由外部Vendure服务提供，目前没有已接入的事件出口，仍保留用户主动开启的30秒自动查询；不能将普通邮箱已接入等同于该来源已完成。充值与该邮箱来源的具体接入边界见 `EXTERNAL_EVENT_ACCESS_20261112.md`，后续不复制这个轮询例外。
- 后台监控探测、汇率采集、任务执行及 TOTP 计时是现有业务作业，不是浏览器定时刷新列表。其规则与本文件的页面刷新协议分别验收。
- 本轮用户单独批准的3项隔离SQLite测试已通过：重启后回执与改体重放拒绝、不同资料双进程保存、同一资料双进程冲突。授权仅限本次合成测试；数据库及整站的一般本机禁令继续有效。真实HTTP会话/跨账号隔离和其他业务并发仍需对应环境验证。
- 线上版本、代理/SSE超时、网络耗时和真实业务结果须发布后另验。本轮无提交、推送、部署授权，不把本地修复说成线上已生效。
