# 微软邮箱管理与接入计划

## 第一阶段 · 邮箱库存

「邮箱管理 → 微软邮箱」登记个人 Microsoft 账号，包括 Outlook 和 Hotmail。自注册、线上购买、客户提供共用字段，以来源渠道区分。每条资料沿用库存编号，邮箱地址创建后只读。第一阶段各登记一个主要辅助邮箱和绑定手机号，可同时登记多种验证方式。实际登录方式、两步验证状态和取码能力由录入人核对后登记。

| 资料 | 录入规则 |
| --- | --- |
| 邮箱账号、登录方式、登录密码 | 邮箱、登录方式必填。同类型地址忽略大小写去重。密码登录填写密码，无密码登录清空密码并选择实际验证方式。 |
| 辅助邮箱、取码方式 | 支持未核验、系统内邮箱、人工取码、无法取码。已登记取码方式或使用邮箱验证码时填写辅助邮箱。选择系统内邮箱时关联现有库存编号，目标须唯一且与地址一致。批量录入时先登记作为辅助邮箱的记录。 |
| 两步验证、验证方式、验证设备或确认人 | 两步验证默认未核验。可多选邮箱验证码、Authenticator 手机确认、动态验证码、通行密钥、短信验证。确认用的设备或人员按实际填写。 |
| 手机号、2FA 密钥、应用专用密码 | 选填。只有实际掌握动态验证码密钥时才录入，并选择动态验证码。应用专用密码用于留存已有的兼容客户端凭据。 |
| 国家地区、来源渠道、注册时间、登录设备、备注 | 来源渠道与账号状态必填。空白注册时间以系统录入时间补齐，原注册时间、录入时间和最近操作时间分别记录。 |
| 状态、录入人、最近操作人、导入批次 | 沿用库存状态及死号、解封中视图。操作人由会话确定，导入前逐行预检，同类型重复或任一行错误整批退回。 |

库存资料使用现有加密 `business_document` 的 `inventory.mailboxes`，以 `type: microsoft` 区分。通用字段沿用密码、辅助邮箱、手机号、2FA 与来源等已有属性，`microsoftSecurity` 保存登录方式、取码方式、两步验证、验证方式、验证设备及可选的 `recoveryMailboxId`。沿用库存版本校验与操作审计，登录身份读取含微软邮箱的库存时记录操作者与版本。详情可回查有权限查看的辅助邮箱资料，关联失效时显示需核对。批量预览、导入回执、操作日志和批量复制均不带密码或 2FA 原文。

个人 Microsoft 安全信息与两步验证以官方账户设置为准。短信属于可能仍存在的验证方式，Microsoft 正逐步停止将 SMS 用于个人账户身份验证与恢复。托管取信使用实际授予的 OAuth 权限和已有查询连接。 [Microsoft 安全信息与验证码](https://support.microsoft.com/en-us/accounts-billing/manage/microsoft-account-security-info-verification-codes) · [Microsoft 邮件 OAuth](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth)

## 后续接入顺序

| 阶段及入口 | 当前谷歌邮箱的关联 | 微软邮箱接入与验收 |
| --- | --- | --- |
| 2A · 系统设置 → 邮箱分类；管理快捷 → 邮箱提交 | 全局分类决定快捷提交、提取、账号邮箱类型等候选。快捷提交复用库存录入和导入记录。 | 先分开“允许登记”和“允许提取/下游选用”两项能力。快捷提交复用本次微软校验、批次记录和独立草稿。旧开关读取保持原语义。 |
| 2B · 邮箱提取、提取与归还 | 工作台按邮箱类型和资格筛选，记录提取批次、用途、领取人、时间、归还与异常。快捷核对按类型找原批次。 | 在同一库存版本内核验正常、未使用、未领用及用途所需的登录／取码条件。领取后生成唯一明细，限制原领取人或授权管理员操作。同步接上批次详情、快捷查找、状态和归还。验证同一条并发提取只有一笔成功，明确使用后的归还被拒绝。交付模板按密码或无密码模式区分所需资料。 |
| 3A · 账号提交、GPT／Claude 账号及邮箱注册结果 | 账号登记或批导选择邮箱类型。谷歌可登记注册结果，实际成功、待核对和未成功分别留历史。 | 加入微软邮箱类型；有库存来源时选定 `assetId` 和有效 `claimId`，记录目标产品、登记人、结果和时间。客户自有账号只记录来源。单条、批量、编辑和回读采用同一规则。 |
| 3B · 库存使用核对、GPT／Claude 订单与费用规则 | 账号、注册结果及有凭据的订单会触发核对。订单已支持微软邮箱成本配置和选用账号时的费用映射。 | 优先按稳定编号匹配库存与订单。历史记录只有规范地址、类型及可核实的领用或归属证据一致才可关联。重名、缺证据、客户自有等进入相应核对或跳过，不自动消耗库存。验证重复回执幂等、历史费用快照与已核算订单原值保留。 |
| 4A · 在线工具 → 邮箱查询、托管邮箱池及 Claude 邮箱候选 | 谷歌库存、托管连接、Claude 候选是不同数据来源。微软托管邮箱已经有独立授权入口。 | 以库存编号关联已授权的托管邮箱编号，核对实际地址、服务商与授权范围。授权失败、过期或撤回时显示状态和重授权入口。OAuth 凭据留在既有托管连接，只有明确操作才发起查信或建立买家查询码。 |
| 4B · 数据管理 → Claude 谷歌订阅管理 | 该报表按谷歌类型、谷歌邮箱库存和托管连接核对现有 Claude 订阅。 | 保留谷歌报表原有范围。若需要同类微软订阅跟踪，单列微软视图和授权状态，采用对应微软连接。 |
| 5 · 网站总览、员工数据统计、Google Sheets、备份 | 总览汇总谷歌可用、待归还和异常。员工统计读取库存录入和领用记录。Sheets 区分库存与托管池，整库备份保护加密库存文档。 | 总览在领取规则接通后分别展示登记、可提取、待使用和异常。员工统计已按通用入库规则纳入微软记录，后续验证新领用及归还归属。Sheets 在确定范围后启用微软库存元数据映射，继续隔离登录、绑定、授权与验证码资料。现有加密备份包含库存文档，恢复验收应核对记录数和关联编号。 |

实现对照入口为 `frontend/inventory-prototype.js`、`frontend/operations-prototype.js`、`frontend/commerce-prototype.js`、`frontend/overview-prototype.js`、`server/inventory-usage.mjs`、`server/tools/claude-mailbox-candidates.mjs`、`server/claude-google-subscriptions.mjs`、`server/employee-statistics.mjs` 和 `server/backup/sheets-source.mjs`。阶段 2–5 为后续开发范围。
