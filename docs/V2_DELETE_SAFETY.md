# V2 删除安全规范

## 目标

当前系统以状态流转、冲正和审计留痕代替业务数据物理删除。任何新增删除入口都必须先确认它是否会改变库存、财务、订单、客户、仪表盘或历史报表结果。

## 当前删除影响清单

| 对象                 | 当前行为                                                         | 影响判断                                                                             | 处理规则                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| ID                   | 不提供删除接口和删除按钮                                         | ID 被礼品卡、余额流水、订单、锁定、开通记录和报损记录引用，删除会破坏业务链路        | 仅允许可用、停用、已售出、已报损之间的受控状态流转；停用必须填写原因                                                                                 |
| ID 报损记录          | 不提供删除接口                                                   | 报损会生成余额扣减和财务分录；删除记录会让账务失去来源                               | 只允许恢复；恢复必须生成冲正记录并保留原报损记录和审计                                                                                               |
| 订单                 | 软删除，仅允许已退款、已取消或失败订单，并要求原因               | 软删除后会退出普通订单列表和仪表盘统计，因此会改变报表可见结果；财务和余额流水仍保留 | 仅限误录清理；正常业务修正优先退款、取消或冲正。执行前后必须复核报表和审计                                                                           |
| 客户                 | 软删除                                                           | 会退出客户列表和新增订单候选；历史订单仍通过外键保留                                 | 日常不用“删除”代替停用；有历史订单的客户优先停用。确需软删除时保留审计并通过数据治理恢复                                                             |
| 员工账号             | 仅唯一超级管理员可预检查后软删除                                 | 禁止登录并撤销全部会话；移交业务管理权，原业务、创建人、审计及账务不变               | 日常保留或停用账号再复用；执行中充值任务或付款结果未确认时拒绝删除。业务接管和审计在同一事务完成；重复确认幂等，影响变化时重新确认，禁止物理删除用户 |

| IP 白名单            | 物理删除配置记录                                                 | 不影响业务报表，但可能影响系统访问                                                   | 仅唯一超级管理员可操作；系统必须先确认删除后当前请求 IP 仍被剩余启用规则覆盖，并写审计                                                               |
| 开通银行卡资料       | 管理员从账号页预览并确认后物理删除                               | 退出银行卡清单和付款候选；订单、订阅、任务及财务不删除                               | 有未结束充值任务时拒绝；删除前写入卡名称、加密脱敏卡号和删除时间，外键置空；账号保留首位与末八位及已删除状态，保留姓名盲索引绑定与审计               |
| 表格列偏好           | 物理删除当前用户的一条界面配置                                   | 不影响业务数据或报表，只恢复默认列                                                   | 可保留“恢复默认设置”，不使用业务“删除”措辞，并写审计                                                                                                 |

## 银充与 ChatGPT 账号补充规则

- ChatGPT 账号只有没有官网核验或业务引用时可预览并软删除；停用且保留加密凭据、邮箱/官网唯一键，不再物理删除。恢复必须通过数据治理提供备份证据和异人审批，仍保持停用。
- 银充仅手工误录、未过账、无真实付款/收款/财务和续费来源引用时可作废；自动付款、已核验付款与过账单据使用实际更正或退款。作废只取消确实指向本单的活动投影，不影响后来订阅。
- 作废误录单可软删除进入回收站。未软删的作废单恢复为待补全；软删单通过数据治理独立审批恢复。两者均清空未核对的开通/到期日期，不生成账务或激活订阅，不释放原付款/证据唯一键。

## 明确禁止物理删除的记录

员工软删除的接管范围包括充值任务／记录／地址、已保存的业务动态口令和中转部署任务，原编号与来源保持不变。
有效的中转执行租约也会阻止删除；任务两次执行步骤之间已释放租约时，可接管已保存的进度。
同名资料不合并、不覆盖。员工登录 MFA、个人界面和外部连接凭据不移交；继续中转部署使用接管人的已授权连接。

- ID、礼品卡、订单、开通记录和 ID 锁定记录。
- ID 余额流水、供应商余额流水、财务日记账及其明细。
- ID 报损记录以及报损、恢复产生的原始和冲正记录。
- 审计日志、敏感资料查看日志和数据治理审批证据。
- 已被业务单据引用的客户、选项、汇率快照或附件关系。

数据库关系继续对上述业务链使用 `Restrict` 或保留引用的软删除设计，不得改为级联物理删除。

## 新增删除功能的准入检查

新增或恢复任何删除按钮、接口或批量清理前，必须同时满足：

1. 列出所有直接和间接引用，以及受影响的列表、导出、仪表盘和财务报表。
2. 优先提供停用、取消、冲正或恢复机制；无法恢复的物理删除必须说明保留期限和法规依据。
3. 创建、修改删除状态和清理操作均写审计；审计中不得记录密码、密保、完整卡号或 token。
4. 高风险操作必须先预览受影响数量，并在独立确认后执行；执行时重新检查数据是否变化。
5. 自动化测试必须覆盖不可删除状态、引用保护、幂等、审计和报表可见性。

## 本次 ID 生命周期结论

- 已售出 ID 不允许停用或报损。
- 已停用 ID 必须保留停用原因和停用时间，可重新启用。
- 已报损 ID 从 ID 管理主列表分流到报损记录，可手动恢复，但不可删除。
- 已停用和已报损都不是数据删除；原始业务、金额和审计链完整保留。
