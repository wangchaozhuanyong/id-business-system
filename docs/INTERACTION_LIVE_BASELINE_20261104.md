## 3. 导航与滚动的新版补充要求

线上 `V2AdminLayout.vue:499`、`:567` 已按 `route.fullPath` 保存和恢复**正文** `contentElement.scrollTop`，聚焦使用 `preventScroll:true`。这部分继续复用。

左侧导航是独立验收项：用户明确要求切换页面后保持左侧位置及合理的展开状态。e51 同文件 `:585` 会随路由设置单个 `openSectionKey`，目前源码核对没有取得左侧滚动恢复证据。当前设计原型 `prototype.js:664` 已保存和恢复 sidebar `scrollTop`，继续保留这个行为。正式 UI-03 应在现有布局层核对并补齐侧栏位置，覆盖跨分组、返回、折叠、手机收放、键盘聚焦和快速切页；正文恢复不计作左侧已完成。

## 4. 当前原型与正式实现的差别

| 当前入口               | 已有内容                                                                   | 仍需正式接入的部分                                                                    |
| ---------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 设计原型的状态预览     | 手动切换正常、首次加载、刷新、错误、空数据和权限的视觉示例，不发送网络请求 | 不能证明 120ms 时序、clean 缓存、参数过渡只读、请求取消或真实权限已实现               |
| 原型导航及输入         | 有内存草稿、路由条件恢复和侧栏滚动保留                                     | `render()` 会重建主要内容，没有生产查询缓存、导航代码加载、身份代际或认证故障恢复能力 |
| Vue 标题／抽屉离线预览 | 验证当时实际组件的标题、草稿及局部行为                                     | 旧构建来自当前工作树，只证明各自记录的源码，不代表 e51 全套加载或导航已接入           |
| 新版正式页面           | 按本矩阵复用线上共享层并接入真实模块                                       | 每页记录实际 phase、权限、scope/key、列表条件、草稿及加载归属，逐项验收               |

本轮不为原型增加假网络延迟、第二套查询缓存、第二套会话或平行加载状态机；保留其明确的演示属性。原型的立即刷新条和固定形状示例不能作为正式加载实现移植。

## 5. 开发接入与验收顺序

1. 在隔离候选登记 e51 源码与待合入新设计清单，保护主目录 WIP。会话、Router、查询、缓存、加载区域、草稿、搜索、呈现动效和表测量作为同一套既有机制核对，不逐页复制私有实现。
2. UI-03 先验证正文和侧栏位置；UI-08 每个正式页面接入 `V2AsyncRegion` 及唯一主 `useV2ModuleQuery`，辅助选项声明加载归属及 `enabled`，表单和条件登记共享草稿。
3. 验收冷启动、缓存回访、快于／慢于 120ms 的刷新、参数切换、成功空结果、首次／刷新失败、依赖未就绪及真实无权限；检查主反馈唯一、框架和实际文字稳定、旧结果只读。
4. 验收 A→B→A 快速导航、迟到响应、资源失败及重试、正文与侧栏位置、抽屉导航失败、保存期间继续编辑、身份清理、中文搜索与重置、深浅主题及减少动态效果。
5. 运行受影响的类型／单测／lint／构建、项目 UI 与加载规则；实际前端交互可用项目既有离线拦截验收。真实 API、SSE、网络和线上耗时另在获准的隔离环境验收，不能用历史 P95 或静态包回读替代。
