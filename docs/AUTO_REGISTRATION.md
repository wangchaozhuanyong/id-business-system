# 自动注册 GPT 与名字数据表

本功能由系统私网执行器使用内置 Camoufox 指纹浏览器执行，一次只处理一个已授权邮箱。自动注册不连接比特浏览器，不要求管理员配置本机连接器、浏览器分组或标签。代码与本地验证不代表已经上线或真实注册成功。

## 页面与资料

左侧“自动注册”提供“自动注册 GPT”和“名字数据表”。名字支持新增、修改、启停和每次最多 2000 项的逐行导入，每个名字最多 120 个字符；重复项跳过。自动选择启用名字中被选次数较少的项，任务建立后固定姓名和原浏览器窗口，重试不重新随机资料。

名字导入接口单独允许最多 1MB 的 JSON 请求，覆盖 2000 个较长中文名字；其余接口沿用默认请求大小限制。

注册邮箱从“邮件验证码查询”的有效邮箱别名选择，代理使用现有已启用目录。确认邮箱授权；年龄可直接填写 20 至 45 岁的整数（例如 25），无需填写完整出生日期。年龄留空时，在点击“开始注册”创建任务时随机生成 20 至 45 岁的整数。名字为空库、邮箱过期、代理不可用、指纹执行器未就绪或已有执行任务时不能开始。

“自动注册 GPT”提供“隐藏邮箱／未注册／已注册／注册任务”四个页签。三个邮箱视图共用完整源邮箱清单，包括停用邮箱，合并账号的独立 registered 状态后搜索、分类、统计和分页，按邮箱更新时间和编号稳定排序。无账号视为未注册；邮箱启用状态与注册状态互相独立。注册状态是资料登记状态，不代替原任务中的官网登录、密码或 MFA 核验。

管理员可在三个邮箱视图的“注册状态”下拉中选择已注册或未注册，再确认实际结果，系统从源邮箱读取真实地址，使用本地事务加密保存对应 ChatGPT 账号并写脱敏审计；密码与 2FA 不被伪造，可在账号页补充。重复标记复用已有账号，不覆盖密码、2FA、停用状态或备注。全部未结束的同邮箱任务（包括授权过期、部分完成及关闭未确认）阻止状态转换，需先结束或确认取消原任务；改回未注册保留已有账号和安全资料；人工标记不改写自动任务的安全验证结果。该操作不新增、修改或删除邮件验证码查询中的邮箱，也不启动官网注册或付款。

ChatGPT 账号新增“优惠状况”，支持筛选和修改：待核实、0元购、半价号、全折扣号、其他优惠。旧账号默认待核实。自动识别只根据当前已核实账号明确展示的优惠卡片；没有优惠入口、普通升级按钮或普通价格不能证明资格。未识别时保持待核实，可人工修改；人工标记不会被自动结果覆盖。当前“全折扣号”和“其他优惠”通过人工核对设置。

ChatGPT 账号清单提供独立“国家”列，新增与编辑可选择或清空国家。自动注册在官网身份核实完成时，通过原注册浏览器的同源网络观测读取真实出口国家，保存首次确认的注册国家快照；不依据代理目录配置、服务器或首次／最近登录的国家猜测。网络观测失败或旧连接器未提供国家时显示“未记录”，普通导入和隐藏邮箱人工标记也保持未知，可在编辑中补充。手动修改或清空后，重复注册回执、恢复任务与后续密码、MFA、优惠回执均不覆盖该值。国家使用两位地区代码保存，界面展示简体中文名称；仅传国家，不把注册出口 IP 加入回执、数据库或日志。

## 代理与使用说明

先在隐藏邮箱或未注册列表点击“选择注册”，再点击页首“开始注册”。抽屉只读显示已选邮箱，不再重复选择；不可注册邮箱显示受控原因，已有本人任务提供查看入口。注册表单直接从“代理 IP 管理”选择启用代理，复用动态提取和固定代理的协议、链接与加密账号密码。无需再配置“代理 IP 与窗口设置”；该抽屉原有使用说明仍用于其他既有入口。目录停用、删除或失效时，服务端停止启动，不回退历史连接资料。

注册与充值共用已有默认代理引用。空白注册表单自动带入默认代理，已有手动选择保留；本次注册使用任务表单中的选择。新任务每次只读准备先提取一次代理，再启动新的指纹浏览器，核实出口国家并打开官网初始页面；Context、出口和初始页面共用 20 秒。注册资料提交之前，动态代理连接失败或超过这段时间时，确认关闭失败窗口后重新提取 IP、生成新指纹，最多尝试 10 次（含首次）。静态代理失败直接停止；本人验证、无效配置、授权失败或清理未确认不自动轮换。准备成功后复用页面，提交注册资料后与暂停继续均保留原代理和原窗口。

代理与名字在各自下拉框独立搜索和翻页，已选资料的文字在搜索和分页后保留；不再展示共用“资料搜索”和“选项页码”。注册页和开始注册抽屉的标题右侧“使用说明”介绍邮箱授权、代理、名字、执行和账号入库、验证码、原任务恢复及本人验证。任务创建或接收结果不明时保留输入和尝试编号，按钮变为“核对原任务”；通过仅返回本人任务的查询找回原任务，切到注册任务查看或继续，不重新创建。已核对确实没有任务时才允许再次明确点击开始。新任务开始前检查全部未结束任务和 Worker 的原窗口占用；任务暂时没有有效授权不等于已释放窗口。

默认代理复用已有 JSON 配置的 `proxyId`，本轮没有新增数据库表、字段、环境变量或迁移。前一轮代理设置证据见 `.runtime/registration-proxy-settings-20261002/RESULT.md`；本轮指纹切换证据见 `.runtime/registration-builtin-browser-20261002/RESULT.md`。

## 系统执行器

注册和服务器充值复用既有 `auto-recharge` 私网 Worker、地址和认证配置。新增经用户允许的 Camoufox 0.5.6 依赖和 152.0.4-beta.30 内核，构建时校验固定下载文件的 SHA-256，运行时无需下载内核、扩展或 GeoIP 数据。没有普通 Chromium 回退。安装与发布边界见 `BUILTIN_FINGERPRINT_BROWSER.md`。

密码、待确认 MFA 密钥和任务授权只从 API 传给私网 Worker；管理端接收任务编号、尝试次数和接收状态，不接收这些秘密。回执限制任务授权、当前尝试和 45 分钟期限；管理员身份、邮箱授权失效后不能继续读码。

## 执行、暂停与恢复

依次处理邮箱、验证码、姓名及年龄（或官网要求的出生日期）、官网身份核实、设置密码、验证密码登录、设置验证器 MFA、验证 MFA 登录和优惠检查。新任务使用填写的整数年龄；留空时由 API 随机生成 20 至 45 岁的整数，并在已有注册事务内保存为任务快照。继续任务、增加执行尝试和代理预检重试都沿用原年龄。官网显示年龄输入框时填写固定年龄，不向该控件填写日期；显示完整出生日期时使用该年龄按当前业务年份推导的 1 月 1 日兼容日期，该日期不代表用户真实生日。已有客户端仍可提交原出生日期，系统据此计算年龄并保留原日期；历史任务没有年龄快照时不回填，沿用原生日计算年龄。姓名固定使用任务资料。资料表单尚未完成时，即使已有登录身份也不跳过这一步；只有官网身份、密码登录及验证器登录均通过，才显示“注册与安全配置完成”。优惠可以仍待核实。

空白或暂未识别的注册页面先有限等待，再在原窗口、原代理对安全官网地址执行最多一次 GET 刷新，重新识别后继续；不使用可能重放上一张表单 POST 的刷新方式。恢复期间阻止网页自动写入，排除验证码、验证链接、授权回调和付款页面；本人／电话验证优先暂停，HTTP 错误不能当作恢复成功。按钮按当前资料表单内唯一可用控件定位，不使用固定屏幕坐标。资料提交事实保留在原窗口内，继续或换执行尝试不自动重复点击已提交的资料。

邮件读取限定目标邮箱、新邮件时间、官方发件人和未确认接收的邮件。进入验证步骤时 API 补读一次已有邮件，随后由新邮件事件唤醒任务，核验管理员授权、当前尝试与步骤后投递到私网 Worker。Worker 不定时查询邮件，不依赖管理端保持页面打开；确认接收后才记录邮件编号，传输失败可以重试。继续同一原窗口、同一注册邮箱挑战时保留首次读码时间；明确发起新邮件及密码／MFA 新挑战时重设边界。官方发件人兼容 iCloud 隐藏邮箱完整编码地址；历史提取值为产品名称时，从明确验证文案恢复唯一数字验证码。临时验证码不进入会话草稿；管理员手动提交时绑定当前尝试和步骤。MFA 验证器码由当前密钥计算，不把邮件验证码当作验证器码。

2026-10-04 自动读码修复兼容 iCloud 隐藏邮箱中编码原地址的 OpenAI 转发发件人；这是来源筛选线索，不是原发件域的认证证明，显示名称不能单独作为依据。提取结果必须为完整的 6 至 8 位数字；旧提取值无效时，只从同封邮件明确的验证文案中恢复唯一数字，不截断长数字、邮箱、混合串或跨行分组。邮件仍绑定原邮箱、收码时间和最近已接收邮件，已知接收时间之前的旧邮件不能再次使用。

原注册窗口停在验证码页面、明确继续等待原挑战时保留收码时间，因此暂停期间收到的邮件仍可自动使用；重新提交邮箱、密码登录核实或 MFA 登录核实触发新邮件时，在提交前建立新的时间边界。既有 `waiting_email` 回执新增可选布尔 `newMailRequest`：新 Worker 明确区分新请求与原挑战；旧 Worker 缺少该字段时沿用原重置行为。没有新增端点、数据库结构、迁移、依赖或事件推送链路；单次提交、原任务／窗口、权限、租约和付款保护沿用既有实现。隔离测试不证明真实官网接受验证码，也不绕过本人、电话或银行验证。

生成的密码和待确认的 MFA 密钥提前加密保存；失败保留任务检查点，继续使用原窗口。官网注册核实后即可在 ChatGPT 账号列表看到该账号，尚未核实的安全配置不会伪装成完成。密码/MFA 核验在同一浏览器、相同代理和指纹的新 Context 中进行，避免把已登录 Cookie 当作验证通过。本人验证、电话验证、无法识别的表单和存在密码的既有账号会暂停或停止，不处理验证挑战。必要时由管理员在执行器原窗口处理；当前版本没有新增远程桌面入口。账号页可补录实际密码或 MFA 密钥，再继续原任务重新核实。

执行器崩溃或原窗口关闭后停止为“原窗口丢失”，先核对官网账号，不另开窗口重复注册；原 Cookie 和凭据不落盘。已有比特任务不自动转换为新指纹窗口。回执未能保存时先恢复系统连接；未失效的原授权不能直接发起第二次执行。取消先撤销任务授权，再通知执行器关闭窗口，关闭未确认时页面明确提示管理员检查。取消不撤销官网已完成的注册，已保存的账号及安全配置保留。

不自动点击领取、确认订阅或付款。本流程阻断支付写请求，不领取促销或修改套餐。官网界面发生变化时保留待继续状态，不能用本地模拟验证替代真实页面验收。

## 邮件事件配置

邮件源使用 Vendure iCloud Relay 的 IMAP IDLE。邮件与通知记录在同一事务保存，HTTPS 签名通知只包含事件编号、主邮箱和别名编号及时间。ID 系统保存幂等回执，发布邮箱范围 SSE 并唤醒任务。失败通知退避重试，启动和重连补齐；连接保活不查询邮件。收件页与中继查询收到事件后更新，保留原列表和筛选。

新增 ID MySQL 迁移 `20261004093000_mailbox_event_receipts` 和 Vendure 迁移 `1791075600000`。发布时先按各项目流程备份并应用增量迁移，再更新私网 Worker 和 ID API，最后更新邮件源并启用通知。Worker 健康响应必须有 `mailDeliveryVersion: 1`，旧版本不能启动或继续注册执行。

ID 配置 `VENDURE_MAILBOX_WEBHOOK_SECRET`；Vendure 配置 `ICLOUD_MAIL_WEBHOOK_URL`（ID 的 `/api/id-business-v2/vendure-mailboxes/events` HTTPS 地址）及相同专用密钥 `ICLOUD_MAIL_WEBHOOK_SECRET`。密钥至少 32 字符，通过既有服务器秘密配置流程注入；源码只提供空占位。本轮未提交、推送、部署或执行生产迁移，真实收信和官网注册需发布后验收。

生成的密码和待确认的 MFA 密钥提前加密保存；失败保留任务检查点，继续使用原窗口。官网注册核实后即可在 ChatGPT 账号列表看到该账号，尚未核实的安全配置不会伪装成完成。密码/MFA 核验在同一浏览器、相同代理和指纹的新 Context 中进行，避免把已登录 Cookie 当作验证通过。本人验证、电话验证、无法识别的表单和存在密码的既有账号会暂停或停止，不处理验证挑战。必要时由管理员在执行器原窗口处理；当前版本没有新增远程桌面入口。账号页可补录实际密码或 MFA 密钥，再继续原任务重新核实。

## 数据与接口

此前自动注册使用向前迁移 `20261002160000_auto_registration`，不修改旧基线；本轮浏览器切换不新增迁移：

- 新增 `id_business_v2_registration_names` 和 `id_business_v2_registration_jobs`。
- ChatGPT 账号新增 `offer_status`、`offer_source`、`offer_observed_at`。
- 任务与员工、名字、代理、账号建立限制删除的关联。有关联记录的代理与账号不能直接删除；有未结束注册任务的员工不能删除，已结束记录可随既有员工接管流程转移管理权。
- 邮箱、出生日期、密码及 MFA 密钥加密保存。日志仅记脱敏邮箱、状态及配置是否核实；不记录密码、验证码、验证链接、会话或任务授权。

管理员接口前缀 `/api/id-business-v2/auto-registration`：`GET execution/options/names/jobs/jobs/:id`，`POST names/names/import/jobs/jobs/:id/launch/jobs/:id/code/jobs/:id/cancel/jobs/:id/resume`，`PATCH names/:id`。移除管理端 `connection` 和 `resume-credentials` 秘密分发接口；`code` 改为绑定尝试和步骤的手动提交。Worker 回执沿用 `POST local/:id`，新增授权读码 `POST local/:id/code`。私网 Worker 提供注册健康、派发、同尝试状态查询、继续、验证码与取消端点，均复用现有 Worker 认证，不公开给管理端。账号原有查询增加 `offerStatus`，修改增加受控优惠值与原版本校验。
