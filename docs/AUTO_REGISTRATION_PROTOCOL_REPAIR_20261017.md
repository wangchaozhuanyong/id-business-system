# 原协议自动注册响应修复

## 范围

保留已恢复的原开源服务器 HTTP 协议注册方式。冻结 upstream 文件不修改；不新增桌面执行方式、接口、数据库表列、迁移、依赖或运行环境变量。

本次修复已有证据支持的异常放行与诊断缺口，不能据此声称官网已接受注册或历史 HTTP 400 根因已被完全证明。

## 行为

1. 精确观察原 `HTTPClient.post → HTTPClient.request → Session.request` 的前置安全响应，保留原请求参数及重试。前置校验拒绝非官方来源、非成功状态、非法 JSON、无有效 token、必需或非法挑战要求。在原 `_check_sentinel` 吞异常的处理之外停止；同一个会话的有效证据才允许提交邮箱。
2. 密码响应检查状态、最终官方来源、JSON 对象和明确错误信号。拒绝后不调用验证码或创建接口；密码已提交的未知结果仍保留原任务保护。正常对象不新增页面白名单。
3. 新任务写入现有加密记录中的 flowEvidence v3。增加前置阶段、挑战要求类别、密码错误结构和未知页面受限摘要。密码、Cookie、Token、完整响应、授权链接及原始未知页面值不进入证据。
4. 历史 v1/v2 不自动升级。新增观察先以 v3 判定能否继续，再按旧版本投影用于保存；历史格式没有前置阶段时跳过该阶段的存储，不能据此绕过执行校验。v1 已有阶段、首次失败与人工资料继续保留。
5. 两处现有任务详情复用原布局展示中文原因；未知页面只显示摘要是否记录，不直接显示原值、哈希或任意后端文案。

## 核对与限制

- 原 uv 锁与当前 worker 依赖存在差异，但原 pip 安装本就允许更高版本；没有据此整体降级或修改代理。
- 旧未知页面类型未保存，不能从摘要恢复，更不能猜测放宽允许分支。新摘要仅用于安全关联，不等于已经识别该页面的合法语义。
- 对密码 HTTP 200 空正文／非 JSON 采取无法确认即停止的保护；尚无真实成功响应证明官网当前契约，因此真实兼容性仍需独立验收。
- 官网要求当前实现无法完成的额外验证时，准确停止和报告原因。该情况仍是注册未完成，不属于自动注册成功。

## 验证

本机使用项目已有 Python 环境运行硬阻断 SQLite、socket 和 DNS 的纯测。成对测试提取原注册引擎及原 HTTPClient 方法，避免假客户端调用方向掩盖问题。

已覆盖必需挑战即使有 token 仍停止、缺 token、错误状态、非法响应、非官方来源、证据保存失败、会话替换、密码 200 错误、历史投影、创建后的提前保存、同步补偿及人工资料保护。

API 定向测试、类型检查、构建、七项界面规则及两个详情的模拟浏览器验收分别记录于项目内 `.runtime/registration-parity-20261016/protocol-repair-20261017/`。浏览器测试采用真实构建资产和全部模拟路由，不启动本机网站或数据库，不发外部请求。

真实存储集成套件只在远端隔离 CI 运行；不得在这台 Mac 创建测试数据库，也不得用生产库验证。

发布必须绑定实际当前清单和组件版本，并保留之后上线的模块、配置、数据及历史前端资产。旧发布合同继续冻结，不改 hash 重跑旧发布。

当前已取得只读基线：清单及 API/Admin 组件均为 `0222adf9d5225669b73e8e8f9ec711564eb6163a`，38 条主台账、56 条迁移、6 条历史失败任务；本轮基线读取没有写入或注册请求。

正式发布、版本回读和单个邮箱真实验收分别取得确定回执后登记。真实验收只使用提交前核实为未注册、暂无任务且无待核实占用的邮箱；取得官网身份、凭据保存、注册结果和主台账回读四项证据才算成功。官网拒绝后停止，不换邮箱连续试错。

服务器在本轮检查期间已独立发布线上代充修复；本次生产基线随之更新为 0222，包含最新线上代充 API、前端及执行器。重构顺序保留固定 c8 的历史恢复配方，再叠加已经正式发布的 0222 源码；本次不修改这些线上代充行为。前端完整保留现用 2283 个历史资产。
