# V2 生产数据重建与安全切换

## 当前门禁

- 生产数据库只允许执行脱敏 `preview`，当前工具硬性拒绝生产 `apply`。
- 在已验证的新数据导入包形成前，禁止执行任何只清空生产业务表的操作。
- 历史聊天、旧操作编号、旧备份哈希均不能作为新的生产删除授权。
- 部署流程不得调用本维护脚本；维护与部署必须分开执行和审计。

## 隔离重建

1. 从当次生产保护备份恢复本机 PostgreSQL 副本。
2. 使用 `preview` 生成一小时内有效的脱敏指纹和唯一操作编号。
3. `apply` 必须同时匹配预览文件、操作编号、备份文件和 SHA256；数据库指纹有任何变化都会拒绝执行。
4. 隔离清理只删除当前 V2 业务记录，保留用户、角色、权限、选项设置、系统设置、汇率行情历史、迁移历史和审计历史。
5. 使用正常后台表单录入客户、ID、礼品卡和业务动作；密码、密保、手机号和完整卡号不得进入恢复报告或普通日志。

### 恢复后的结构兼容检查

- 生产备份恢复到隔离库后，必须对照当前 Prisma 基线检查 `v2_auth_identities`；当前结构只允许 `user_id` 关联用户，不应再出现废弃的 `legacy_user_id`。
- 如果旧备份仍带有 `legacy_user_id NOT NULL`，管理员/员工创建会在写入认证身份时返回 500。只允许在本机隔离副本中删除该废弃列及其外键，并记录 `isolated_reconstruction.auth_schema_alignment` 审计；不得据此直接修改生产库。
- 完成兼容处理后，必须通过正常 `POST /api/v2/employees` 创建并清理一次临时管理员探针，确认接口返回 201、探针用户和会话均清理为 0，再交给用户录入业务数据。

## 正式切换前条件

- 用户已核对脱敏恢复清单和财务借贷平衡。
- 已在新的生产副本完成“导入、校验、回滚”演练。
- 已生成切换前新备份并验证可恢复，且 SHA256 写入当次批准记录。
- 已实现并测试“删除旧业务图 + 导入已验证新业务图”的单事务切换；只清空生产的实现不允许上线。
- 当次明确批准必须绑定最新生产指纹、唯一操作编号、导入包哈希、备份哈希和有效期。

## 回滚

- 事务内任一数量、外键、金额、加密字段或权限校验失败，立即整体回滚。
- 提交后发现问题，只能使用当次切换前备份恢复；不得使用本次事故之前的旧批次备份。
- 回滚也必须重新获得当次明确批准并生成独立审计记录。
