# 数据变更通知及本窗口界面整合

新数据由服务端变更通知触发局部读取，不通过定时刷新业务列表实现。本次同时整合已完成的字段说明按钮、直接操作下拉菜单及买家查询码显示/复制，并保留 main 新版比特浏览器布局与 IP 功能。

## 变更合同

- 新增只读 `GET /api/local/change-events`，沿用现有会话、Host 和同源检查。SSE 首次/重连发送范围版本快照，之后仅发送有变化的范围；心跳不包含业务更新。
- 事件仅含 `{ schema: 1, versions: { 范围: 版本 } }`。不发送业务正文、邮箱、密码、查询码、密钥或 Cookie。
- 普通保存、批量事务、后台订单同步在事务成功提交后通知。回滚不通知。另监听当前数据文件的操作系统变更事件，覆盖其他进程提交；文件事件也必须比较版本后才推送。
- 个人工具、2FA 元数据、比特连接、IP 和地址的版本按当前账号读取；员工不接收设置、财务、审计等管理范围版本。员工目录只使用已有版本字段的摘要，不改变登录或权限规则。
- 不新增数据库表、字段、迁移、依赖或环境变量。

## 页面行为

- 共享读取层比较已接受的文档版本与服务端版本。相同版本、重复通知和心跳不重新读取业务数据；本页已成功保存的版本也不会重复加载。
- 相关范围失效后，更新对应库存、客户订单、余额、设置、总览、人员显示名及当前可见的读取工具。无关列表不重读。比特浏览器只更新空闲时的选项，不打断正在执行的任务或配置编辑。
- 保留现有查询、分页、筛选与会话草稿。编辑表单、操作菜单、确认与写入期间暂缓读取，关闭或切页后补上更新；不自动覆盖原始编辑版本。
- 网络中断保留最后内容，只重连事件通道；重连比较当前快照，补上断线期间遗漏的变化。临时流读取失败不会使有效登录失效；真正失效的会话沿用原有清理流程。
- 倒计时、提醒时间边界与原代充任务状态轮询继续沿用原业务规则；它们不替代本次版本通知，也不新增周期性业务数据查询。
- 查询码等业务资料仍由原鉴权读取接口返回，事件不承载原文；身份清理时关闭事件通道并清空读取快照与版本跟踪。

## 验证

本机仅执行不启动网站或数据库服务的纯单元、语法、差异检查和拦截请求的离线浏览器检查。真实事务、HTTP 会话/同源拒绝及两客户端收到同一提交版本由 `test/change-sync-integration.test.mjs` 在远端 CI 隔离环境运行。

- `test/change-sync-feed.test.mjs`：相同版本、心跳、通知合并、文件事件、失效身份和临时失败。
- `test/local-data-read-cache.test.mjs`：版本判断、自身写入、漏失快照、迟到读取与身份清理。
- `test/change-sync.browser.mjs`：库存新资料自动出现、无变化不重读、相关范围刷新、筛选分页、草稿、断线补偿及手机深浅主题。
- 受影响的共享布局、长列表、操作菜单、买家查询码、订单历史邮箱与比特账号/IP 浏览器回归。

项目没有单独 typecheck、lint 或前端编译脚本。生产资源仍从确定的 main 提交重新归档和构建，保持单一发布任务、候选金丝雀、正式版本与线上回读对应同一提交。
