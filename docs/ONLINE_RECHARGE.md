## 行为基准

本地路径：Session 恢复 → Checkout 接口优先 → 原定价页回退 → 地区／套餐选择 →
地址与卡片预约 → 填卡和提交 → 验证码 → 结果确认 → 记录 → 尝试关闭自动续费。

保留 Plus／Pro 5x／Pro 20x 映射、唯一按钮定位、Pro 二次确认、卡排序、成功绑定上限、
明确拒付上限、明确拒付后同任务换卡、已尝试卡排除、最多尝试次数、浏览器模式、代理及验证码通道。
调试模式在付款前停止。本地取消续费失败单独记录，不能把取消失败改成充值失败。

第三方路径：Session 预检 → 卡／代理预约 → 幂等提交 → 保存上游订单与任务编号 →
轮询 → 原次数统计与通知。第三方明确拒付后不重新建单换卡，不增加本地自动取消续费动作，
不套用本地账单计算。保留供应商返回的真实金额与状态。

## 数据与运行边界

专属配置、卡、代理、地址、兑换码、任务（Session 加密）、事件、账单与 Webhook 回执从空数据开始。
独立数据范围 `online-recharge` 不联动钱包、银充、利润或自动充值资源。创建、修改、删除、敏感读取
均遵守现有审计；额度及付款状态使用受控枚举，金额使用 Decimal。

执行器通过内部共享密钥与任务租约访问 `/worker/rpc`，不持有数据库连接。
后台实时连接以现有身份换取短期票据，客户以任务凭证授权；不在 WebSocket URL 放现有登录 Token。
供应商与卡片补货密钥仅由配置加密保存。补货回调校验原签名／解密协议并原子去重。

本地入口：`npm --prefix apps/api/src/id-business-v2/online-recharge/engine start`。
独立依赖、Dockerfile 与运行要求见该目录文档。所有可控媒体、临时资料及验收输出必须在本项目内。
`.env.example` 仅含占位值；默认 `ONLINE_RECHARGE_ENGINE_ENABLED=0`，显式配置并授权业务运行后开启。
执行并发仍受原配置与浏览器槽位约束，环境变量只能限制执行器硬上限。
