# 比特账号连接与执行 IP 分离

比特登录先选择当前电脑／主账号或子账号的连接，再选择执行 IP。网站不切换比特客户端身份；新电脑首次需登录客户端、启用本地接口、填写对应密钥并检测分组与标签。

IP 普通录入仅填写备注名称、动态住宅／静态住宅／移动类型和代理信息；国家、协议及连接方式自动识别，可在高级设置中手动指定。执行不再另选国家；国家从选定 IP 读取。新增失败保留当前输入，成功选中新 IP。连接配置不依赖 IP 列表，已有连接和历史代理资料保留。

本机接口密钥提供眼睛按钮，默认隐藏，切换连接、页面隐藏或离开时恢复隐藏。代理凭据不进入草稿、列表响应或审计；普通元资料和选择沿用现有会话草稿桥接。

`/api/local/bitbrowser-proxies` 复用既有管理员与同源校验。GET 返回当前操作人的版本和摘要，PUT 按版本新增，POST 按编号与版本取用并写审计。数据复用已有加密文档存储，无新增 SQL 表、迁移、依赖或环境变量。正式备份继续覆盖已有业务库和密钥，新增代理不会改写原连接。

同会话原窗口仍按账号和本机接口凭据隔离。换 IP 时先确认原窗口已关闭，只更新网络字段并回读，不更换窗口编号、Cookie 或指纹；结果不能核实时停止。

验证使用合成资料，未执行真实账号登录、代理提取、付款或通知。专项单元测试、12 组宽窄屏深浅主题离线页面与共享布局通过；SQLite 持久化与接口回归由受保护 PR 的远端隔离 CI 执行。正式发布、当前提交与线上只读验收以发布回执为准，不以本文预先声明完成。

## 页面整理与 IP 资料库（后续修订）

- 登录页按选择比特账号、选择执行 IP、填写登录资料分为三个区域；连接设置默认收起，新增连接时展开。说明进入标题右侧的共享说明浮层。
- IP 资料库提供名称／国家／类型／连接方式／地址摘要表格，支持搜索、类型筛选、排序、分页、使用与编辑；保存后选中 IP 并返回登录页。手机表格内部滚动、操作列保持可见。
- 编辑沿用同一 PUT 接口，新增可选 `id`。留空代理链接保留原密文对应资料；切换方式或协议必须填写新链接。使用既有版本检查、按用户隔离和审计，无新数据库表或迁移，不提供删除入口。
- 账号连接新增可选 `accountName` 标记，和原有 `name`（电脑／连接备注）分开。旧客户端不传时保留已有账号标记；没有标记的旧连接显示“账号待确认”。名称不代表自动验证或切换比特客户端身份，同一本机接口下的多个旧配置不能凭 IP 名称推断属于不同账号。
- 新增／编辑 IP 的非敏感字段、列表筛选／页码／页签复用宿主会话草稿；代理秘密不进入草稿。失败保留输入，409 后先显示最新摘要并由用户再次确认保存，保存中阻止关闭和重复提交。
- 验证：`test/bitbrowser-account-ip.browser.mjs` 离线覆盖 12 组宽度／主题、空与跨页列表、固定操作列、编辑链接回填、保存失败重试及执行参数；共享布局测试 8 项。实际数据隔离、版本与密文测试在远端 CI 的隔离数据库执行，不连接生产测试。

## 代理录入简化与本机检测

普通新增／编辑显示备注名称、IP 类型、代理协议、代理链接。支持购买平台直接生成的 `账号:密码@主机:端口`、`主机:端口:账号:密码` 和完整代理 URL；高级设置默认收起，可选连接方式和中文国家。国家不再必填，检测后自动带入；未识别国家不会阻止授权 JSON 登录。

“测试代理”使用所选本机连接的密钥直连比特 `/checkagent`，按照[比特官方接口](https://doc.bitbrowser.net/api-docs/browser-profiles#proxy-detection-api-can-be-used-to-query-proxy-information-and-check-the-availability-of-proxies)读取成功结果与有效出口 IP。没有协议前缀的原始地址按 SOCKS5、HTTP 顺序识别；原始地址保存时自动完成识别。标准完整 URL 可直接保存。HTTP／HTTPS 提取链接测试先通过同源受控接口读取一条代理，再交给当前电脑的比特检测；实际打开窗口仍沿用旧版的动态提取流程。检测不创建或启动窗口、不导入授权，也不触发付款。

测试显示出口 IP、国家及当前电脑的检测耗时；不把格式正确或接口外层 success 当作代理可用。列表也可直接测试已保存记录。保存和执行共享同一解析器，主机、端口、账号密码自动写入比特窗口；保留固定版本 e51dd9c9 的仅登录流程。选中代理即按独立的网络配置处理，未检测国家时也能保留原窗口并更换网络，不借用国家字段控制窗口复用。

继续使用原接口、加密文档及审计；countryCode 可为空，不新增表、迁移、依赖或环境变量。旧记录完整保留。普通元资料经宿主草稿白名单保留，代理链接、接口密钥和授权 JSON 不进入草稿。探测结果只在页面内保留脱敏摘要，连接资料改变后重新检测。

## 2026-11-08 代理明文与提取兼容修复

- 新增、编辑框直接显示代理链接。编辑通过既有按账号隔离、版本校验并记审计的 POST 接口读取；关闭后清空，迟到响应不回填其他记录。服务端仍加密保存，代理链接不进入草稿或日志，列表仅返回地址、协议和连接方式。
- 支持带路径、参数和自定义端口的 HTTP／HTTPS API 链接；识别明确的协议参数。提取解析兼容单条文本以及常见的 data／list／proxies 包装、ip／host 与 port、账号密码字段。普通移动／住宅属性不代表代理协议。
- 新增 `POST /api/local/bitbrowser-proxies/extract`，仅管理员同源 JSON 请求可用；复用已有公开网络校验，DNS 全集核验后固定 IP、保留 TLS 主机名校验，禁止跳转、私网与转发 Cookie／Authorization。每人每分钟最多 20 次，限制并发、请求长度、读取时间和响应体大小。无需新表、迁移、依赖或环境变量。
- 嵌入页 CSP 原先禁止直接访问外部提取接口；本次保持 CSP，通过同源接口完成读取，再由比特 `/checkagent` 检测真实出口。供应商限制来源／白名单时显示“未完成检测”，不误称比特不支持。服务器提取来源与执行电脑不同，供应商的白名单需允许对应来源；真实执行继续将原始链接交给比特。
- 列表区分“未测试”“可用”“检测未通过”“未完成检测”，保留明确失败原因。明确协议的标准地址或 API 链接可直接保存；未注明协议的地址／API 在自动模式下需检测识别后保存，或明确选择供应商所用协议。
- 本机无数据库单元测试覆盖解析、来源／权限、DNS 私网、跳转、响应边界、协议及安全错误；离线浏览器覆盖连续新增、失败重试、明文回填、迟到响应隔离、12 组宽度／主题的抽屉及 4 组嵌入页切换。线上真实检测和正式版本另记发布回执，不能用离线结果替代。

线上对照确认：旧版自动录入的无协议 API 曾被直接记为 HTTP；现在保存前用检测确认协议。仅对只读 `/checkagent` 的连接中断重试一次；不会重试创建窗口、登录、付款或其他写操作。连续失败仍报告未完成检测，不伪装可用。
