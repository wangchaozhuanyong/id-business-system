# 网站总览规划与页面设计

日期：2026-11-06。入口保持 `#/overview`，导航与页名统一改为“网站总览”。

## 页面定位

作为日常打开系统后的经营与待办入口，优先回答：订单和客户情况如何、哪些事情需要处理、库存是否足够。具体录单、充值、退款、取用和归还继续进入原模块执行。

已接入当前系统的只读订单、客户、库存和苹果余额统计。数据从对应模块读取成功后展示，失败保留上次成功快照。独立预览使用空内存业务库。

## 页面由上到下

| 区域 | 本期设计 | 统计与展示口径 |
| --- | --- | --- |
| 时间范围 | 今日、近7天、近30天，默认近7天 | 北京时间；近7/30天包含今日。只影响经营指标和订单趋势，切页返回保留选择 |
| 经营概况 | 订单数量、订单实收、已核算利润、新增客户 | 订单按创建时间，续费是新订单；实收只统计已确认金额，按原币分列；利润沿用冻结汇率及费用规则；客户按创建时间去重 |
| 常用入口 | 提交订单、客户录入、邮箱提取、账号提取、比特登录、ChatGPT代充 | 使用既有入口，不复制流程；普通员工按权限展示可用订单入口 |
| 订单趋势 | 按日展示订单与撤单 | 按北京时间汇总订单与撤单，可展开查看每日数量 |
| 待办关注 | 续费待处理、订单待补资料、已领用待处理、苹果待回款 | 统计当前情况，点击进入对应业务页；显示实际数量，链接进入现有业务页 |
| 库存概况 | 谷歌邮箱、苹果隐藏邮箱、GPT、Claude的可用/已领用/异常 | 沿用库存资格与占用规则，不能只按未使用计可用；Claude需满足养号条件；隐藏邮箱可提取资格需远端核验 |
| 客户经营 | 有效服务客户、续费待跟进、流失客户 | 按客户全部有效订单判断；单笔到期、拒续都不能直接判定整体流失。归属不明后续进入待核对 |
| 后续接入 | 未来业务及已有模块的总览接入规划 | 见下表；点击右侧抽屉查看计划展示内容，外点或Escape可收起 |

缺少或失效汇率快照的订单必须进入“待核算”，不按零利润处理。利润卡旁显示待核算数量。实收以订单创建日归集，客户退款以退款登记日按原币单列。利润使用订单核算模块，苹果待回款与已确认到账分别处理。

## 保留的占位与后续接入

| 模块 | 当前标记 | 后续总览内容 |
| --- | --- | --- |
| 微软邮箱 | 业务占位 | 库存登记、领用归还、状态异常；区别于已存在的邮箱查询工具 |
| Gemini | 业务占位 | 账号库存、订单与续费、实收及核算 |
| Grok | 业务占位 | 账号库存、订单状态、客户与续费 |
| Claude代充 | 业务占位 | 排队、执行、结果与任务订单对账；不影响现有Claude订单模块 |
| Google表格同步 | 业务占位 | 新版同步表格/字段范围、最近成功、失败和待同步；按用户确认的新需求开发 |
| 数据中心 | 业务占位 | 资料完整度、重复记录、跨模块对账 |
| 监控中心 | 业务占位 | 服务可用性、执行器连接、最近异常及恢复 |
| 网站访问 | 待接入总览 | 已授权GA4与访问采集的访客、访问量、来源、更新时间；不由总览推断线上配置状态 |
| ChatGPT代充概况 | 待接入总览 | 既有代充任务的等待/执行/成功/失败与更新时间 |

中转脚本按现有安排不展示。租金待发放、最近业务记录作为后续可选项：确认有日常处理需要再加入，避免首页重复完整明细表或展示联系方式与账号秘密。

## 统计边界与后续接入

- 经营指标、趋势、待办、库存、客户经营已接入。通过原业务模块取只读汇总，金额使用已有精确小数实现。
- 进入总览或点击刷新时读取。加载时保留现有数据，读取失败展示上次更新时间，成功空集显示 0。隐藏邮箱的已领用和异常来自本机记录，可提取数量仍需远端核验。
- 普通员工可进入既有明细并查看授权库存。跨产品经营、财务和客户汇总仅向有统计权限的身份显示，员工总览不发出 Commerce 统计读取。
- 明细链接进入对应现有模块。按区间或待办条件直接下钻仍待单独接入。网站访问、代充任务概况和明确延期的业务保留占位，Google 表格同步等待表格与字段定义。
