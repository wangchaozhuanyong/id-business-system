## 上游全链路无轮询：明确剩余项

目前 `server/preview.mjs` 仍在充值同步启用时每 60 秒调用一次 `orderSync.run({ apply: true })`。它负责发现与导入上游数据，与前端 SSE 是不同一段链路。受保护原版页面也有自己的任务读取逻辑。本轮未删除这些现有机制，不能宣称网站所有来源已经完全无轮询。

已检查锁定原版的 `server.js`：WebSocket 接受 `subscribe + jobKey`，向已知任务发送状态；没有可用于发现全部新任务的全局事件订阅。单纯接这个接口无法可靠发现其他窗口、商城或后台新建的所有任务。

建议后续采用独立的数据库变更捕获（CDC）接入，由外围组件读取已提交事务事件。MySQL 的行复制日志描述实际受影响的行，是该接入方向的技术基础；当前生产版本、配置和可用权限尚未核实。[MySQL 官方复制格式说明](https://dev.mysql.com/doc/refman/8.4/en/replication-formats.html)

实施顺序与验收条件：

1. **只读核验环境**：上游实际 MySQL 版本、行日志格式、GTID／日志位点、保留期限、网络及可用复制权限。没有核验前不新增凭据或变更生产配置。
2. **准备独立事件适配器**：不改锁定付款源码；从任务与账单等实际业务表读取变更，只在事务提交后触发已有订单证据核对。表范围需按真实写入路径最终确认，不只监听一个状态字段。
3. **可靠接续**：保存已处理位点、事件去重和按任务合并；中断后续接，位点过期时明确告警并执行一次受控快照核对。启动／恢复核对不是固定频率刷新。
4. **隔离敏感内容**：适配器在服务端处理，浏览器仍只收到当前权限允许的模块版本；不把数据库复制连接、银行卡、Session 或原始行事件发给客户端或写入诊断日志。
5. **先验证再替换**：隔离环境验证其他来源新增、成功／失败、事务回滚、重复事件、断线、重启和事件积压。确认全量任务可发现后，才替换现有 60 秒扫描；不能提前移除而漏单。
6. **验收真实效果**：无变更时没有业务列表查询和重绘；单次提交仅更新受影响视图；断线恢复不漏最新状态；编辑不丢、重复事件不重复业务写入。外部商城／邮箱来源须使用各自明确的事件出口，不能假定本项目 SSE 能感知另一个服务的数据库。

这一步涉及受保护充值边界、数据库复制权限／可能的配置及独立运行依赖，需要按 `AGENTS.md` 取得具体授权后实施和验证；发布仍需另行授权。

## 方案依据与限制

本项目采用“事件驱动实时更新（SSE）＋事务内乐观并发控制＋幂等回执”。SSE 是服务端向浏览器推送事件的标准机制，适合当前单向通知需求。[WHATWG SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)

SQLite 允许多个连接读，但同一时间只有一个写事务。现有 `BEGIN IMMEDIATE` 将校验和写入置于同一写事务；仍需要上述真实并发测试验证本项目实现，而不能只引用数据库保证。[SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)

回执当前保留在现有加密文档库，不在本轮自动删除；长期容量与保留期限需结合实际写入量确定。订单和库存的严格整文档版本冲突仍可能要求重新核对，它们没有被自动合并。尚未运行数据库套件或线上验证，不能据本轮结果承诺生产环境“绝不会错乱”。
