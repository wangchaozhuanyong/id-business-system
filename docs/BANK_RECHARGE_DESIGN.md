# 银充订单与 ChatGPT 自动充值设计

## 业务闭环

1. 管理员在「自动充值 → ChatGPT 账号」保存邮箱、密码和可选 2FA。列表只展示脱敏邮箱和配置状态；取登录资料与验证码须有管理员权限并写审计。
2. 在「自动充值」选择已保存账号，沿用现有单账户、单窗口、单次付款保护。只有官网登录账号匹配、官方报价与付款凭据一致、付款完成且订阅生效时，才自动建立银充订单。JSON 和账号密码模式的核验成功也使用同一建单规则。结果未知和只读复查不触发新订单或再次付款。
3. 「自动充值 → 银充订单」可手工录入真实代付及付款凭据。自动订单的官网代付事实锁定；待补全阶段指定客户、账号、银行卡、客户实收、汇率、开通与到期时间。客户可从当前抽屉快捷新增并自动选中。
4. 客户手续费 = 代付金额 × 手续费率 ÷ 100，按付款币种最小单位四舍五入；如 1000 × 2.5% = 25。可单笔手动改手续费金额。银行实际扣收手续费另列，不与客户收费混用。
5. 财务资料核对后完成订单，按人民币汇率快照生成平衡日记：客户实收、代充收入、客户手续费收入、官网代付成本、银行手续费。Visa 卡只按预存资金卡处理，完成时从选定的人民币代付资金账户扣账；退款仅在真实退款发生后登记并冲销原订单日记。
6. 已核验充值按 ChatGPT 账号保留一条当前使用中订阅，订单记录保留历史。到期时间使用现有全局续费预警天数，显示在「工作台 → 续费操作」和顶部提醒。新的续费订单更新当前订阅指针，旧订单仍可追溯。

## 数据与界面

- 新表：ChatGPT 账号、银充币种、银行卡标识、银充订单、当前订阅；自动充值任务增加账号关联和加密预期邮箱，财务枚举增加银充收入、成本和手续费。
- 银充订单宽表将客户、ChatGPT 账号、银行卡、代付、费率、客户手续费、银行手续费、实收、利润、到期、充值结果、使用状态、订单状态各放独立列。所有单元格保持单行，长文本省略并提示，窄屏在表格内横向滚动。
- 银行卡仅保存名称、末四位和付款币种；仅支持先有余额再付款的卡。完整卡号与安全码不入库。金额使用 Decimal，关键修改、取密、建单、入账和退款均留审计。

## 本地验收与上线边界

- 全量前后端单测、类型、lint、构建、UI／表格／架构／加载／金额／时区／Prisma 检查和静态性能预算已经通过；Python 的连接器单元测试与币种纯函数检查通过。27 个迁移已在一次性隔离 MySQL 8.4 上从空库顺序应用成功，银充币种表回读覆盖原自动充值支持的全部 29 个币种（含 CLP、IDR、PHP），并核对 0／2 位小数精度。
- 已用一次性隔离 MySQL 8.4 和合成数据验证账号加密、手工／自动建单、手续费、财务平衡、预存卡扣账、退款、续费预警及自动建单幂等；自动成功凭据经过与回调相同的安全清理。基于实际页面路由和模拟 API 的浏览器验收覆盖 1440／900／390 像素、首页／末页／空状态、单行宽表、操作按钮、客户快捷新增、手续费预览、ChatGPT 账号与 2FA 表单及工作台银充续费提醒。截图与验收脚本位于项目内 `.runtime/bank-recharge/` 和 `scripts/acceptance-v2-bank-recharge-ui.mjs`。
- 历史成功任务不会自动生成银充订单和财务流水；须人工核对真实付款证据后处理。真实官网登录、扣款、生产数据迁移、发布和生产页面验收均尚未执行。
