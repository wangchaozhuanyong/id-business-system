# 银充订单与 ChatGPT 自动充值设计

## 业务闭环

1. 管理员在「自动充值 → ChatGPT 账号」保存邮箱及可选密码、2FA。单条新增和批量导入均不强制密码；批量导入默认「邮箱＋2FA（无密码）」，也可选择「邮箱＋密码＋2FA」，Tab 可留空列，空格分隔用 `-` 占位。无密码账号可独立取 2FA 验证码，使用密码登录前须补充密码。列表只展示脱敏邮箱和配置状态；取登录资料与验证码须有管理员权限并写审计。
   批量导入仅保存 ChatGPT 账号，不选择主邮箱、不读取或写入邮件验证码查询中的邮箱。系统先验证整批资料和重复账号，再用本地事务保存；失败保留输入供重试。导入请求只提交账号数组，兼容旧请求时忽略主邮箱字段，不触发邮箱同步。
   账号操作增加「复制」，显式点击后经管理员校验与审计读取 `邮箱----密码----2FA密钥----买家查询码`，字段之间统一使用四个连字符，字段内部的连字符保留原样；未设置密码或 2FA 时保留对应空位。读取的是当前有效 BUY 码，失效、缺失、关联不唯一或账号停用时不复制残缺资料。临时明文不进入列表或查询缓存，响应禁缓存，审计不含凭据或查询码。
   「ChatGPT 账号」页顶部操作区的「批量导入」左侧提供「复制后缀」，按当前管理员保存在现有窗口设置 JSON 的内部键 `accountCopySuffix`；复制时另起一行追加并保留内部换行，留空不追加。窗口和默认代理设置修改保留该键，执行器参数排除该键。关闭和导航保留未保存草稿，失败可重试；成功不清理保存期间新编辑的输入。
2. 在「自动充值」选择已保存账号，沿用现有单账户、单窗口、单次付款保护。只有官网登录账号匹配、官方报价与付款凭据一致、付款完成且订阅生效时，才自动建立银充订单。JSON 和账号密码模式的核验成功也使用同一建单规则。结果未知不建单。只读复查不再次付款；确认原付款已生效时，按服务端保存的原任务、账号、报价与付款凭据幂等补记缺失订单，已有订单只返回原记录。
3. 「自动充值 → 银充订单」可手工录入真实代付及付款凭据。自动订单的官网代付事实锁定；待补全阶段指定客户、账号、银行卡、客户实收、汇率、开通与到期时间。客户可从当前抽屉快捷新增并自动选中。
4. 客户手续费 = 代付金额 × 手续费率 ÷ 100，按付款币种最小单位四舍五入；如 1000 × 2.5% = 25。可单笔手动改手续费金额。银行实际扣收手续费另列，不与客户收费混用。
5. 财务资料核对后完成订单，按人民币汇率快照生成平衡日记：客户实收、代充收入、客户手续费收入、官网代付成本、银行手续费。Visa 卡只按预存资金卡处理，完成时从选定的人民币代付资金账户扣账；退款仅在真实退款发生后登记：客户退款、官网实际回款和银行手续费实际退回分别入账，支持部分退款和分批回款。未收回的本金与手续费继续保留成本，不自动恢复代付资金。
6. 已核验充值按 ChatGPT 账号保留一条当前使用中订阅，订单记录保留历史。到期时间使用现有全局续费预警天数，显示在「工作台 → 续费操作」和顶部提醒。新的续费订单更新当前订阅指针，旧订单仍可追溯。

7. 未发生退款的已完成订单可通过“更多操作 → 更正订单”修正资料与账务；同一事务内冲销旧日记、更新订阅并重新入账，失败完整回滚，保留版本、原因和审计。自动付款事实不可修改；已有退款或回款的订单拒绝直接更正，避免改写售后金额口径。
8. 客户删除预览与提交时均核验银充进行中订单和活动订阅。账号页支持搜索、真实总数与分页，关联账号、银行卡和客户不再截断固定 500／1000 条。

## 数据与界面

账号清单的“注册时间”按首次录入系统时间 `createdAt` 展示，“已注册天数”按服务器当前时刻减去首次录入时刻，每满 24 小时计 1 天，不足一天显示 0 天；未同步服务器时钟时显示“时间同步中”。“更新时间”继续展示账号主资料的 `updatedAt`，保存账号资料时刷新，浏览页面不改变；登录网络和银行卡是独立记录，不能把该时间理解为所有关联事件的发生时间。上述两列复用现有数据，无迁移或历史回填。

2026-10-02 账号与到期规则：ChatGPT 账号页仅显示未开通的待用账号，状态仅展示启用／停用；开通成功后隐藏，原资料和银充订单保留。自动充值账号密码字段可选择已保存的待用账号，沿用身份读取与登录资料审计。银充订单显示“开通时间 → 到期时间”，并提供“全部订单／已到期订单”页签，服务端以 `dueAt <= 当前服务器时间` 过滤到期订单，未设置到期时间的记录不进入到期页签。

新订单默认按北京时间自然月计算：2026-03-04 10:15 开通，2026-04-03 10:15 到期；续费同日在下月不存在时夹到下月最后一天，再减一天，闰年同样处理。自动订单优先采用同账号、同目标套餐官网核实的账期结束日减一天作为提醒，无法取得官方账期时使用默认规则，不把内部提醒当作官网证明。本次订阅／升级成功时间是订单开通时间，不沿用旧套餐开通日；手工订单默认采用服务器时间并可指定实际开通时间。修改开通时间时，仅自动联动原默认到期值或空值，人工指定日期保留。已有日期不批量修改；历史缺失开通时间的列表展示兼容使用创建时间。本次复用既有字段，无数据库迁移。

- 新表：ChatGPT 账号、银充币种、银行卡资料、银充订单、当前订阅；自动充值任务增加账号关联和加密预期邮箱，财务枚举增加银充收入、成本和手续费。
- 银充订单宽表将客户、ChatGPT 账号、银行卡、代付、费率、客户手续费、银行手续费、实收、利润、到期、充值结果、使用状态、订单状态各放独立列。所有单元格保持单行，长文本省略并提示，窄屏在表格内横向滚动。
- 银行卡保存名称、末四位、付款币种、有效期、备注，以及加密的完整卡号；仅支持先有余额再付款的卡。管理员查看完整卡号须留审计，页面短暂展示后清除。安全码不入库、日志或备注，每笔充值时临时输入。金额使用 Decimal，关键修改、取密、建单、入账和退款均留审计。

## 订阅双成本口径（2026-10-01）

新建手工和自动银充订单使用 `subscription_cost_v2`，两项费用初始为 NULL（待核对），没有费用需明确输入 0。`usdtFee*`、`shoppingFee*` 分别保存原币金额、币种、付款账户、人民币汇率快照及折算金额；人工汇率需填写原因并审计。非零费用必须绑定同币种有效资金账户。

完成凭证中客户实收全额计入订阅收入，本金沿用人民币代付账户规则。USDT 手续费与购物网手续费进入各自专用成本科目和各自付款账户。成本合计为本金加两项费用，费用占本金比例为本项人民币金额除本金人民币金额；不从实收差额倒推。

退款输入 `usdtFeeRecoveryAmount` 和 `shoppingFeeRecoveryAmount` 为原币实际退费，使用原费用快照及原付款账户。费用未退保留成本，累计退费不能超原费用，最后一笔精确冲清剩余人民币成本。本金继续输入实际人民币回款。更正需记录原因、旧新费用和凭证关联；有退款或回款记录时拒绝直接更正。

既有记录迁移默认 legacy，原客户手续费和银行手续费字段保留。旧已完成订单仅在未退款时经更正入口重新核对；旧未完成订单需 `confirmFeeConversion=true` 并明确输入两项费用。禁止自动映射旧费用。
