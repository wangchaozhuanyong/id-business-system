# 库存字段契约与首张正式表实施

日期：2026-11-04。任务：UI-06 首表及 INV-01 字段核对。独立候选基线 e51dd9c9974c6292dbbc6572a5d844a672f0d0f1。未发布。

## 1. 本次真正完成与缺列原因

正式 `accounts.main` 原为13列，无默认隐藏列；手机号等漏项是没有登记列，并非已经隐藏。当前保持 tableId 和旧列 key，增加8个现有响应真值列，扩为21列（20数据列＋操作列），新增字段默认可见。已有用户隐藏偏好继续生效，可通过明确的“列设置”入口查看、全部显示、恢复默认。

| 正式新增列   | 既有响应字段           | 来源／展示                                    |
| ------------ | ---------------------- | --------------------------------------------- |
| 手机号       | displayPhone           | 既有完整业务资料响应，空值显示破折号          |
| ID购买成本   | purchaseCost           | 沿用人民币成本格式；已有排序能力              |
| 采购原币金额 | purchaseOriginalAmount | 单独数字列，不与币种堆叠                      |
| 采购币种     | purchaseCurrency       | 复用 financeCurrencyLabel，中文与代码一起显示 |
| 采购汇率     | purchaseFxRateToCny    | 原采购快照，不拿当前汇率重算                  |
| 采购时间     | purchasedAt            | 沿用既有接口；历史空值回落录入时间的旧口径待核对                      |
| 备注         | remark                 | 单行、完整内容提示                            |
| 录入时间     | createdAt              | 北京时间，独立于注册／采购／修改时间          |

桌面及移动卡共用同一列key和服务端偏好机制。ID标识固定左侧，操作固定右侧；保留原分页、支持的排序、权限、行操作和区域加载。将 createdBy 的列名由“操作人”改为“录入人”，缺失显示“历史未记录”；健康状态显示“账号状态”，记录启停显示“启用状态”，不更改后端枚举或命令。

Apple ID 专用余额原型另补录入人、最近操作人、最近操作时间，原18列变21列。直接读共享库存主档；业务事件更新最近操作，不覆盖录入出处，历史缺失不借当前身份或期初余额登记人补造。此处是原型修复，不冒充新增正式API。
