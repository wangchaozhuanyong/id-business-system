# 兑换码接入比特浏览器

本轮为本地代码交付，未提交、推送、创建 PR、执行生产迁移、部署或真实充值。
本机网站、数据库、Docker 和充值助手均未启动；合成验收不能代替真实端到端验收。

## 功能

- 客户仍在 `/online-recharge` 提交兑换码和完整授权 JSON，套餐由兑换码决定；不能指定卡片、通道、电脑或付款策略。
- 系统配置提供服务器浏览器／第三方代充／比特浏览器。接单开关只影响新请求，已受理任务继续。
  比特默认上限 100，单机单并发；电脑离线或比特未就绪时排队，容量满额不预约兑换码。
- 默认“核对金额后付款”：详情展示账号、套餐、当次应付、税费和月续费，管理员确认后继续。
  全自动必须完整配置三个支持套餐的币种和正数上限，Decimal 比较、等于上限允许、超限转人工。
  币种、套餐、周期和单位不符停止；没有猜测或预填自动付款金额上限。
- 每笔任务固定受理时的通道、设备、付款策略、代理国家及加密连接配置。Pro 5 倍沿用智利代理与 CLP 规则。
  与本机手动任务共用原 Registry 占用检查，不生成第二套业务订单。

## 电脑接入

2026-11-03 已按用户要求扩展为 Mac／Windows 分别登记、网站指定其中一台，并提供一次性后台启动设置。
当前接入以 [网站指定执行电脑](ONLINE_BITBROWSER_WEBSITE_ONLY_20261103.md) 为准；下面保留首轮手动启动记录。

发布及隔离数据库验证完成后再接入。本轮没有执行以下启动步骤。

1. 在“线上代充 → 系统配置”填写比特 Local API 地址、密钥、已存在的分组和标签。
   默认 `http://127.0.0.1:54345`，分组／标签默认“线上代充”；先在比特中启用接口、建好分组与标签。
2. 填写电脑名称并下载配对文件，10 分钟内单次有效。更换凭证前停止旧助手；有运行中任务时拒绝换绑。
3. 把文件移入**执行电脑上本项目**的 `.runtime/bitbrowser-recharge-assistant/device.json`。
   POSIX 目录设为 0700、文件设为 0600；Windows 使用仅执行账户可读取的 ACL。不要提交或共享此文件。
4. 使用 Python 3.11 或以上版本，运行原助手并增加选项：

   ```sh
   npm run auto-recharge:connector -- \
     --allowed-origin=https://管理端域名 \
     --online-config-file=/执行电脑上本项目的绝对路径/.runtime/bitbrowser-recharge-assistant/device.json
   ```

   原脚本准备项目内专用 Python 环境。无需本地网站、数据库或 Docker；HTTPS 主动领取，无新增公网端口。
   关闭网页不影响助手进程，退出助手或电脑休眠后停止执行。不传新选项时原手动助手行为保持原样。

5. 确认电脑在线、比特就绪，公共卡池有适用卡、线上代充有美国账单地址、代理池有对应国家的启用代理。
   缺少安全码时等待管理员补充；CVC 只在任务限定的临时内存通道使用。
6. 选择比特通道并保存，先保留人工模式完成付款前验收。真实付款需另行授权。

配对文件兼容 UTF-8 BOM。首次兑换后原子替换为设备凭据；服务器只存 SHA-256 摘要。
后台可停用电脑，旧密钥、过期或其他任务租约不能继续付款。

## 付款与恢复

- 报价及许可绑定任务、账号、套餐、币种、金额、摘要、版本和租约，5 分钟过期。变化后重新确认，重复确认幂等。
- 全自动也由服务器发放许可，不能从原本机确认接口绕过。浏览器付款请求前先持久化提交标记及加密原付款记录。
- 原付款凭据和精确账号／套餐都确认后才核销、记账和计数；支持 Checkout、PaymentIntent 及升级 Invoice 凭据。
- 未提交付款的掉线任务重新排队。已提交但结果不明进入待核对，保留兑换码与银行卡占用。
- “核对原任务”将**同一任务**交回原设备，以核心 `recheck` 模式读取原付款；不携带卡号、CVC 或付款授权，
  不创建第二个任务、不重新建单、不更换付款编号。明确失败才释放兑换资格；套餐尚未核实则继续待核对。
- 付款前可取消运行中比特任务；取消和付款提交共用任务锁，旧租约不得继续付款。
- 浏览器人工验证完成后，任务详情可通知电脑继续；继续指令只适用于当次租约。
- 新配置只影响新任务；服务器执行器跳过比特任务，设备不能领取其他通道／设备的任务。

## 接口与迁移

现有客户接口不变。以下路径均以 `/api/id-business-v2/online-recharge/` 为前缀：

| 接口                                      | 用途及授权                                     |
| ----------------------------------------- | ---------------------------------------------- |
| `GET admin/bitbrowser/device`             | 电脑状态，读取权限                             |
| `POST admin/bitbrowser/device/pairing`    | 一次性配对，读取及管理权限                     |
| `POST admin/bitbrowser/device/revoke`     | 停用电脑，读取及管理权限                       |
| `POST admin/bitbrowser/tasks/:id/confirm` | 确认报价摘要／版本，读取及管理权限             |
| `POST admin/bitbrowser/tasks/:id/resume`  | 继续人工验证，读取及管理权限                   |
| `POST connector/pair`                     | 单次配对凭据换取设备身份                       |
| `POST connector/rpc`                      | 独立设备凭据及租约校验，无通用 worker RPC 权限 |

设备方法限制为 heartbeat、connection、claim、lease、prepare、quote、quote-status、release、callback。
状态、配对及设备响应使用 no-store。私有 CVC 服务增加任务限定 claim／release，迟到释放不清除别的任务的 CVC。

专属增量 migration：`20261102150000_online_recharge_bitbrowser`，只增加 provider 枚举值与两张表：

- `online_recharge_bitbrowser_devices`：设备身份、唯一槽位、凭据摘要、配对期限、在线／就绪／忙碌状态及时间戳。
- `online_recharge_bitbrowser_states`：任务／设备／租约、账号摘要、报价／授权、提交标记、加密付款记录及版本。

本轮已生成 Prisma Client 并验证 schema，**未应用迁移**。不修改纯净基线、不删除历史数据，无新依赖或环境变量。
正式发布需迁移身份执行增量迁移，并通过现有权限配置流程赋予运行身份新表 SELECT／INSERT／UPDATE，不能赋予 DELETE。
API、管理端、私有 CVC 服务及执行电脑助手需同步更新。兼容回退先停接单及助手、核清已受理任务，保留新增表和历史记录。
