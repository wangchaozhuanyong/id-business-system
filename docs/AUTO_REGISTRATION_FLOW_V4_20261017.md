# 原协议注册逐次诊断与闭环验收

本任务按用户批准的《原协议自动注册修复与验收方案》实施。保留冻结上游服务器 HTTP 模式，不引入桌面或比特注册，不设置双重验证，不修改充值业务、数据库结构、依赖、环境变量或公开接口。

## 实施约定

- 只有新任务建立 `flowEvidence v4`；已有 v1–v3 证据不升级、不重写。四个阶段的既有响应观察仍使用 v3 结构。
- v4 逐次记录响应、网络失败和证据存储失败，保留最近 32 条、全局递增序号及截断标志。最后一次网络失败不能展示为前一次响应；首次失败独立保留。
- 只记录受控响应分类、设备 Cookie 前后存在性和配置默认值相等性。明确证据不足的 403 保持原因未明；不保存 Cookie、密码、Token、原响应或授权链接。
- 诊断存储错误不伪装成网络错误，关键存储、占用及密码检查点失败仍停止后续有副作用步骤。初始化和授权阶段使用准确的中文状态。
- 控制台选择服务时的回车不得误建任务，开始按钮仍支持键盘操作。取消受理仅表示收到请求，最终状态必须回读原任务。

## 无邮箱诊断边界

`worker/precondition_diagnostics.py` 从冻结源码提取原客户端、引擎构造器和初始化方法，保留类继承、真实设置、IP 预检、同一 Session 以及原生自动授权跳转；不调用 `run()`，不加载应用或数据库初始化。

部署操作方先独立核对版本、镜像、源文件摘要及实际持久配置。私有设置只在内存与私有标准输入中处理，任务代理快照必须与当前可只读解析的代理配置一致；不一致时不联网。

诊断仅允许一次 IP 预检、一次授权初始化（最多五次原生跳转），授权通过后最多一次 Sentinel。IP 和 Sentinel 不跟随重定向，作为明确声明的诊断预算差异。首个拒绝或预算达到后停止，不能提交邮箱、密码、验证码、创建账号或换取凭据。预算触发和传输无法确认均为“诊断未完成”，不证明注册失败；诊断通过也不等于账号创建成功。

## 验证与正式交付

纯测试和离线合成浏览器禁止数据库及外部业务请求；存储验证由远端隔离 CI 执行。本机不启动网站、数据库或 Docker。类型检查、定向测试、lint、构建及七项 V2 界面门禁均需通过。

正式发布固定实际当前版本和精确产物，只覆盖批准的注册 Worker 与 Admin；API 运行 JavaScript 保留当前已发布字节，类型变动单独编译核验。发布前后核对现有台账、历史任务、加密记录及其他服务，不重触发结果未定的发布。

无邮箱诊断通过后，才重新核对 `pebbled_88sparrow@icloud.com` 的注册、占用和资料状态并进行一次获准验收。有创建事实时只恢复原账号资料和授权，不重复注册、不更换邮箱。官网身份、加密凭据、注册结果、注册 IP／国家和主台账全部回读一致才登记成功。
