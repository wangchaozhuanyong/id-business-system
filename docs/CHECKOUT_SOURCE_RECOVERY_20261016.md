# 原结算来源恢复

本轮真实核价复验在“恢复原账号与结算资料”阶段得到 409。原 Plus 结算仍可打开，但服务器原建单记录未保存结算编号；后续仅登录及窗口替换记录成为当前窗口来源，使原实现把登录任务当作建单任务。本轮没有发送付款请求，也没有取得填表后最终金额。

修复分别核对建单来源与当前窗口归属。只有唯一未付款建单、完整的已确认窗口替换链，以及各替换窗口的同账号官网身份核实同时成立，才允许读取当前窗口里唯一的原生原结算。后续仍执行原有账号、套餐、结算状态、最终金额与账单指纹校验，并等待单次人工确认；不增加建单或付款权限。

未完整查到历史、多个未识别建单、归属不符、链路缺失、付款／确认／卡片令牌请求及其他原单冲突仍拒绝恢复。原执行记录不改写为成功，历史未知付款保护保留。

业务修改仅为 `recharge-account-restore.ts`、`recharge-unidentified-checkout.ts` 及相应测试。沿用现有已审计回传事务和查询，不新增 API、表、字段、数据库迁移、依赖或环境变量。102 项定向测试及相关类型、构建、ESLint、格式与架构边界通过；发布控制测试 5 项通过。
