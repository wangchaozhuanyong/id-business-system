## 第一批：页面等待、确认与错误

- 读取原任务连接成功并复核账号、报价和有效期后，实际调用确认接口才消费临时凭据。
- 页面内的任务发送标记不随状态、报价或执行记录切换清除；发送后的丢回包只刷新原任务。
- 必要执行进度保存与展示读取分开；展示刷新最多一个在途请求，期间的新进度合并补读。
- 登录模块加载最多 30 秒，取消、页面退出或身份变化会终止原任务等待，迟到模块不再执行。
- 首次业务错误、错误代码和请求编号保留；后续停止或展示刷新失败作为补充信息。
- 启动中切换员工身份时，旧点击不继续创建任务，不写入新身份的页面状态。已取得原启动回执时，
  用原任务能力结束未接管的零付款任务；拿不到迟到回执时保留原任务核查边界。

验证：第一批 111 项定向前端测试通过；第三批最终共 212 项定向覆盖通过。
类型、构建、定向 lint/格式和七项 UI 规则通过。最终构建后的离线浏览器覆盖
1440、768、390 宽度及深浅主题、输入保留、临时凭据清理、连接配置隔离和旧周期确认。
独立审查补修了姓名核实前过早生成付款快照的问题；核实后的姓名和自动地址正确传入卡准备、API 和助手，
点击时的账号、方案、币种、身份和连接仍绑定，明确编辑会结束旧点击。

## 第二批：付款事实与有界收尾

- 本机回调在事务锁内校验任务能力；过期、取消中或已结束任务只补收同账号、原操作、原报价的事实。
- 不恢复过期任务执行、不续租约、不重新占用窗口或账号资源。
- 第一次取消固定五分钟截止；重复取消、迟到普通进度和零付款取消不能倒退已保存的付款事实。
- 完成时保留服务端私有的不可逆收据身份摘要、规范化内容摘要和原应答，清空执行凭据。
  相同完成回执重放不重复建订单、使用地址或记审计。
- 账本严格 CAS；只有版本 `n` 已写为 `n+1` 且规范化内容一致的重发可复用原结果。
- 先采集必要认证事实，再核对原确认/升级的 intent、认证来源、账号、金额及币种。
  临时缓存最多八条、合计 512 KiB，不保存响应正文、卡资料、认证秘密或请求头。
- 结算页、升级和原单复查共用观察收尾。关闭自动操作后最多等待五秒，剩余观察取消有界。
  正文读取最多 30 秒；回调每笔最多十秒，超时不自动重发。
- 收尾合并最强事实，最终账本最多保存一次。已捕获付款证据在保存失败时继续保留并报告原单待核验。
- 助手沿用主分支已有的终态回收，最多保留 128 个简化结果。

最终受影响 Python 回归 400 项通过，最后新增的周期与截止边界再补验 29 项通过。

## 第三批：新周期协议

已实现。公开协议定义位于 `packages/shared/src/v2/auto-recharge.ts`：

- API 列表的可选 `subscriptionCycleProtocol: 1`、助手能力 `next-subscription-cycle-v1` 与管理端启动标记
  同时匹配后启用周期流程。旧组合维持原单只读核查。
- 本机回调增加 `prepare_next_subscription_cycle` 的 `inspect`、`status`、`commit` 阶段。
- 本人认证接口 `POST /api/id-business-v2/auto-recharge/jobs/:id/next-cycle-confirm` 只接受
  `reviewDigest` 和 `confirmedPreviousCycleEnded: true`，不授权扣款。
- 归档键由 API 生成：`history/<旧文档 SHA256>.json`，77 个字符；客户端不能写入历史或周期关闭元数据。
- 复用现有 JSON 保存私有收据、核实资料和一次建单资格，没有新增表、数据库列、依赖或环境变量。
- 完整历史已付款且已开通的记录只允许先核实同账号官网订阅，不填卡、建单或付款。
  官网明确没有有效订阅、全账号没有未决付款，并取得旧周期结束证明后才建立新周期资格。
- 确实缺少旧周期结束证明时，原操作人可以一次人工核实。当前有效订阅、缺失订阅字段、未知付款或
  已知未来账期都不能被人工确认覆盖。合法 Go→Plus／Plus→Pro 保留原升级流程。
- 核实和资格均有五分钟期限；轮询、核实进度和重复请求不延长期限。建单前再次读取官网状态，
  状态变化立即撤销资格，核实流程不延长原任务租约。
- 同一事务归档旧结算并登记转换；历史付款证据原位保留。第一笔新建单标记与一次资格同时消费，
  助手收到保存成功才建单。重放、标记后崩溃或结果未知只能恢复原操作，不再创建第二个订单。
- 未消费资格到期可以重新只读核实原转换；已消费标记不能再次授予新操作。旧格式只读复查可以
  读取已归档周期和新周期未知原单，仍不能调用建单或付款。

验证：API 全部受影响集合 274 项通过；最后的核实进度免续约修正补验三文件 114 项，其中新周期 33 项。
实际 API 回包传入 Python 账本的跨语言契约通过：归档键长度 77，首标记消费一次，精确重放不再建单，
旧付款证据完整。隔离 MySQL 新周期三项、付款回执四项、员工并发十六项全部通过。
实际本地 Chromium 的完整新周期模拟流程建单、付款各一次；网站请求均被本地路由截获。
管理端构建验收确认人工核实不会调用付款接口，核实后仍单独等待官网报价确认。
