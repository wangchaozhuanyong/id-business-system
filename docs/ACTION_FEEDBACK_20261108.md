# 全站操作反馈核对与修复

## 问题与规则

原有 `notify()` 把提示放在 body 的普通层级。模态抽屉和确认框位于浏览器顶层，
会遮住提示并使外部 live region 不可访问；提高 z-index 无法解决。
此外，一些手动刷新没有完成反馈，部分保存回调只关抽屉或重画列表。

统一提示使用手动 Popover 顶层，并放在当前模态容器内；抽屉关闭、重建或打开确认框后继续保留。
成功、失败、提醒与进行中有相应图标／颜色，屏幕阅读器可读，可主动关闭；成功 3.8 秒、失败和提醒 8 秒，
悬停或键盘操作时暂停消失。重复点击复用同一提示，不堆叠遮挡。
提示只写结果，不写密码、查询码、银行卡号、授权或复制正文。

耗时操作复用 `beginActionFeedback()` 或 `withActionFeedback()`，350ms 后显示进行中提示。
只在真实读取／保存成功后提示完成；失败与取消不提示成功，切页后的迟到读取不弹出旧结果。
保存反馈单独观察既有操作，不增加保存 Promise 包装，保留原有回执、冲突和草稿处理顺序。
`completeAction()` 仅在已提交成功且业务回调没有自己的提示时补充成功反馈，避免重复。

## 操作核对

| 操作类别 | 处理 |
| --- | --- |
| 话术、邮箱账号、联系方式、订单／充值码、买家查询码、银行卡号复制 | 共用复制成功反馈；剪贴板失败明确提示并沿用手动复制入口；空值不伪报成功 |
| 2FA 验证码、邮箱池查询码直接复制 | 保留有效期校验，结果通过修复后的公共提示显示 |
| 库存、客户／租户、订单等保存及状态修改 | 成功回调补齐静默场景，保留已有具体结果及冲突错误；慢保存显示进行中 |
| 总览手动刷新 | 成功提示；部分模块失败不报告全量成功，保留各区原资料和失败状态 |
| 员工、库存／业务重试、汇率、操作记录、余额流水、地址、邮箱池刷新 | 明确进行中、完成或失败；仅用户手动操作提示，后台自动更新不弹成功消息 |
| 订单归属人刷新、银行卡刷新／完整卡号读取 | 明确读取结果；保留字段下方校验及错误 |
| 隐藏邮箱资料、收件服务状态、收件记录重读 | 明确读取结果；切页或被更新请求替代时不伪报成功 |
| 个人工具、话术重新读取 | 明确读取成功或失败，保留输入与已有重试入口 |
| 费用规则、分类／客户选项重新读取 | 保留原有草稿处理确认，补充读取完成结果 |
| 指定代充任务核对 | 明确有结果或没有可同步记录，核对不等同同步入单 |
| 批量导入、提取／归还、撤回／恢复、启停／重置 | 复用已有确认、逐行预检／结果和公共提示；本次修复让抽屉内提示可见 |
| 文件下载、邮件查询、网站查询／统计、连接测试与 IP 检测 | 已有就近的进度、结果、错误和重试区，保留具体结果，避免重复弹消息；下载只报告已交浏览器保存 |
| 充值原版及比特嵌入页 | 保留既有按钮禁用、状态、执行结果和错误展示，不改变充值核心、付款或重试行为 |
| 导航、页签、筛选、分页、展开详情、显示／隐藏字段 | 通过页面、选中态或浮层本身反馈，不额外弹成功提示 |

## 验证边界

`test/action-feedback.browser.mjs` 用实际页面、按钮与共享方法，拦截全部请求，拒绝业务写入。
先复现旧版提示被模态遮挡，再检查 1440／390／320px 深浅主题、真实话术复制处理器、重复复制、
确认框、抽屉关闭／重建、剪贴板拒绝、手动复制入口、空值、静默保存回调、慢刷新、防重复请求、
读取失败和切页迟到响应。截图与几何证据保存在项目 `backups/action-feedback-20261108/`。

共享布局夹具补齐 main 新增的套餐选路只读响应；不修改正式选路实现。
相关模块回归包括查询码、2FA、汇率设置／草稿、订单归属人、账号选择、直接操作菜单和共享布局。
完整隔离测试通过远端 CI；本机不启动网站、Docker 或数据库。真实付款、生产数据写入不用于反馈验收。
