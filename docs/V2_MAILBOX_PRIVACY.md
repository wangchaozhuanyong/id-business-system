# 邮箱查询数据边界

## 服务器数据库保留

为保持跨浏览器的邮箱池、买家查询码和官方邮箱授权可用，数据库只保留：

- 完整邮箱地址、备注和邮箱类型；
- 字段级加密的 Gmail/iCloud 应用专用密码或 Microsoft refresh token；
- 买家查询码的 HMAC 哈希、加密副本、末四位提示和到期时间；
- 邮箱状态、最近验证/查询时间、最近错误类型和操作人；
- 邮箱池创建、状态、授权和查询码变更审计。

管理界面继续完整显示邮箱地址和查询码，不使用脱敏文案影响复制和查询。邮箱密码和 OAuth 令牌不回显。

## 不写入数据库

以下数据只在当次请求或短期进程内存中处理：

- 邮件标题、发件人、收件人、正文和附件源数据；
- 买家查询尝试、查询码哈希、IP 哈希和单次查询结果；
- Microsoft OAuth state、授权中间状态和授权码；
- Microsoft access token；refresh token 只保留加密副本。

公开查询和邮箱管理响应使用 `Cache-Control: no-store`，前端不使用
`localStorage`、`sessionStorage` 或 `IndexedDB` 保存查询码和邮件结果。

## 运行限制

- 公开查询限流仅在 API 进程内保留 5 分钟，进程重启后清空。
- Microsoft 授权任务仅在 API 进程内保留；授权进行中若发布或重启 API，需重新发起授权。
- 当前生产为单 API 实例。如果未来扩展为多实例，需使用不记录业务内容的短期共享限流层。
