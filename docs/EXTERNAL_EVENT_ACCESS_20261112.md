# 外部事件接入：已完成范围与下一步操作清单

日期：2026-11-12。本文只属于 ID 业务管理系统独立新版。没有访问生产数据库、修改其他项目、提交或部署。

## 本轮已落地的邮箱通道

谷歌、苹果主邮箱、微软邮箱沿用现有查询码验证、固定服务商地址、TLS 和授权方式，增加只读 IMAP IDLE 监听。实现使用 Node 自带 TLS，无新增依赖、数据库结构或环境变量。浏览器继续使用原查询入口；选择自动更新后，另以同源 POST + `Accept: text/event-stream` 订阅。查询码只在正文中传递，事件只有 `ready/changed/stopped` 和连接内版本号。

同一邮箱共用监听，最多同时监听3个不同邮箱、40个查看连接；沿用查询接口的频率限制。最后一个查看者离开即断开上游连接。初始化、网络恢复及重新显示页面后核对一次快照；只有真实邮件变化才触发后续查询，内容相同不重建结果。新邮件到来保留已展开旧邮件和筛选条件；连续通知合并为当前读取结束后的补读。查询码重置、邮箱改绑、到期或停用立即关闭相应连接，切换账号清理浏览器监听。

IDLE 每25分钟的 DONE/IDLE 和 SSE 心跳仅维持连接，不读取邮件或重绘页面。网络异常最多自动重连3次，持续失败或不支持IDLE明确提示；手动查询和立即刷新保留。[IMAP IDLE 标准](https://www.rfc-editor.org/rfc/rfc2177)允许服务端主动通知，建议在29分钟以内续接IDLE。本实现未依赖 Python 新版本的 idle()，也没有改动现有 Python 收信脚本或其他任务的运行镜像。

本地测试使用合成协议连接、模拟请求处理器和拦截全部网络的真实浏览器。真实服务商的 IDLE 能力、服务器出口和反向代理长连接仍需获准环境验收，不能将离线通过当作已经上线。

## 仍需接入的两个来源

### 1. 自动充值的全局事务事件

已核对当前源码，现有 WebSocket 只接受已知任务订阅。`server/preview.mjs` 的60秒扫描仍承担发现其他窗口/商城新任务的职责，不能直接删除。

外围订阅必须覆盖实际写入路径：

| 来源 | 影响 | 接入后的动作 |
| --- | --- | --- |
| `task_logs`：`job_key`、状态及补充任务结果 | 新任务和成功后的资料更新 | 按任务合并，调用现有 `orderSync.run({ apply: true, jobKeys })`，保持原订单证据规则 |
| `billing_records`：按原关联键产生账单 | 任务先成功、账单后到的补全 | 在服务端关联任务并再次核对，不能只监听成功状态变更 |
| `cdk_codes`、`card_assets`、`orbitcard_card_usage` / `orbitcard_card_recharges`及本地归属资料 | 未完整订单的码、卡及归属证据补充 | 只唤醒受影响的未完整任务，不重发充值、不改写付款结果 |

以上表名来自 `.upstream/codexdaichong/mysql-store.js` 及其 schema；生产实际结构、表引擎和复制格式尚未核验。候选方案是独立 CDC 服务读取 MySQL 已提交行事件，原执行器文件不变。[MySQL 复制格式说明](https://dev.mysql.com/doc/refman/8.4/en/replication-formats.html)说明了行日志的基础；不能据此假定当前环境已经具备复制条件。

批准后按以下顺序实施：

1. 只读核验数据库版本、binlog 是否启用、ROW 格式、行映像、GTID/文件位点、日志保留、网络和权限；只记录配置结果，不记录业务行、密码或连接串。
2. 根据实际版本确定独立连接器及精确依赖锁；最小只读订阅账号由受管秘密配置提供。若需要调整生产复制配置或重启，另列具体变更再审批，不在此许可内自动执行。
3. 在受管隔离环境接收 COMMIT 后事件；服务端丢弃 Session、银行卡、正文等敏感字段，输出任务键及变更类别。回滚不推送。处理进度与待处理任务持久化，业务受理后才推进位点。
4. 启动快照与增量衔接，断线续接、事件重放、任务与账单乱序、超过6个任务的分批处理均验收。现有 `run()` 的409互斥不能直接当作事件已处理；忙时必须排队，不能丢弃事件。
5. 满足全来源发现与补全后，才在获准发布中替换60秒扫描。故障显示同步不可用，恢复时补齐快照，不自动退回固定频率页面刷新。

### 2. 苹果隐藏邮箱的外部通知

`server/apple-relay/vendure-provider.mjs` 目前调用 `icloudRelayCodeTarget` / `icloudRelayMailPage` 等 GraphQL 查询，没有已接入的订阅出口。它属于另一个服务，不能用本项目的普通 IMAP 监听冒充该服务的提交事件。

需要由该服务在邮件保存、重新归属、查询码或授权变化提交后输出可续接的范围通知。本项目只接收主邮箱/别名范围与版本，经原查询码校验后读取既有接口；回滚、重复事件、别名改绑、失效查询码和断线恢复都要隔离验收。实际接口由服务所有者确认后才能实现，本文没有虚构一个已存在的 webhook / GraphQL subscription。

当前仍保留该来源用户主动开启的30秒自动查询选项，默认关闭。没有新增轮询，不能宣称这一来源已完成无轮询更新。

## 授权边界

现有授权足以完成上述普通邮箱监听与离线验证。本项目 `AGENTS.md` 要求保持锁定充值原版，且本机不启动整站、Docker 或数据库；用户通用规则同时要求新增大型依赖、数据库结构及权限逻辑先确认。因此，接下来的 CDC 独立运行依赖、数据库复制接入和另一个邮箱服务的事件出口需要单独确认具体执行范围。

建议批准范围：独立外围订阅的本地开发、必要依赖，以及受管远端隔离验收；允许只读检查外部事件能力。生产权限/复制配置写入、其他仓库修改、提交、推送、部署、付款和外部通知仍按各自明确授权执行。此前批准的3项本地SQLite测试已经完成，不把该许可扩展到其他数据库测试。
