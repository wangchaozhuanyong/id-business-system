# 外部事件接入规则与验收边界

2026-11-12，用户已批准外围组件、必要依赖、远端隔离验收，以及新增生产只读复制账号、FULL行元数据和现有邮件事件接口接入。此前待授权清单已落实为具体实现；授权不覆盖真实付款、订阅变更、外部通知、数据删除或生产回滚。

## 普通邮箱

谷歌、苹果主邮箱与微软邮箱复用IMAP IDLE和同源POST通知。同邮箱共享连接，最多3个来源、40个查看者。首次、恢复和重新显示时核对快照，真实邮件变化才触发读取，相同内容不重绘；保留展开的旧邮件，连续事件合并补读。离页、换码、身份变化、到期、停用和改绑清理连接。IDLE续接和SSE心跳不查邮件。断线最多自动重连3次，持续失败明确提示，手动查询与立即刷新保留。参见[IMAP IDLE标准](https://www.rfc-editor.org/rfc/rfc2177)。

## 自动充值

task_logs、billing_records、cdk_codes、card_assets、orbitcard_card_usage、orbitcard_card_recharges的提交事件经Python订阅器交给Node父进程，复用原orderSync证据及来源幂等规则。迟到账单和本地资料变更重新核对未完整任务，不创建或重发充值任务。

先记录日志位置，再分页读取原入单边界以来创建或更新的任务。业务受理及活动回读成功才确认位点；失败不确认，重放按既有来源去重。被删除的源任务保留人工核对提示，不阻塞后续提交。无关事务不触发页面通知或逐条磁盘同步。六张表的实际引擎已核验为InnoDB。

正式启动器管理独立只读账号、TLS、私有凭据管道与0600检查点，替换主站60秒导入及5秒动态扫描。无事件时不查询；断线补齐缺口，DDL、来源变化及位点过期停止并报告不可用。原执行器及其内置界面保持锁定，不把外围改造称作核心改造。

## 发布与证据

精确依赖锁、事务隔离、重放、只读权限、TLS、撤销、手机与桌面交互分别验收。生产条件准备、合并、确定提交部署、线上只读回读及真实业务端到端是不同证据，统一记录在本项目backups/的发布目录。

本机不启动整套网站、Docker或数据库。此前3项SQLite测试授权不扩展到新数据库测试；此轮数据库测试放在获准远端环境。正式发布继续遵守main、现有CI、单任务发布锁、金丝雀和版本回读门禁。
