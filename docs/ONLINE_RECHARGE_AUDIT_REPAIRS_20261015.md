## 已修复的问题

| 问题                                 | 修复行为                                                                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 一般付款错误可能被当作明确拒付并换卡 | 提交后先核验原账号实际套餐。一般错误且未确认时保留原单待核对，不换卡重付；明确拒付才进入原有轮换路径。上一张卡拒付提示未消失时停止再次提交。                                         |
| 旧订阅被当作本次成功                 | 付款前读取原账号状态。已是精确目标套餐则不提交、不新增成功账单；同账号且明确无订阅的 Free 账号允许缺少套餐字段；身份或订阅状态不明确时停止。                                         |
| 应付金额误取月费／小计               | 只解析明确的今日应付或总额，支持中英文、跨行和 PHP 等货币代码；冲突或无法辨认时保留未知，不用折扣前金额、税额估算或页面首个金额代替。业务记录沿用十进制字符串／Decimal。             |
| 第三方错单失败被当作原单失败         | 成功、失败和原单复查都核对供应商订单／任务身份；缺失或不一致时待核对，不释放原单后重建付款。                                                                                         |
| 续费变更被银行卡提交校验拦截         | 在现有任务 JSON 中独立记录续费动作和提交意图，验证租约、原账号和动作；只发一次 POST，再读取同账号实际续费状态。查询不明和租约中断不重放。                                            |
| 续费原单核对可能被当作付款           | 按原续费动作只读核验 `autoRenewRaw` 和实际上游账号，不凭目标套餐存在确认付款；不创建账单、不增加卡次数、不把续费任务标为已付款。原账号仍有充值或续费待核对时，禁止创建新的变更任务。 |
| 后台兑换提交可绕过管理权限           | 兼容接口路径保留，但移除匿名入口；读取需要后台登录及读取权限，提交需要管理权限，任务记录实际操作人。旧独立路径重定向到后台。                                                         |
| 概览把检测／调试成功算作充值成功     | 分开显示任务成功和已确认充值；确认充值只统计充值任务的付款确认标记。                                                                                                                 |
| 结果和明细缺失或误查询               | 兑换码详情只跟踪真正的关联任务；消费汇总数组可显示；订阅、会话预览、浏览器池字段补齐；浏览器状态注明检测快照，登录日志仅管理员可见。                                                 |
| 回调重试不能重交付安全码             | 已验签的相同事件可向临时内存重交付原卡安全码；卡片及回执仍幂等，正文冲突拒绝。交付失败或资料不匹配时准确返回不可用；安全码不落库。                                                   |
| 动态提取链接被当作代理连接           | 新增 IPDEEP 固定 HTTPS 生成链接适配，每任务只提取一次并固定该次端点；下一任务重新提取。支持四段网关及直连协议。提取失败停止，不回退为无代理；不做 IP 去重。                          |

`tableSchemas.ts`、`sections.ts`、权限登记及相关测试；旧路径在 `apps/admin/src/v2-router.ts` 接入后台。

`payment-retry.js`、`subscription-check.js`、`mysql-store.js`。

既有返回值增加充值统计和任务展示字段；既有任务 JSON 增加续费提交／原单核对信息。
未来上线时需要同时更新 API、Admin 和独立执行器，不能只换页面。
