### 1.1 数据治理边界

数据治理只允许管理员访问。恢复和清理必须先冻结确定性影响预览并填写备份证据，再由非发起人审批；
审批通过后按批次执行，每个条目独立事务、记录结果审计编号，并保留可恢复的执行检查点。账号恢复后保持
停用，业务选项恢复时检查原唯一键冲突，订单只恢复可见性且不改变锁定和财务状态。清理范围仅限已结束、
超过保留期且未被礼品卡引用的汇率采集历史；通用硬删除保持关闭，不开放任意表清理能力。

员工账户只允许管理员开通，不提供公开注册。安全中心写操作仅限管理员：开启强制 MFA 前必须保证
所有启用管理员均已绑定，强制策略开启后不得停用或重置启用管理员的 MFA；IP 白名单修改后必须仍
包含当前请求 IP，无法确认当前 IP 时拒绝启用规则。我的账户只读取当前用户且默认脱敏，设备与 MFA
操作不接受其他用户 ID。仪表盘按当前用户权限返回分域数据，无权限值必须标记为不可用，不得伪装为
0；库存只合计人民币账面成本，不得混加不同原币余额。业务监控仅管理员可访问，异常由源业务状态
实时计算，修正源数据后自动消失，不维护第二套手工“已处理”状态，也不发送外部通知。
系统监控仅管理员可访问，只执行只读探针和聚合查询；Realtime 浏览器连接、历史错误率、慢请求历史、
托管备份与恢复没有可信运行时证据时必须显示“未知”，不得据此宣称正常或故障。

## 2. 业务规则

- 所有业务操作由内部员工完成。
- 供应商付款与礼品卡加卡是两套独立快照：供应商实际到账 USDT 按付款结算汇率增加供应商人民币
  余额；礼品卡仍按“面值 × 加卡汇率”形成该卡人民币成本并扣减供应商人民币余额。
- 加卡供应商资金采用手工期初切账，切账前历史记录不伪造资金扣款。余额不足允许加卡并形成负数，
  前端必须显示预计余额、欠款金额和强警告。
- 被赎回和 ID 报损属于经营者损耗，不改变供应商资金余额；只有礼品卡撤回按原始供应商扣款金额
  精确返还，不使用当前汇率重算。
- 供应商付款、调账、付款撤销和供应商更正只通过不可变流水处理；付款手续费单独记录，不增加
  供应商余额。
- 加卡记录标记“被赎回”时可选择同时报损冻结该 ID；未选择时只损失当前礼品卡，选择后先扣除
  当前礼品卡，再将 ID 的剩余余额与余额人民币成本计入损耗但不清零，两项操作原子完成。
- 续费只完成系统内订单、余额、成本和开通台账。
- 汇率采集是唯一允许的联网业务采集。
- 订单匹配只能使用同国家、状态正常、余额足够、未占用且未卖出的 ID。
- “保留 ID”不计 ID 购买成本；“卖出 ID”保存购买成本快照并停止匹配、加卡、余额调整和续费。
- 取消未完成的卖出订单会自动收回 ID；退款默认保持已卖出，只有明确确认“ID 已收回”才恢复可用。
- ID 报损会冻结资料并保留余额与余额人民币成本，同时把余额成本和未售 ID 采购成本计入损耗；
  已售 ID 的采购成本已在订单完成时确认，不重复计损。
- 已卖出 ID 允许报损并保留原销售关系；已报损冻结期间不允许编辑、删除、加卡、调余额、匹配、
  扣款或续费；解除冻结会自动生成反向财务流水冲回损耗，但不自动恢复历史开通记录。
- 金额使用 4 位 Decimal；利润与建议收款均按“余额成本 + 实际计入的 ID 成本 + 平台手续费”计算。
- 逐单 `profitAmount` 只用于订单核对，不再次加入总利润；处理中订单只显示预计利润，完成后才确认。
- 财务同时提供经营利润、分币种资金收支和资产余额三套视图，三者互相对账但不得混算。
- 给卡商充值只把自有资金转为卡商预付款，不立即确认亏损；购卡、赎回、报损、退款无法收回或
  订单完成时才按对应规则确认成本或损失。
- 礼品卡撤回先转为待卡商退款；收到退款时关闭应收，最终无法收回时才确认损失。
- 额外经营开支按分类记录 CNY、MYR 或 USDT 原币金额、付款账户和交易汇率快照。
- 本位币固定为 CNY，财务日界线和月界线使用 `Asia/Kuala_Lumpur`。CNY 汇率固定为 1；
  USDT/CNY 使用现有 P2P 汇率结果，MYR/CNY 使用 ECB 的 CNY/EUR 与 MYR/EUR 交叉汇率。
- 每笔交易锁定汇率快照，历史利润不随最新汇率漂移；最新汇率只用于资产估值和未实现汇兑变化。
- 汇率缺失或过期时不得使用零值或静默沿用；人工汇率必须填写原因并审计。
- 财务日记发布后不可编辑或删除，只允许冲销并重记；已关账月份禁止新增日记，重新打开必须填写
  原因并审计。
- ID 密码、密保和手机号等敏感字段加密保存并默认脱敏。
- 礼品卡号继续加密保存，但在具备余额查看权限的加卡记录和余额变动页面直接显示完整值；操作日志
  仍只允许记录脱敏卡号。
- 删除采用软删除；不可变账务通过反向流水纠正。

## 3. 财务核算闭环

经营净利润按人民币确认：

```text
已完成订单收入
- 平台手续费
- 已消耗礼品卡余额成本
- 已卖出 ID 成本
- 退款及退款成本
- 礼品卡赎回损失
- ID 余额报损
- 未售 ID 采购成本报损
- 额外经营开支
± 已实现汇兑损益
```

资金收支按 CNY、MYR、USDT 分别统计实际收入、实际付款和净现金流。资产余额统计自有资金账户、
卡商预付款、未消耗礼品卡余额成本、未售 ID 采购成本和待卡商退款。当前资产按最新汇率给出人民币
估值，但估值变化不进入经营净利润。

业务写入和对应财务日记必须在同一数据库事务中完成，失败全部回滚；幂等键重复提交不得重复建账。
订单完成、退款、取消、收回，礼品卡入账、赎回、撤回、退款，ID 采购、卖出、报损以及手工开支均
必须能够从财务明细追溯至原始业务记录。

历史数据按 CNY、汇率 1 生成 `legacy_assumed_cny` 回填日记；卡商余额、自有资金余额和系统外旧开支
由启用向导录入期初余额。期初余额不进入当期利润。在期初余额和遗漏开支确认前，经营分析必须显示
“历史数据未完整”，不得宣称为完整生命周期利润。

## 4. 续费预警

- 全局提前预警默认 3 天，可设置 1–365 天。
- 默认列表和右上角提醒显示预警窗口内即将到期及已到期记录。
- 日期范围允许查看任意到期时间。
- 7 天以后的记录只能查看，不能执行续费。
- 提醒不是未读消息，不触发外部发送。

## 5. 快捷新增客户

订单录入选择客户时可打开右侧新增客户抽屉：

- 不跳转页面。
- 复用正式客户创建接口、权限、校验与审计。
- 保存后刷新客户选项并自动选中新客户。
- 保存失败保留表单内容。

## 6. 明确不在范围

- 外部消息推送与消息渠道配置
- 兑换码商城、自动发货和售后补发
- 平台 OAuth、平台订单同步和发货回传
- Apple 官网登录、验证码、设备确认和自动操作
- 图片文字识别
- 网站内容管理
- 公开注册
- 法定会计、报税和固定资产折旧

新增范围必须由用户明确授权后写入本文件。
