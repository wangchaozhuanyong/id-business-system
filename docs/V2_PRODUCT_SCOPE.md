### 1.1 数据治理边界

数据治理只允许管理员访问。恢复和清理必须先冻结确定性影响预览并填写备份证据，再由非发起人审批；
审批通过后按批次执行，每个条目独立事务、记录结果审计编号，并保留可恢复的执行检查点。账号恢复后保持
停用，业务选项恢复时检查原唯一键冲突，订单只恢复可见性且不改变锁定和财务状态。清理范围仅限已结束、
超过保留期且未被礼品卡引用的汇率采集历史；通用硬删除保持关闭，不开放任意表清理能力。

业务删除的影响分级、禁止物理删除对象和新增删除功能准入条件统一遵守
[`V2_DELETE_SAFETY.md`](./V2_DELETE_SAFETY.md)。

员工账户只允许管理员开通，不提供公开注册。安全中心写操作仅限管理员：开启强制 MFA 前必须保证
所有启用管理员均已绑定，强制策略开启后不得停用或重置启用管理员的 MFA；IP 白名单修改后必须仍
包含当前请求 IP，无法确认当前 IP 时拒绝启用规则。我的账户只读取当前用户且默认脱敏，设备与 MFA
操作不接受其他用户 ID。仪表盘按当前用户权限返回分域数据，无权限值必须标记为不可用，不得伪装为
0；库存只合计人民币账面成本，不得混加不同原币余额。业务监控仅管理员可访问，异常由源业务状态
实时计算，修正源数据后自动消失，不维护第二套手工“已处理”状态，也不发送外部通知。
系统监控仅管理员可访问，只执行只读探针和聚合查询；Realtime 浏览器连接、历史错误率、慢请求历史、
托管备份与恢复没有可信运行时证据时必须显示“未知”，不得据此宣称正常或故障。

## 2. 业务规则

- 全系统用户可见时间、时间表单、日期筛选、导出文件名和业务日统一使用 `Asia/Shanghai`；当前时刻
  由后端提供，浏览器时区和本机时钟不得改变业务语义。数据库的时刻字段继续保存绝对时刻，纯业务
  日期继续保存日期值，接口边界负责北京时间与绝对时刻之间的转换。
- 所有业务操作由内部员工完成。
- 所有登记数据表支持当前用户选择需要显示的业务列；偏好按用户和表标识存入数据库，在刷新、重新登录和更换设备后保持生效，不影响其他用户。
- 列显示偏好只改变前端展示，不改变接口权限、数据查询范围或导出口径；操作列和系统控制列不允许隐藏。
- 供应商付款与礼品卡加卡是两套独立快照：供应商实际到账 USDT 按付款结算汇率增加供应商人民币
  余额；礼品卡仍按“面值 × 加卡汇率”形成该卡人民币成本并扣减供应商人民币余额。
- 加卡供应商资金采用手工期初切账，切账前历史记录不伪造资金扣款。余额不足允许加卡并形成负数，
  前端必须显示预计余额、欠款金额和强警告。
- 被赎回和 ID 报损属于经营者损耗，不改变供应商资金余额；只有礼品卡撤回按原始供应商扣款金额
  精确返还，不使用当前汇率重算。
- 供应商付款、调账、付款撤销和供应商更正只通过不可变流水处理；付款手续费单独记录，不增加
  供应商余额。
- 加卡记录标记“被赎回”时可选择同时报损冻结该 ID；未选择时只损失当前礼品卡，选择后先扣除
  当前礼品卡，再将 ID 的剩余余额与余额人民币成本计入损耗但不清零，两项操作原子完成。
- 续费只完成系统内订单、余额、成本和开通台账。
- 联网能力仅包括汇率采集，以及管理员验证或买家主动查询时连接受管 Gmail/iCloud/Microsoft 邮箱；邮箱读取
  只允许系统内受控的 IMAP 主机，不接受用户提供上游地址，也不执行后台轮询或常驻同步。
- 库存 ID 匹配只能使用同国家、状态正常、余额足够、未占用且未售出的 ID；
  客户已购 ID 必须手动选择，且只能由原销售订单所属客户使用。
- “保留 ID”不计 ID 购买成本；首次“库存 ID + 卖出”保存购买成本快照并仅确认一次
  ID 成本。客户已购 ID 后续下单、续费、加卡和调账不改变归属，订单 ID 成本固定为 0。
- 已售 ID 仅允许原购买客户继续开通业务或续费；服务端必须重新校验客户归属、国家、余额、
  业务分类冲突、资料状态、报损状态和订单锁。
- 已完成订单退款按原实收金额执行整单全额退款；若本单包含已售 ID，系统同步把 ID 标记为
  “ID 已退款”、解除客户归属、冲回本单 ID 成本并直接恢复可用，同时取消来源开通记录并释放订单锁。
  ID 当前剩余余额和余额成本默认保留；只有确认原消费已实际退回时，才按历史消费流水精确恢复。
- “额外退款成本”只记录订单本金以外实际支付的通道手续费、平台罚款或额外补偿，不得重复填写
  订单本金、余额成本、平台手续费或 ID 成本。退款后的逐单结果不再保留原实收收入。
- ID 管理允许对员工误标的已售 ID 执行“纠正售出”，必须填写原因；该操作不退款、不改变来源订单
  业务状态、不取消来源开通或业务锁，保留 ID 当前余额、余额成本和采购成本原值，仅解除客户归属、
  更新 ID 去向与利润，并在已完成订单已确认 ID 成本时生成冲回分录。存在下游客户已购订单、
  下游有效业务、其他活动锁或报损冻结时禁止纠正。
- ID 报损会冻结资料并保留余额与余额人民币成本，同时把余额成本和未售 ID 采购成本计入损耗；
  已售 ID 的采购成本已在订单完成时确认，不重复计损。
- 已售 ID 允许停用、启用和报损，操作不得清除原客户归属；停用后不允许下单、续费和加卡。
  已售 ID 报损只确认剩余余额成本损失，ID 采购成本损失为 0；已报损冻结期间不允许编辑、加卡、调余额、
  匹配、扣款或续费。
  报损记录不允许物理删除；恢复时自动生成反向财务流水冲回损耗，并保留原报损快照和审计记录，
  但不自动恢复历史开通记录。
- 金额使用 4 位 Decimal；利润与建议收款均按“余额成本 + 实际计入的 ID 成本 + 平台手续费”计算。
- 逐单 `profitAmount` 只用于订单核对，不再次加入总利润；处理中订单只显示预计利润，完成后才确认。
- 财务同时提供经营利润、分币种资金收支和资产余额三套视图，三者互相对账但不得混算。
- 售后业务报表只汇总 `customer_owned` 订单，以总账凭证为唯一事实来源；ID 成本必须为 0，
  出现非零值时同步进入财务对账异常。
- 给卡商充值只把自有资金转为卡商预付款，不立即确认亏损；购卡、赎回、报损、退款无法收回或
  订单完成时才按对应规则确认成本或损失。
- 礼品卡撤回先转为待卡商退款；收到退款时关闭应收，最终无法收回时才确认损失。
- 额外经营开支按分类记录 CNY、MYR、USD 或 USDT 原币金额、付款账户和交易汇率快照。
- 手工资金流入按受控性质区分经营收入、股东投入和借入资金。经营收入必须选择可维护的收入分类并计入
  当期经营利润；股东投入和借入资金只增加资金账户并分别计入权益和负债，不得计入经营利润。订单收入、
  供应商退款和礼品卡退款继续由原业务自动记账，禁止通过手工资金流入重复确认。收款流水号和收款凭证
  均为选填；填写流水号时仍执行跨订单和手工收入的全局防重，上传凭证时仍加密保存并校验完整性。
- 本位币固定为 CNY，财务日界线和月界线使用 `Asia/Shanghai`。CNY 汇率固定为 1；
  USDT/CNY 使用现有 P2P 汇率结果，MYR/CNY 使用 ECB 的 CNY/EUR 与 MYR/EUR 交叉汇率。
- 每笔交易锁定汇率快照，历史利润不随最新汇率漂移；最新汇率只用于资产估值和未实现汇兑变化。
- 汇率缺失或过期时不得使用零值或静默沿用；人工汇率必须填写原因并审计。
- 人民币收购报价首批固定 15 个币种，每个币种使用自身兑人民币市场汇率、独立收购比例、显示单位和
  受控舍入方式计算，不得以美元中转。ExchangeRate-API 免费开放接口以 CNY 为基准，在北京时间每天
  09:05 采集，无需 API Key；接口方向取倒数后
  才得到“1 单位外币兑人民币”。任一已启用币种缺失、非正数或波动超过设置阈值时整批不发布；异常批次
  必须由管理员确认或驳回，采集失败、等待审核和报价超过有效时限时均保留最后有效报价并明确提示。
- 收购报价允许生成微信排版、等宽排版和纯文本并在管理端复制；系统不连接或群发到任何外部消息软件。
- 财务日记发布后不可编辑或删除，只允许冲销并重记；已关账月份禁止新增日记，重新打开必须填写
  原因并审计。
- ID 密码、密保和手机号等敏感字段加密保存并默认脱敏。
- 敏感资料展示按角色、字段和使用位置配置；管理员业务资料默认完整显示，密码和密保只允许受控查看，
  审计始终脱敏。脱敏搜索使用服务端 HMAC 盲索引，不依赖页面展示值，详见
  `docs/V2_SENSITIVE_DATA_POLICY.md`。
- 礼品卡号继续加密保存，但在具备余额查看权限的加卡记录和余额变动页面直接显示完整值；操作日志
  仍只允许记录脱敏卡号。
- 删除采用软删除；不可变账务通过反向流水纠正。

## 3. 财务核算闭环

经营净利润按人民币确认：

```text
已完成订单收入
+ 其他经营收入
- 平台手续费
- 已消耗礼品卡余额成本
- 已卖出 ID 成本
- 退款及退款成本
- 礼品卡赎回损失
- ID 余额报损
- 未售 ID 采购成本报损
- 额外经营开支
± 已实现汇兑损益
```

资金收支按 CNY、MYR、USDT 分别统计实际收入、实际付款和净现金流。资产余额统计自有资金账户、
卡商预付款、全部未报损 ID 的未消耗余额成本、未售 ID 采购成本和待卡商退款。当前资产按最新汇率给出人民币
估值，但估值变化不进入经营净利润。

业务写入和对应财务日记必须在同一数据库事务中完成，失败全部回滚；幂等键重复提交不得重复建账。
订单完成、退款、取消、收回，礼品卡入账、赎回、撤回、退款，ID 采购、卖出、报损、手工资金流入以及手工开支均
必须能够从财务明细追溯至原始业务记录。

历史数据按 CNY、汇率 1 生成 `legacy_assumed_cny` 回填日记；卡商余额、自有资金余额和系统外旧开支
由启用向导录入期初余额。期初余额不进入当期利润。在期初余额和遗漏开支确认前，经营分析必须显示
“历史数据未完整”，不得宣称为完整生命周期利润。

## 4. 续费预警

- 全局提前预警默认 3 天，可设置 1–365 天。
- 默认列表和右上角提醒显示预警窗口内即将到期及已到期记录。
- 日期范围允许查看任意到期时间。
- 7 天以后的记录只能查看，不能执行续费。
- 提醒不是未读消息，不触发外部发送。

## 5. 快捷新增客户

订单录入选择客户时可打开右侧新增客户抽屉：

- 不跳转页面。
- 复用正式客户创建接口、权限、校验与审计。
- 保存后刷新客户选项并自动选中新客户。
- 保存失败保留表单内容。

## 6. 个人工作区与在线工具

- 全局侧栏左下角提供当前登录用户的个人工作区，不新增业务页面路由。
- 用户可以新增、修改、删除和排序自己的快捷网址；设置按用户存入数据库并跨设备保持，其他用户
  不可读取或修改。
- 快捷网址只允许 `http://` 和 `https://`，点击后使用浏览器新标签页打开，不通过后端代理访问目标站点。
- 当前系统的内置工具包含在线获取 2FA 验证码、邮箱查询与邮箱池、网站即时监控、多平台作品解析，
  以及管理员专用的“Google 表格同步”和“中转脚本”；2FA 可从登录页或个人工作区打开右侧抽屉，
  未登录也可使用，邮箱查询另提供公开 `/mailbox` 页面。
- 网站即时监控在个人工作区以“网站监控”右侧抽屉提供，只允许已登录用户检测单个公开 HTTP/HTTPS
  地址的状态码、总响应时间、安全跳转链和 HTTPS 证书有效期。后端必须在每次请求及每次跳转前重新
  解析并固定公开目标地址，阻断本机、内网、链路本地、保留地址和包含账号密码的网址；限制单用户
  频率和并发。系统内置 `https://flashcast.com.my` 作为默认监控目标；用户临时输入的其他网址及检测
  结果不写入数据库、日志、审计或浏览器持久化存储。健康检测不包含定时巡检、检测历史和外部告警。
- 同一抽屉内的装修网站访问统计仅管理员可读取，固定查询 FLASH CAST 自有统计资源和数据流，
  不随健康检测输入的网址切换。近 7／30 天的浏览量、去重访客数、访问次数和每日明细来自 Google
  Analytics 只读报表接口；日期按媒体资源实际时区标明，刷新失败保留最后成功内容。无授权和
  未返回记录必须明确显示，不得视为零访问。原始 IP 不从 GA4 获取；装修网站公开页面另经
  Cloudflare Pages Function 采集访问时间、路径和可信来源 IP，并以 HMAC 签名发送到固定 AWS API。
  浏览器请求不得包含 IP、查询字符串或 referrer。ID 系统使用独立表字段级加密保存 IP，使用 HMAC
  盲索引完成独立 IP 统计和精确搜索，在线记录最多保留 30 天。访问记录、精确 IP 搜索和完整 IP
  查看仅管理员可用；列表默认脱敏，完整值查看必须写审计且不得把 IP 写入审计内容。
- “中转脚本”支持 Gemini 订阅号、AI Studio API Key 和 Google Cloud Vertex AI 三种部署模式。
  订阅号模式完成 Antigravity OAuth、隐私设置、实时模型同步、参考映射复制和逐模型验收；
  API Key 模式固定验证 `gemini-3.7-flash` 与 `gemini-3.1-flash-tts-preview`，先直连 Google 官方接口测试，
  再创建 CloudBridge 账号并做单账号测试；Vertex AI 模式完成项目创建、结算绑定、API 启用、
  服务账号与最小权限、参考模型白名单复制。所有异步操作和逐模型测试按步骤落库并支持续跑；
  同一任务必须持有有时效的数据库执行租约，禁止双击或多标签页并发重复执行。
- 中转脚本仅限管理员使用，中转站服务端地址固定为 `https://codexgemini.cc`，不得把后台接口变成任意 URL
  代理。Google OAuth 客户端密钥、OAuth 令牌、CloudBridge 会话和任务中的服务账号 JSON 使用现有字段级
  加密保存，密码与 2FA 验证码不得持久化或写入日志、响应和审计；API Key、订阅号授权会话和服务账号 JSON
  仅加密暂存，在相应凭据使用完或任务加入正式分组后立即清除。
- 在线版不执行 Google 密码自动填写、验证码/CAPTCHA、付款、条款确认或浏览器指纹操作；这些高风险交互
  必须由管理员在 Google 官方页面完成。任何模型验收失败时，中转站账号必须保持不可调度。
- Google 表格同步仅限管理员使用，固定为系统到 Google 网盘的单向报表同步，不接受表格回写。
  系统使用 `drive.file` 最小权限，只管理自己创建的报表文件；OAuth 客户端密钥、刷新令牌和表格文件
  编号必须字段级加密保存。后台每 30 秒核对订单、加卡、续费和财务版本，仅在数据变化时更新，也可
  手动立即同步；同步失败只记录脱敏状态并自动重试，不得阻塞任何业务写入。
- Google 报表固定包含订单、加卡、续费和财务汇总，每张明细表最多保留最近 10,000 条。不得同步 ID
  密码、密保、邮箱授权信息、应用专用密码、完整礼品卡号、手机号、其他联系方式、Token 或审计敏感
  内容；Google 表格只能作为运营报表，不能替代 S3 加密数据库备份和恢复流程。

  256 MB，同一用户同时只允许一个解析和一个下载任务，解析容器不得暴露宿主机端口。
- 2FA 工具支持 Base32 密钥、`otpauth://totp/` URI 和多行账号文本。临时查询仍只在浏览器
  内存中生成，临时密钥、验证码和完整账号文本不得上传、持久化、缓存或写入日志与审计。

- 2FA 计算优先使用已同步的服务器时间；无法同步时必须明确提示本机时间可能导致验证码不准确。
- 管理员可把 Gmail、iCloud 或 Microsoft 邮箱加入系统邮箱池。Gmail/iCloud 使用平台生成的应用专用

  日志和审计不得返回这些授权凭据。

  邮箱池直接查看和复制。管理员可搜索、筛选、分页查看邮箱池，批量导入 Gmail/iCloud，停用查询、
  更新或重新授权邮箱、重置买家查询码；历史只存 HMAC 的查询码需要重置后才能查看完整值。
