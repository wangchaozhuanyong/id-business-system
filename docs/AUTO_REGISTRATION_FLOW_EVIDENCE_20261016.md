# 自动注册前置响应校验与任务诊断

## 问题与范围

两次真实注册任务均在密码请求收到 HTTP 400／`account_creation_failed` 后结束。密码检查点已可靠保存，但账号创建尚未确认，未进入账号保存及主台账同步。错误响应未提供细因，不能把本次失败归因为代理、邮箱或密码。

只读检查及内存模拟确认：初始化仅凭设备 Cookie 可以放行错误 HTTP 状态；注册前一步收到 HTTP 200 时，即使 JSON 无效或页面类型未知也会继续提交密码；合法页面类型 `password` 的日志会被整行脱敏。现有原记录无法补回从未保存或在写入前已隐藏的响应信息。

本任务于 2026-10-16 获用户明确批准实施。仅修改现有自动注册适配层、任务类型和详情展示，以及必要测试和发布配套；冻结的 upstream 源码、请求地址、请求头和代理选择保持原样。不新增接口、数据库表、列、迁移、依赖或环境变量。

## 前置门禁

- 初始化响应必须取得成功 HTTP 状态和 HTTPS 官方来源，设备 Cookie 不能单独代表初始化成功。
- 注册前一步必须取得官方来源、HTTP 200、有效 JSON 对象和已知页面类型。密码页进入原密码流程；已有账号验证页进入原验证流程，仍须独立核验身份。
- 无法确认前置状态时停止原任务，在密码提交之前给出明确诊断；不自动更换邮箱、解除占用或重复创建。
- 原 `firstFailure` 格式及首次失败不可覆盖规则保持兼容；原任务、人工资料和恢复边界继续保留。

## 安全任务证据

现有加密 task binding 及任务读取结果增加可选 `flowEvidence`，版本为 1，最多包含 `authorize`、`signup`、`password` 三个阶段。

每个阶段仅记录观察时间、HTTP 状态、内容类型枚举、JSON 结构枚举、页面类型映射、官方来源判断、最多五项重定向域分类、是否截断、请求编号存在位及 SHA-256 摘要、阶段判定和受控原因。原始页面类型仅在内存映射为受控值；不保存请求正文、完整响应、Cookie、Token、密码、授权状态或含查询参数的 URL。

证据只属于任务，不写入邮箱公开事实、账号台账或同步资料。旧任务缺少该字段仍可读取；未知字段、异常枚举及不合法结构须被校验器拒绝。两个任务详情入口仅展示中文白名单标签，不直接展示内部键、未知字符串或请求编号原值。

## 检查与发布

纯内存单元测试覆盖错误初始化、非官方来源、异常 JSON、缺失和未知页面、正常密码页、已有账号验证页、敏感信息隔离、旧记录兼容及原失败不覆盖。本机不连接或创建数据库，不启动网站或 Docker；数据库夹具和完整 Worker 回归在远端 CI 隔离环境执行。

界面修改运行七项 V2 规则、类型检查、定向测试及构建，并以合成响应检查深浅主题、宽窄屏、旧记录和错误反馈。正式发布沿用当前单一发布流程，核对最新主分支与实际运行前驱，保留其他服务、数据库及并行源码。

正式发布后，选择新的“未注册、暂无任务”邮箱，在该次账号创建及条款确认后仅提交一次。只有官网身份、凭据保存、主台账及邮箱原任务全部回读一致才登记注册成功；若仍被拒绝，保留新证据并停止继续消耗邮箱。
