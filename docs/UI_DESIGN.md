# ID 业务管理系统 UI 规则

## 1. 设计目标

- 高密度后台界面保持清晰、稳定、可扫描。
- 相同业务结构复用相同组件和交互，不为单页制造特殊规则。
- 桌面端优先提高录入效率，移动端保证核心操作完整可用。
- 所有状态必须来自真实数据，不使用视觉占位冒充成功。

## 2. 页面结构

- 页面级标题由 `V2AdminLayout` 根据路由 `meta.title` 统一渲染，业务页面不得再次渲染同名或同义标题。
- 每个业务路由只允许一个页面级 `h1`；业务页面内的 `h2/h3` 只用于命名真实内容分区。
- 页面标题下需要补充数据口径、状态、更新时间或安全边界时，统一使用不带标题能力的
  `V2PageContext`；不得用卡片标题、粗体标题或禁用按钮重复表达页面名称。
- 主要操作放在首个工具栏或 `V2PageContext` 的操作区，不再创建第二套页面头。
- 筛选区、数据区和分页区使用稳定的纵向顺序。
- 筛选条件和操作在空间足够时保持同一行，只有实际空间不足时才换行。带标题的分组筛选复用 `V2ListToolbar`，已有简单分组可继续使用
  `v2-filter-bar`、`v2-filter-bar__fields` 和 `v2-filter-bar__actions`；筛选组必须占用可用宽度，
  不得用未定宽父级中的百分比控件宽度触发过早换行。普通列表内联表单复用 `records.css` 的共享规则。
- 只有搜索、筛选和新增／导入操作的列表，统一将内联表单放入 `V2PageContext` 的 `filters` 插槽，
  操作放入 `actions` 插槽；说明由公共帮助按钮保留，宽屏合为一行、窄屏自然换行。
  页面直属表单与公共工具栏内表单共用标签、控件宽度和断点规则，不在页面内另写标签偏移。
- 业务页使用 `v2-page-layout` 的共享纵向间距（兼容现有 `v2-records-page`）；`V2AsyncRegion` 内容内的相邻区块同样由共享间距控制，不在单页用负边距拼接卡片。
- `v2-records-page` 与 `V2AsyncRegion` 内容网格均使用可收缩的 `minmax(0, 1fr)` 列，防止新列表被长邮箱、表格或操作区撑出页面；窄屏列表标题和操作统计在同一标题区内换行，不得把标题挤成竖排。
- `v2-records-list` 的分区标题直接使用 `<header>`，复用共享内边距和分隔线；不得用无样式的 `<div>` 包裹标题。
- 桌面表格在容器内滚动，关键状态与操作列可固定。
- 移动端使用信息卡列表，不把宽表格强行压缩。
- 页面不得出现互相覆盖的悬浮按钮、抽屉、固定底栏或双重滚动区。

### 新页面的公共布局入口

- 页面原生根容器统一添加 `v2-page-layout`；异步内容由 `V2AsyncRegion` 自动管理模块间距。
  嵌套的纵向模块组使用 `v2-page-stack`，不要在新页面复制 `display/grid/gap` 或单页断点。
- 模块间距、面板内部间距、控件间距分别使用 `layout.css` 中的
  `--v2-layout-section-gap`（14px）、`--v2-layout-panel-gap`（16px）、
  `--v2-layout-control-gap`（10px）；面板内边距使用 `--v2-layout-panel-padding`。
  业务内部的表格、表单分栏仍可保留自己的布局，不用模块间距代替所有控件间距。
- 页首指标总览使用 `V2PageOverview`，每个指标使用 `V2OverviewMetric`，操作放入 `actions`。
  标题和数值统一字号、行高及居中对齐；长说明进入帮助入口，业务日期、当前身份等即时信息保留在 `meta`。
  金额、状态、权限提示沿用现有展示规则，不得把缺失或无权限数据显示为 0。
- 带标题的列表筛选使用 `V2ListToolbar`：默认插槽放筛选控件，`actions` 放查询／刷新，
  `meta` 放总数和当前筛选状态。生命周期导航放 `navigation`，隐藏整个筛选区时绑定 `show-filters`。
  简单列表继续使用 `V2PageContext.filters`。共同布局按实际容器宽度换行，禁止单页覆盖公共几何。
- 列表标题使用 `v2-records-list > header` 和 `V2SectionHeading`，标题与总数共用公共字号、行高和垂直模型。
- `npm run check:admin-ui` 会拒绝缺少公共根布局、复制旧总览／工具栏、硬编码模块间距、
  覆盖公共布局几何或偏移业务表单标签的写法。标签宽度可以调整；独立登录页保留自身表单尺寸。
- 公共布局验收入口：`apps/admin/layout-contract-fixture.html`，不含单页布局样式。
  修改公共组件后运行 `node scripts/acceptance-v2-page-layout.mjs` 和现有筛选布局验收；
  实际列表还要覆盖第一页、末页、空状态、刷新与失败重试。

```vue
<section class="v2-page-layout">
  <V2PageOverview :columns="1" title="资料总览" help="资料的使用说明。">
    <template #metrics>
      <V2OverviewMetric label="筛选结果" :value="total" note="全部匹配资料" />
    </template>
  </V2PageOverview>
  <V2ListToolbar title="资料筛选">
    <el-input v-model="keyword" aria-label="搜索资料" />
    <template #actions><AppButton @click="search">查询</AppButton></template>
  </V2ListToolbar>
  <V2AsyncRegion :phase="queryPhase" skeleton="table" loading-title="正在加载资料">
    <!-- 当前模块的数据列表 -->
  </V2AsyncRegion>
</section>
```

### 2.1 表格操作列

- 桌面表格操作列统一使用 `V2TableActionColumn`，由 table schema 的 `layout`
  选择 `icon | single | double | triple | quadruple | wide` 宽度档位；页面只允许绑定对应的
  `schema.columns[index]`，禁止自行维护宽度或固定位置。
- manifest 只引用当前功能的 table schema，不得复制列契约或宽度数值。
- 操作按钮不得被裁切、遮挡、挤出单元格或静默隐藏；桌面端保持单行，移动卡片允许自然换行。
- 禁止同时叠加 `gap` 与 Element Plus 相邻按钮默认边距，按钮间距只能由统一操作列组件控制。
- 操作超过当前档位容量时，应升级档位或使用带“更多操作”文字说明和可访问名称的菜单。
- 新增、删除或改名操作后，必须重新运行静态表格检查和多视口浏览器布局验收。

### 2.2 表格语义列与对齐

- 所有桌面表格必须显式使用 `V2Table` 并绑定登记过的 table schema；业务数据列
  统一使用 `V2TableColumn`，页面只绑定 `schema.columns[index]`。`kind`、`label`、
  `widthPreset`、`pin` 和稳定语义 `key` 由 schema 统一声明。
- 普通文本左对齐；订单号、ID、卡号等标识左对齐并使用等宽数字；序号居中。
- 数字、金额、汇率和百分比右对齐并使用 `tabular-nums`，保证整数位、小数点和小数位可纵向扫描。
- 日期和时间左对齐并使用等宽数字；完整日期时间默认使用 165px 档位。
- 状态、属性和布尔值居中；颜色不得作为唯一状态提示。
- 数据表状态标签统一使用语义柔和底色、同色边框、状态点和中文文字：成功为绿色、进行中为蓝色、
  待处理或需关注为橙色、失败或异常为红色、中性或已结束为灰色；移动卡片中以标签展示的对应状态
  必须保持一致。
- 表头必须跟随对应内容方向，禁止同一列的表头与内容采用不同对齐方式。
- 空值统一显示 `—`，禁止使用容易与负数混淆的短横线。
- 共享列宽使用 72、112、128、160、165、192、224px 语义档位。除序号列、显式
  `pin` 的关键列、控制列和操作列外，数据列均将档位作为 `min-width`，
  按容器剩余空间比例自动分配；长文本保留单行省略和完整内容提示。
  值与按钮、状态与日期需要同行完整显示时使用 `inlineContent`（320px）组合内容档位。
- 表格单元格横向间距按表格容器宽度通过 `clamp()` 在 8px–12px 之间连续自适应，
  不得根据页面视口或单页样式单独计算。
- 业务页面禁止直接传入 `kind`、`width-preset`、`width`、`min-width`、`fixed` 或
  `layout`；展开控制列固定 52px，选择控制列固定 46px。
- 当共享最小宽度总和超过容器时，保留表格内部横向滚动，不得继续压缩到文字重叠；桌面操作列继续固定在右侧。
- `rowKey.kind = path` 由 `V2Table` 从 schema 注入，页面不得重复声明 `row-key`；
  仅 `rowKey.kind = binding` 允许页面绑定 schema 指定的行键函数。
- schema 或视图 key 切换时，表格横向滚动位置必须同步回到最左端，并在下一次 DOM 更新后校正；
  滚动不允许使用 smooth 过渡。
- 900px 及以下，`mobileMode = cards` 必须提供与 schema id 一一对应的移动卡片列表；
  `mobileMode = scroll` 保留内部横向滚动，不得隐藏桌面表格。共享 `V2Table` 在此断点统一解除数据、控制与操作列的固定位置，列宽和操作按钮保留，避免左右固定列覆盖手机数据区；恢复桌面宽度时自动恢复 schema 固定列。

### 2.3 全局列显示设置

- 每张登记过 schema 的 `V2Table` 统一提供“列设置”入口，业务页不得再实现单页专用的隐藏列逻辑。
- “列设置”不得单独占用一行工具栏；应与列表标题、本页数量和总数处于同一标题行，
  并位于“本页 / 总数”统计左侧。窄屏可在同一标题区内换行，但不得重新生成整宽独立行。
- 设置以“当前登录用户 + table schema id”隔离并写入数据库；页面刷新、重新登录或更换设备后必须重新从服务端恢复，不得把 `localStorage` 作为最终数据源。
- 只允许隐藏业务数据列；展开、选择、序号、操作等系统控制列不进入可隐藏清单。每张表至少保留一列数据列。
- `mobileMode = cards` 的移动卡片必须与桌面表格使用同一列 key 判定可见性；隐藏列后不得继续在移动端显示同一字段。
- 新增 schema 列默认可见，已删除或更名的旧 key 在客户端忽略；不得因历史偏好导致新列静默隐藏。
- 列设置抽屉必须覆盖搜索、全部显示、保存中、写入失败重试、恢复默认和未保存关闭保护；只有服务端写入成功后才能提示“已保存”。

### 2.4 中文界面语言

- 用户可见的标题、说明、标签、占位符、按钮、提示和装饰文字默认使用简体中文，禁止使用纯英文装饰标题。
- schema key、数据库字段名、接口字段名、枚举值和代码标识属于内部契约，不得直接渲染或作为用户可见搜索项；
  必须在 table schema 或展示层先映射为中文 `label`。
- 业务术语白名单只保留确有辨识意义的专有名词和缩写，例如 ID、Apple ID、API、MFA、IP、CIDR、
  QQ、WhatsApp、币种代码和支付平台品牌；新增白名单必须经过明确审查，不能用来绕过中文化。
- 新功能必须运行 `npm run check:v2-ui-language`；检查覆盖 Vue 模板、可见属性、脚本标题/标签/提示文案，
  以及直接展示内部字段名的行为，并在 CI 中阻止不合规变更。

### 2.5 跨模块对齐与稳定尺寸

- 同一视觉行中的“标题 + 值”必须复用相同的语义结构、字号、行高和垂直对齐模型；禁止一侧使用
  `flex + align-items: center`，另一侧使用 `grid + baseline` 等混合方案制造肉眼可见的基线偏差。
- 并排模块的标题线、首个内容行、底部操作区和状态指标必须建立共享对齐基准；只允许有业务含义的高度差，
  不允许通过单页 `margin-top`、空白占位或不一致内边距修补。
- 对齐验收必须测量实际文字节点的 `top`、`bottom`、`height` 和 `line-height`；父容器尺寸相同不能作为
  文字已经对齐的证据。
- 分页、筛选、空状态或数据条数变化不得改变主要模块外框高度。候选列表应使用稳定的最小高度、行轨道
  或内容占位保持框架尺寸，切换到最后一页时不得自动收缩。
- 多列表单中的文本域、帮助文字和错误提示不得单独撑高相邻列；需要扩展时应让整行共同增长，并复核左右
  字段的起止位置。
- 筛选器在中间宽度下必须为所有网格子项设置可收缩边界；日期范围、“更多筛选”和主操作按钮不得
  相互覆盖、裁切或溢出容器。
- 桌面端完成局部调整后必须复查整个页面，不得只检查被修改的组件；重点排查模块顶部不齐、底部不齐、
  文字基线偏移、分页跳动、按钮遮挡和窄屏横向溢出。

## 3. 表单强制规则

- 标签必须在控件左侧，所有 `el-form` 使用 `label-position="left"`。
- 禁止 `label-position="top"` 以及任何“标题在上、输入框在下”的等价实现。
- 标签与控件水平对齐，标签宽度在同一表单内保持一致。
- 页面与抽屉、弹窗的标签共用首行控件高度和居中规则；不得保留顶部标签的底部内边距。
  桌面默认控件与标签最小高度为 36px，窄屏为 44px；帮助文字、校验错误和文本域扩展时，
  标签仍对齐首行，不跟随整个内容区垂直居中。需要较大控件的表单使用 Element Plus 的 `size="large"`，
  桌面为 40px，窄屏仍为 44px；禁止在单页重写标签高度、字号、行高、颜色或对齐规则。
- 业务样式的颜色与阴影只能引用 `base.css` 中的主题令牌，不得另写固定调色板或颜色回退；
  复制、粘贴等操作同样复用 `AppButton` 的 normal、hover、active、focus、disabled 和 loading 状态，
  页面只负责位置和宽度，不维护第二套按钮皮肤。运行 `npm run check:v2-color-contrast` 检查规则。
- 业务选择器不得覆盖共享按钮的颜色、字号、字重、行高、圆角、边框颜色、阴影或动效；
  允许调整位置、宽度、换行和更大的点击目标，默认尺寸仍由公共皮肤控制。
- 业务查询、重试、复制、提交及任务控制按钮必须使用 `AppButton`，不得直接使用 `el-button`。
  `check:admin-ui` 对业务组件执行此门禁；原生按钮仅用于导航、页签、展开、条目选择和启动恢复等
  已有专用控件，并保留对应的键盘、焦点、中文名称与状态语义。
- 共享筛选与表单样式修改后运行 `node scripts/acceptance-v2-filter-layout.mjs`，
  测量实际标签文字与下拉值文字，并覆盖桌面、窄屏、列表首末页与空状态。
- 必填星号紧跟字段标题右侧，统一设置
  `require-asterisk-position="right"`，禁止星号出现在标题左侧。
- 窄屏可缩窄标签、允许标签换行或将多列折叠为单列，但标签仍在控件左侧。
- 错误提示靠近对应控件，不通过全局提示代替字段校验。
- 金额、日期、状态和敏感资料使用适合的数据控件，不用普通文本输入模拟。
- 新增功能的关闭、取消和导航离页默认只收起表单，保留会话内草稿；重新打开同一资料恢复输入。
  `V2FormDrawer` 与 `V2ConfirmDialog` 默认使用 `retain-draft`，父级通过 `useV2SessionDraft`／`useV2FormDraft` 管理草稿，
  搜索、筛选、排序、分页和页签也使用会话内草稿；不得在 `closed`、切页或重新打开时无条件清空。保存成功按提交快照清理对应草稿；明确的清空／恢复默认操作
  与关闭分开。草稿生命周期和敏感输入边界遵守 `V2_LOADING_STANDARD.md`。

### 3.1 提交与校验反馈

- 必填、格式、金额范围、日期关系等可修正错误不得用于禁用提交按钮。
- 用户点击提交后统一通过 `validateV2Form` 校验全部字段，提示“有 N 项需要处理”，并滚动、
  聚焦第一处错误；修正字段后由 `change` 或 `blur` 清除对应错误。
- 所有数据录入表单必须提供 `model`、`rules` 和字段 `prop`，并开启 `scroll-to-error`；
  错误文字紧邻控件，不能与下一行重叠。
- 权限不足、关联资料未加载、实体冻结、请求进行中或存在待完成业务等硬阻塞可以禁用按钮，
  但必须在按钮附近显示明确原因。
- `V2FormDrawer` 和 `V2ConfirmDialog` 的 `confirmDisabled` 仅用于兼容旧调用；业务表单应使用
  `confirmDisabledReason` 表达硬阻塞，禁止用它表达字段完整性或格式有效性。

## 4. 快捷新增

业务流程需要新增关联资料时，使用右侧抽屉：

1. 用户留在当前业务页面。
2. 抽屉复用正式创建接口、校验、权限和审计规则。
3. 保存成功后自动回填并选中新资料。
4. 刷新当前选择器数据并关闭抽屉。
5. 保存失败时保留输入内容并提供就地重试。

禁止为了新增客户、ID 或业务选项跳转到其他页面，也禁止在下拉菜单内塞入完整创建表单。

## 5. 状态与反馈

- 首次加载展示与内容形状一致的骨架。
- 刷新保留原内容，超过 120ms 后显示区域顶部进度线。
- 写操作只在按钮、当前行、抽屉或弹窗内显示 loading。
- 成功提示说明真实完成的动作；未写入数据库时不得显示“已保存”。
- 空状态必须在请求成功后显示。
- 错误状态保留可用内容，并提供明确重试动作。

## 6. 无障碍与响应式

- 输入框、图标按钮和状态必须有可读标签。
- 键盘可聚焦所有交互控件，焦点顺序与视觉顺序一致。
- 点击目标不小于 36px，移动端主要操作优先达到 44px。
- 颜色不是唯一状态提示，需同时使用文字或图标。
- 390px、768px、1024px 和 1440px 视口不得横向溢出或 UI 重叠。

### 6.1 前景与背景对比度

- 彩色背景必须使用配套的 `on-*` 前景令牌，主题切换时背景与前景必须成对切换。
- 禁止同一个颜色令牌同时作为实底背景和正文颜色，也禁止在共享交互组件中硬编码前景色。
- 按钮文字对比度不得低于 4.5:1；本系统的禁用按钮文字也必须达到该标准。
- 图标、边框和焦点指示不得低于 3:1，焦点状态必须有至少 2px 的清晰可见边界。
- 每个交互组件必须覆盖 normal、hover、active、focus、disabled 和 loading 状态。
- 需要用户核实风险的操作使用共享 `warning` 按钮变体，沿用 `--v3-warning-*` 主题色；
  禁用与加载继续复用统一状态，不得因改用共享按钮而丢失原有警示语义。
- 新增或修改主题色时，必须登记背景/前景组合并通过
  `npm run check:v2-color-contrast` 和 `npm run acceptance:v2-color-contrast`。
- `AppButton` 变体只能设置 Element Plus 的 `--el-button-*` 状态变量，禁止直接覆盖
  `color`、`background` 或 `border-color`，避免组件状态样式因加载顺序失效。

### 6.2 深浅主题契约

- 主题切换必须统一经过 `applyV2Theme`，同步维护 `data-v2-theme`、Element Plus 官方 `html.dark` 协议和
  浏览器原生 `color-scheme`，禁止业务模块直接操作其中任一标记。
- 浅色模式的顶部栏和页面概览模块必须使用 `--v3-topbar-*`、`--v3-overview-*` 语义令牌；
  内容区禁止直接复用 `--v3-sidebar` 或写死深色背景。深色侧栏和功能性预览画布不受此规则影响。
- 概览模块采用“浅冷灰外层 + 白色指标层 + 深色正文 + 蓝灰强调”的层级；模块背景、指标层、
  正文、次要文字、分隔线、交互状态和阴影必须成组切换，禁止只替换背景造成对比度失衡。
- Element Plus 的背景、文本、边框、填充、禁用、遮罩和阴影必须在全局主题桥接层映射到
  `--v3-*` 语义令牌；桥接选择器必须能抵抗按需组件样式后加载产生的 `:root` 浅色回退。
- 业务页面禁止为深色模式单独覆盖 Element Plus 组件背景，也不得通过页面选择器修补输入框、
  选择器、表格、分页、浮层、弹窗或抽屉颜色；缺失状态必须在全局主题令牌层解决。
- Teleport 到 `body` 的下拉菜单、日期面板、提示、弹窗和抽屉必须与页面主体使用同一主题，
  不得依赖 `.v2-shell` 后代选择器才能获得正确颜色。
- `base.css` 是主题令牌、兼容别名和基础组件皮肤的唯一来源。`--v2-*` 主题别名全局映射到
  `--v3-*`；不得靠浅色常量兜底掩盖未定义变量。`npm run check:v2-color-contrast` 同时检查缺失变量。
- 输入框、选择器、标签文字、数据表密度、状态标签和分页的公共规则使用 `html[data-v2-theme]`，
  页面与弹层共用；控件圆角引用 `--v3-radius-control`，默认高度 36px，900px 及以下为 44px。
  业务样式仅保留必要的排版与特定工作区密度，不重复定义主题色、公共字号或弹层替代皮肤。
- 修改公共皮肤后运行 `node scripts/acceptance-v2-skin-consistency.mjs`，实测页面与真实弹窗、抽屉的
  控件、文字位置、表格和状态标签，并覆盖深浅主题、断点两侧、错误、禁用和焦点状态。
- 基础弹层、关闭按钮、共享表单宽度、校验间距和表格单元格皮肤必须在 `base.css` 生效，
  不得依赖懒加载的 `v2.css`、`records.css` 或某个业务页面。登录页、独立工具和后台必须复用同一规则。
- 关闭按钮统一使用实际组件的类名（抽屉为 `.el-drawer__close-btn`），桌面目标至少 36px，
  900px 及以下至少 44px，必须具有悬停、按下和键盘焦点反馈。不得保留已失效的组件选择器。
- 同一选择器在相同媒体、容器和层条件下，每个属性只能定义一次；修改原始规则，禁止在文件末尾
  追加同值声明或互相覆盖的补丁。响应式条件和深浅主题的差异必须显式声明。
  `check:v2-color-contrast` 同时执行弹层归属与重复属性门禁，规则测试为
  `node --test scripts/admin-skin-rules.test.mjs`。
- 页面特有的位置、宽度和布局必须带自身业务容器范围，不能用公共类名覆盖全站。例如订单录入的
  禁用原因宽度只允许定义在 `.v2-order-entry-actions .v2-submit-disabled-reason` 下。
- 共享皮肤验收必须同时运行加载后台布局和仅加载基础皮肤的独立模式，并确认独立模式未请求
  `v2.css`；对比弹层真实头部、正文、页脚、关闭按钮和控件样式，避免验收夹具掩盖入口差异。
- 每次修改主题令牌或升级 Element Plus 后，必须在深浅主题的 1440px 和 390px 视口复测
  表单、表格、分页、标签、浮层、弹窗和抽屉，并运行 `npm run acceptance:v2-color-contrast`。

### 6.3 排版、图标、动效与层级

- 字体、默认字号、字重、行高和等宽数字以 `base.css` 的 `--v3-font-*`／`--v3-line-height-*`
  为准。正文和表单标签默认 13px，辅助文字 12px，说明性小字 11px，页面标题 18px；
  业务统计值可以体现不同的信息层级，但相同结构必须使用相同规格，不在单页修补文字基线。
- 表单、表格和操作按钮的字体不得另建皮肤。标题按 `h1/h2/h3` 的内容层级组织，长文本就地换行或
  提供完整值提示；金额与数量使用等宽数字，不能用空格和空白元素对齐。
- 图标沿用按需引入的 `@element-plus/icons-vue`，随语义文字继承主题色；纯装饰图标不进入键盘焦点，
  独立图标操作必须有中文可访问名称。品牌标识复用 `V2BrandLogo` 和品牌设置，不散落替代图片。
- 控件反馈、导航展开、区域进度和骨架动效分别由对应共享组件维护，业务页不复制这些动效。
  短交互沿用现有 120–220ms 反馈和 `--v3-ease`；加载不使用任意延时假装完成，进度与状态来自真实请求。
  必须尊重 `prefers-reduced-motion`，动效不得改变排版、遮挡操作或干扰输入。
- 弹窗、抽屉、确认框和浮层复用 Element Plus 的层级管理；区域进度只在本区域定位，
  侧栏与快捷工具留在应用壳层。禁止为解决遮挡不断加大 `z-index`、建立第二个全页遮罩或抬高业务内容。
- 禁止用负边距、空白节点或单页偏移修补标签与模块对齐；无障碍隐藏、装饰画布和边框拼接
  必须具有明确用途，不得把这些写法作为业务排版补丁。

## 7. 验收

- 检查所有表单标签位置和必填星号位置。
- 每次整页重设计必须在相同视口、相同数据和相同交互状态下保存修复前后截图，并将两张图放在同一对照图中复核。
- 在 1440px 桌面视口测量并排模块的 `top`、`bottom` 和 `height`；对同一行的标题和值额外测量文字节点，
  不得只测外框。
- 分别检查分页第一页、最后一页、空数据和长文本状态，确认页面框架不缩放、不跳动、不重叠。
- 检查抽屉、弹窗、固定列、底部操作区和移动端导航是否重叠。
- 检查所有权限组合下操作按钮不得被裁切，并覆盖 900px 桌面/移动断点两侧。
- 检查长文本、错误提示、空数据、慢请求和权限不足状态。
- 检查空表单可点击提交，全部字段错误同时出现，并能滚动、聚焦到第一处错误。
- 按第 7.1 节执行全局规则检查和受影响的专项验收，记录实际运行的命令、结果及未执行的条件。

### 7.1 新增页面必须复用的规则与验收

本节同样适用于新增抽屉、弹窗、移动卡片和已有页面新增的交互区。先确认规则所属的共享层，缺失能力在该层修复；不得复制一份页面专用皮肤、加载状态机或草稿机制。

| 范围           | 共享实现与要求                                                                                                                                                                                                                                         | 检查入口                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 页面与筛选布局 | `V2AdminLayout` 统一标题；普通列表用 `V2PageContext.filters`／`actions`，带标题的筛选用 `V2ListToolbar`，总览用 `V2PageOverview`／`V2OverviewMetric`；页面根容器用 `v2-page-layout`，模块间距由 `layout.css`／`V2AsyncRegion` 负责；空间足够保持一行。 | `check:admin-ui`；共享布局变更运行 `acceptance-v2-page-layout.mjs` 和 `acceptance-v2-filter-layout.mjs`。            |
| 皮肤与控件     | `base.css` 统一主题令牌、兼容别名、尺寸、圆角、文字和标签对齐；业务操作用 `AppButton`，下拉及 Teleport 弹层使用同一主题。                                                                                                                              | `check:v2-color-contrast`；共享皮肤变更运行 `acceptance-v2-skin-consistency.mjs` 和 `acceptance:v2-color-contrast`。 |
| 表格与中文     | `V2Table`、`V2TableColumn`、`V2TableActionColumn` 绑定登记的 schema，显示中文标签和统一操作列档位。                                                                                                                                                    | `check:v2-table-standard`、`check:v2-ui-language`；表格布局变更运行 `acceptance:v2-table-layout`。                   |
| 加载与刷新     | `useV2ModuleQuery` 管理读取，`V2AsyncRegion` 提供唯一主反馈；刷新保留内容，失败保留内容并可重试。                                                                                                                                                      | `check:v2-loading-standard`；查询交互变更运行 `acceptance-v2-refresh-interaction.mjs`。                              |
| 输入与切页     | `useV2SessionDraft`／`useV2FormDraft` 保留表单、搜索、筛选、排序、分页和页签；草稿按资料隔离，保存成功按提交快照清理。                                                                                                                                 | `check:v2-loading-standard` 内含输入保留检查；草稿交互变更运行 `acceptance-v2-input-retention.mjs`。                 |

新增或修改界面完成后，必须运行以下全局静态检查；精简前端 CI 也执行相同规则，不得借模块分类跳过。

```bash
npm run check:admin-ui
npm run check:v2-ui-language
npm run check:v2-color-contrast
npm run check:v2-table-standard
npm run check:v2-loading-standard
npm run check:v2-module-architecture
npm run check:v2-isolation
```

界面代码变更另外运行相关管理端测试、类型检查、lint 和构建。按实际修改运行表中的专项验收，
新页面自身必须补充真实路由的验收场景；现有共享脚本通过不能代替新页面验收。覆盖：

- 深浅主题；1440px、1024px、901px、900px、768px 和 390px；测量真实标签／控件文字，检查空间足够时单行、窄屏自然换行、无重叠溢出。
- 首次加载、已有内容刷新、失败重试、第一页、最后一页、空状态、长文本、禁用、焦点、权限不足以及弹层状态。
- 关闭重开、切页返回、记录切换、保存失败、成功清理、保存期间继续编辑、迟到响应及身份清理；具体行为遵守 `V2_LOADING_STANDARD.md`。

只修改规则文档或 CI 选择器时，运行受影响的控制检查与选择器测试即可；无需启动 API、数据库或重跑未受影响的业务验收。
