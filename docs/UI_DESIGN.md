# ID 业务管理系统 UI 规则

## 1. 设计目标

- 高密度后台界面保持清晰、稳定、可扫描。
- 相同业务结构复用相同组件和交互，不为单页制造特殊规则。
- 桌面端优先提高录入效率，移动端保证核心操作完整可用。
- 所有状态必须来自真实数据，不使用视觉占位冒充成功。

## 2. 页面结构

- 页面标题、帮助说明和主要操作位于同一标题行。
- 筛选区、数据区和分页区使用稳定的纵向顺序。
- 桌面表格在容器内滚动，关键状态与操作列可固定。
- 移动端使用信息卡列表，不把宽表格强行压缩。
- 页面不得出现互相覆盖的悬浮按钮、抽屉、固定底栏或双重滚动区。

### 2.1 表格操作列

- 桌面表格操作列统一使用 `V2TableActionColumn`，按 `icon`、`single`、`double`、`triple`
  或 `wide` 选择宽度档位；禁止页面自行编写固定操作列和任意宽度。
- manifest 的操作列宽度必须复用同一档位常量，不得与真实页面分别维护数值。
- 操作按钮不得被裁切、遮挡、挤出单元格或静默隐藏；桌面端保持单行，移动卡片允许自然换行。
- 禁止同时叠加 `gap` 与 Element Plus 相邻按钮默认边距，按钮间距只能由统一操作列组件控制。
- 操作超过当前档位容量时，应升级档位或使用带“更多操作”文字说明和可访问名称的菜单。
- 新增、删除或改名操作后，必须重新运行静态表格检查和多视口浏览器布局验收。

## 3. 表单强制规则

- 标签必须在控件左侧，所有 `el-form` 使用 `label-position="left"`。
- 禁止 `label-position="top"` 以及任何“标题在上、输入框在下”的等价实现。
- 标签与控件水平对齐，标签宽度在同一表单内保持一致。
- 必填星号紧跟字段标题右侧，统一设置
  `require-asterisk-position="right"`，禁止星号出现在标题左侧。
- 窄屏可缩窄标签、允许标签换行或将多列折叠为单列，但标签仍在控件左侧。
- 错误提示靠近对应控件，不通过全局提示代替字段校验。
- 金额、日期、状态和敏感资料使用适合的数据控件，不用普通文本输入模拟。

## 4. 快捷新增

业务流程需要新增关联资料时，使用右侧抽屉：

1. 用户留在当前业务页面。
2. 抽屉复用正式创建接口、校验、权限和审计规则。
3. 保存成功后自动回填并选中新资料。
4. 刷新当前选择器数据并关闭抽屉。
5. 保存失败时保留输入内容并提供就地重试。

禁止为了新增客户、ID 或业务选项跳转到其他页面，也禁止在下拉菜单内塞入完整创建表单。

## 5. 状态与反馈

- 首次加载展示与内容形状一致的骨架。
- 刷新保留原内容，超过 120ms 后显示区域顶部进度线。
- 写操作只在按钮、当前行、抽屉或弹窗内显示 loading。
- 成功提示说明真实完成的动作；未写入数据库时不得显示“已保存”。
- 空状态必须在请求成功后显示。
- 错误状态保留可用内容，并提供明确重试动作。

## 6. 无障碍与响应式

- 输入框、图标按钮和状态必须有可读标签。
- 键盘可聚焦所有交互控件，焦点顺序与视觉顺序一致。
- 点击目标不小于 36px，移动端主要操作优先达到 44px。
- 颜色不是唯一状态提示，需同时使用文字或图标。
- 390px、768px、1024px 和 1440px 视口不得横向溢出或 UI 重叠。

## 7. 验收

- 检查所有表单标签位置和必填星号位置。
- 检查抽屉、弹窗、固定列、底部操作区和移动端导航是否重叠。
- 检查所有权限组合下操作按钮不得被裁切，并覆盖 900px 桌面/移动断点两侧。
- 检查长文本、错误提示、空数据、慢请求和权限不足状态。
- 运行 `npm run check:admin-ui`、`npm run check:v2-loading-standard`、
  `npm run check:v2-table-standard`、`npm run acceptance:v2-table-layout` 和管理端构建。
