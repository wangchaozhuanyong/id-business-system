# 系统设置：汇率采集

本模块按 2026-11-07 用户确认的方案实现。入口为「系统设置 → 汇率采集」，位于费用规则旁，沿用独立新版页面、会话、管理员权限、加密文档、审计和变更通知。

## 页面

- 当前汇率：选择币种的兑人民币报价、来源、报价时间、最近采集时间、有效截止及有效／过期／缺少状态；支持历史报价、列设置和手动采集。
- 采集记录：自动、手动和订单取价分别记录；结果区分采集中、成功有更新、成功无变化、部分失败、失败。支持搜索、币种、方式、结果、北京时间日期与分页；详情保留错误和设置版本。
- 采集设置：来源、自动开关、来源更新／固定间隔、搜索多选币种、重试次数、报价及记录保留天数。变更记录保存修改人、时间、前后配置和版本，并可分页查看差异。
- 运行状态：近 7／30 天任务成功率、失败次数、耗时、连续失败、下次重试及冷却截止。页首展示状态、最近成功、实际计划时间与有效币种数。
- 各页签分别保留筛选和分页；设置草稿在切页、切页签后恢复。保存失败保留输入；迟到响应只清除对应提交快照，保留后续编辑。并发设置冲突需显式核对最新版本，不能自动覆盖。
- 使用说明位于标题或标签右侧，校验错误保留在控件下方。搜索多选为直接浮层，具有顶部搜索框。深浅主题及 1440／768／390／320 像素均沿用共享控件。

## 来源和调度

- 当前唯一可选来源为Fawaz Currency API 的固定 CNY 日报价（jsDelivr 主源、官方 Cloudflare 备援），免费、无需密钥、CC0-1.0 许可，不接收自定义 URL。
- 来源每天更新一次，只显示来源文字。最短固定间隔 60 分钟，默认下一 UTC 日更新；发布延迟时每小时检查。默认选择 USD、MYR、PHP、CLP、IDR、EGP，CNY 基准固定为 1。
- 既有运行入口已选择该来源时，默认恢复自动采集；原来未启用来源的环境仍保持关闭。管理员可以在此页面启用，无需新增环境变量或重启。暂停自动采集后，仍可查看历史或显式手动采集。
- 后台使用服务端单次定时任务，关闭浏览器后仍执行。配置、下次计划、失败次数、冷却和带期限的任务所有权都持久保存，重启恢复；不同实例以文档事务版本和任务所有权防止并发采集。
- 主源与备援共用 4 秒上限；失败按 1／5／15 分钟退避，最多配置 3 次重试。429 至少冷却 20 分钟；关闭重试也不会绕过冷却，订单取价和手动操作共用请求保护。
- 成功报价按来源 UTC 日零点起 36 小时截止。刚采到旧报价不更新报价发布时间或延长有效期。
- 相同来源、报价时点、截止及内容只保存一批报价，记录最近确认时间；每轮执行仍单独留痕。部分币种失败不覆盖以前的有效批次，订单不会拼接不同时点的报价。
- 页面使用已有变更通知局部读取。心跳或相同版本不重复读取；编辑期间保留草稿。另对已知报价到期安排一次边界检查，不使用周期性列表轮询。

## 订单兼容

订单取价优先查找覆盖订阅时点、包含本单及既有 CNY／MYR 统计所需币种的持久报价。没有匹配报价时，按配置尝试采集；仍缺失就保留待核算，不用当前报价冒充过去的报价。

自动快照新增可选 `quoteId`，引用确定的采集批次。保留原 `source`、`at`、`expiresAt`、`basisAt`、`fetchedAt` 及精确十进制汇率。已采集历史凭据可以为对应时点的旧订单补核算；自动路由在保存事务中重新核验凭据和订单版本。旧来源配置兼容映射到新来源且保留启停设置；旧报价和快照的来源、数值、编号与时点不改写。已有手工和自动快照兼容，已冻结快照继续禁止覆盖和删除。

取消采集某币种不移除历史报价；本单所需币种不足时明确待核算。新增其他币种需要同时扩展既有订单核算合同，本次不只添加一个无法核算的选择项。

## 持久化和清理

复用现有加密 `business_document`，增加内部文档范围 `finance-rates`。内容包括 `settings`、`settingChanges`、`quotes`、`runs` 和调度 `state`；创建和修改写原审计。没有新增 SQL 表、列、migration、依赖或环境变量，也没有向通用文档写入接口开放该范围。

报价默认保留 365 天、任务记录默认 90 天。超过期限的数据进入待清理预览，不在后台静默执行不可恢复删除。管理员核对数量后确认，才能清理过期非引用报价及已完成记录。预览限时 5 分钟；配置、采集文档或订单引用变化时，拒绝旧预览并要求重做。清理事务同时检查订单版本，不删除订单、订单快照、引用报价和设置变更记录。

保留期限允许报价 7–3650 天、采集记录 7–365 天；页面和服务端均校验范围。这里只规定采集资料保留，不修改订单原有保存规则。

## 接口与权限

新接口 `GET/POST /api/local/finance/collection`：

- GET：栏目、搜索、币种、结果、采集方式、日期和分页，返回当前范围版本、设置、运行状态与所选页数据。
- POST `settings`：配置版本和完整受控设置；只影响后续采集。
- POST `collect`：立即采集；复用同一运行中的请求和来源冷却保护。
- POST `cleanup-preview`：只读预览待清理范围。
- POST `cleanup`：显式确认、预览版本和范围凭证；拒绝变化后的旧预览。

读取和写入均沿用现有会话和管理员／超级管理员权限。写入要求同源 JSON，限制请求体；拒绝跨站和未知参数。员工看不到导航、页面和 `finance-rates` 版本。事件只传版本，错误不携带供应商原始响应、凭据或 Cookie。

## 验证边界

本地验证使用隔离测试数据与拦截请求的浏览器场景，不启动整套业务服务、Docker 或生产数据库。2026-11-11 只读连通检查确认新来源当日报价覆盖七种所需币种；浏览器业务回归继续使用固定替身。

- `test/finance-collection.test.mjs`：配置、币种、精度、去重、失败、限流、并发、后台调度、重启、历史核算、清理预览、引用保护和权限。
- `test/finance-collection.browser.mjs`：使用实际接口处理器与内存文档替身验证页面操作、草稿、迟到保存、冲突、变更历史、表格、员工限制、事件更新与响应式表现。
- 原财务核算、历史核对、迁移输入、前端静态规则和读取缓存检查继续执行；自动报价测试覆盖日期、有效期、精确倒数、固定备援、冷却、历史来源兼容和冻结不重算。
- 共享布局、长列表边界、手机导航、事件通知和成品选择器通过离线回归。
- `test/finance-collection-persistence.test.mjs` 包含真实 SQLite 事务保护及 HTTP 挂载测试，留给授权后的远端隔离 CI；未在本机运行。
