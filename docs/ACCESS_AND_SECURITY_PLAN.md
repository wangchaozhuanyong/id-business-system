# 人员权限与登录安全

使用规则、六种角色和验收口径已并入 [网站管理统一方案](SITE_FOUNDATION.md)。

## 上线配置与恢复

- 正式站可从账号文件同目录的 `local-auth.json.security.json` 读取以下同名配置。该文件只由运行账号持有，使用 0600 或 0400 权限。未提供文件时读取网站进程的私有环境变量。正式发布制品和仓库只保留示例字段。
- 网站进程从私有环境读取 `ID_TURNSTILE_SITE_KEY` 和 `ID_TURNSTILE_SECRET_KEY`。在 Cloudflare 控制台绑定实际登录域名。分别核对真实页面验证、无验证提交、失效、重复提交和服务不可用的反馈。服务端验证域名和 `login` 用途。应用在同一进程内记住已使用的令牌。正式域名尚未启用前，站内如实显示真人验证未启用。 [Cloudflare 服务端验证说明](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- 正式站可以直接绑定验证器。未提供独立的 `ID_AUTH_MFA_KEY` 时，验证器保护使用由现有业务库密钥派生的专用密钥。已有独立配置时继续使用原密钥，备份时将它保存在另外的受控位置。验证器绑定记录与账号文件同存。相关敏感管理操作始终要求绑定和再次确认。尚未绑定的超级管理员、管理员和财务仍可登录并进入「我的账号」绑定，绑定前无长期登录。更换密钥须走受控恢复或迁移流程。
- 启用 IP 白名单前，入口代理与网站进程配置同一个独立的 `ID_AUTH_TRUSTED_PROXY_KEY`，填写 64 位小写十六进制。目前网站只接收回环入口代理。入口必须覆盖来自访客的同名头，固定写入 `X-ID-Verified-Proxy` 和一个已核对的 `X-ID-Client-IP`。直连反代时取实际连接地址。如经过 Cloudflare 或另一层代理，先按入口配置验证上游来源并解析可信客户端地址。验证代理的回环监听、网站入口和后台长连接之后，再开启限制。
- 实际启用限制前，先在允许的公司网络上核对页面显示的当前地址，另外验证可独立登录服务器的运维账号。上线顺序为配置真人验证和加密密钥、由高权限人员绑定验证器、逐一检查六角色、再选择开启设备或网络限制。
- 离线恢复在站点运行账号下执行。`node server/recover-local-login.mjs --accounts <员工资料文件绝对路径> --action network --confirm RECOVER-LOGIN` 将网络限制暂停，名单继续保留。设备全部遗失时用 `--action device --employee <员工编号>` 清除该账号的设备限制并撤销原会话。验证器与恢复码均遗失时，经线下核验本人身份后用 `--action authenticator --employee <员工编号>` 重置该账号的验证器和设备许可。员工应重新登录、绑定验证器并登记设备。恢复记录显示在「登录安全」。启用前使用隔离副本演练。
- 真实恢复码由账号本人一次性保存。设备限制识别已批准的浏览器。清除浏览器站点资料或更换浏览器后须重新批准。验证码绑定在验证器内使用手动输入，登录时输入六位动态码或一个恢复码。使用恢复码进入后，五分钟内可凭当前密码重新绑定验证器。普通敏感操作使用动态码做安全确认。 [OWASP 两步验证说明](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)
