# ChatGPT 自动充值

当前管理端提供服务器充值与本机比特浏览器充值。服务器模式使用现有私网 Python Worker 和开源 Playwright Chromium，每笔任务独立启动并关闭 Chromium 进程，在其中新建隔离 BrowserContext；建窗前通过加密保存的 HTTPS 动态提取链接获取代理 IP，或使用固定代理。服务器模式支持授权 JSON、已保存 ChatGPT 账号或本次手填账号密码登录；银行卡和账单地址可选用系统资料或本次手填。代理必须从按国家保存的目录选择，停用或失效时在付款前停止。Worker 在官网核对账号、原单及最终报价，超过授权上限时停止；真实付款请求先留持久标记，成功证据通过后端现有规则写入银充订单。付款失败或结果不明不会自动补单或再次扣款，可对原任务发起只读复查。本机比特浏览器流程继续保留。

## 服务器模式（本地代码，未部署）

### 系统 2FA 自动验证

- 账号密码模式的“2FA 方式”支持“已保存账号”，列表复用系统工作区 2FA 功能，只展示当前用户的账号；选择本次 ChatGPT 账号对应的 2FA 后，无需手动查看、复制或填写当次验证码。
- 新充值与原单只读复查均在现有请求的 `login.totpAccountId` 中提交所选编号，与 `login.totpSecret` 互斥。API 按当前用户归属读取加密配置并记录使用审计；不存在、越权、解密失败或服务不可用时阻止任务。
- 配置只临时传给私网执行器，沿用已保存的算法、位数与周期；官网索取验证码时才生成并自动填写，临近过期时等待下一个周期。密钥与验证码不写入任务、审计或日志，也不返回管理端。
- “粘贴密钥”及“其他验证”继续保留；已保存 ChatGPT 账号仍使用该账号自身的 2FA。选择可随会话草稿保留，其他验证沿用人工处理；原单复查仍不发送新的付款请求。本次无新增接口、数据库表、字段或迁移。

### 代理目录与默认选择

- 国家、IP 属性、协议和链接统一在“代理 IP 管理”维护。动态提取可选 HTTP、HTTPS 或 SOCKS5；提取链接自身必须使用 HTTPS，代理连接协议按供应商提供的值选择。直连链接的协议必须与所选协议一致。
- “服务器默认代理”从目录中选择启用条目，按当前管理员保存编号；充值页自动带入对应国家和代理。默认值只负责带入，提交时使用充值页实际选中的条目。手动选择不会被默认设置刷新覆盖，点击“使用默认代理”可恢复默认选择。
- 未设置默认值时须手动选择。代理停用、删除、目录读取失败或与账号首次登录国家不符时，不放行服务器任务。账单地址变更不会静默替换已选代理。
- 默认设置与充值选择均可通过“查看完整链接”进入受审计详情，直接查看完整文字。链接仍加密保存；旧的独立设置保留，服务器页面不再维护第二份链接。
- 默认编号复用设置表现有 `browserOptions.serverDefaultProxyId` JSON 元数据；运行时浏览器参数会移除该元数据。本轮没有新增数据库表、字段或迁移。

1. 在“代理 IP 管理”新增或批量导入代理。动态模式每笔任务重新调用提取链接；登录前通过当前代理读取实际公网出口 IP 和国家，无法核实或与所选国家不符时停止。已记录首次登录国家的账号只能使用同国出口；若新提取的 IP 与上次登录相同，也停止并提示重新提取。服务器模式无需本机连接器、比特接口、分组或窗口名称。
2. 选择授权 JSON、已保存账号或手填账号密码。已保存账号只允许未开通过或已到期的记录进入新充值；需要 2FA 时，已保存密钥或本次输入密钥只在登录时取码。其他验证安全停止。选择套餐和锁定币种，再选所需国家的启用代理。代理国家与账单国家独立，菲律宾、日本等代理可以搭配美国账单地址；账单地址使用所选或手填资料，不随代理国家切换。套餐目录按 [2026-10-01 官方说明](https://learn.chatgpt.com/docs/pricing) 展示免费版、Go、Plus、Pro（100／200／500 美元月档）；本机与服务器自动充值菜单不展示 Business、Enterprise 和 Edu。自动充值支持 Plus、Pro 5×、Pro 20× 和 Pro（500 美元／月档），免费版和 Go 展示不可用原因。500 档已接入官网 Pro 三档控件、独立建单标识 `chatgptpromax` 与订阅类型 `promax`；100／200 档继续沿用现有内部编号与历史记录。银充订单仍可手工记录全部付费套餐并关联账号订阅，免费版无需付款，不进入银充记录。美元档位仅用于识别套餐，实际金额、币种与税费仍以官网结算为准。
3. 选择已保存银行卡或手填卡资料；地址库数据就绪后按现有规则自动选中并回填：排除停用项，优先未使用地址，再按最近使用时间、创建时间和编号排序。已保存卡首次成功付款后记住经核实的姓名与地址，下次选卡优先回填核实地址并拒绝不一致的资料；核实地址不可用时保持空选择，不静默换用其他地址。可通过下拉框手动改选，有效选项在刷新或导航返回时保留，读取失败不清理草稿；也可切为临时手填真实地址。地址可被不同订单复用，每次使用单独留痕；无姓名轮换或虚构账单地址。管理员按套餐和币种预设付款安全上限，未配置则不能启动服务器充值。提交时授权本任务在该上限内最多执行一次官网付款请求。
4. API 加密读取代理配置并把凭据临时发给私网 Worker；完整 JSON、登录密码、2FA 密钥、卡号、安全码和代理凭据不写入任务、审计或日志。页面在任务接收后清除临时凭据与卡资料。
5. Worker 为本次任务启动独立 Chromium 进程和 Context，登录前验证代理出口；官网身份核验成功后再次确认出口未变化，并按账号保存加密的首次 IP／国家及最近 IP／国家。此后同一账号允许同国换 IP，跨国或不能确认出口时禁止登录。继续核对官网会话、邮箱、原单和最终报价；无论成功或失败都关闭本次进程。最终报价的套餐、币种、税费、续费周期及今日应付必须明确，且今日应付不得超过授权上限；通过后自动执行一次付款。只有官网订阅激活及付款证据同时满足既有后端条件，才记录银充订单。
6. 遇到 403、真人验证、短信验证或银行 3DS，服务器模式安全停止或保留原单待核验，不绕过验证。结果未知时可在历史记录点“只读复查原订单”，重新提供原账号授权；系统复用原代理记录和原付款标记，只查询原付款与订阅证据。仍不明确时人工核对银行流水，不能直接发起新付款。
7. ChatGPT 账号清单显示订阅状态与到期时间，可筛选未记录开通、使用中、即将到期、已到期和到期待核实；充值任务历史与银充订单分别保留执行结果和经核实的付款结果。新充值只接受符合续费条件的已保存账号，不能把未知到期时间当作已到期。

500 美元档的标识与控件对应关系来自 2026-10-01 官网当前加载的公开前端代码：定价页在“选择 Pro 套餐档位”组内使用 100／200／500，结算页在 Pro 套餐组内使用 Standard／More usage／Max usage（标准／更多使用额度／最高使用额度）。执行器仅读取当前选中档位，未找到、重复或含糊时停止；不得按当地金额换算套餐，也不得将普通 `pro` 视为 500 档已激活。服务器需要单独配置该档与币种的安全上限，未配置不启动。一次建单、一次付款标记、金额核对与原单只读复查沿用现有保护。已用全部网络拦截的合成官网页面验证；本轮没有真实官网登录、建单、扣款或部署。

## 本机比特浏览器模式

## 操作流程

1. 点击主页面“修改代理 IP 与窗口设置”，在右侧抽屉保存 Local API 地址与密钥、本机连接密钥、动态 IP 提取或固定代理、窗口分组、标签，以及系统／语言／时区／定位／同步选项。主页面显示当前代理来源脱敏摘要与分组；秘密值留空保留，填写新值替换。设置保存后用于后续新建窗口，运行中的任务保留启动配置。保存失败保留输入，关闭时保护未保存内容。
2. 选择“授权 JSON”或“账号密码”。JSON 自动载入注册邮箱；账号密码模式由本次输入的邮箱填写账单邮箱，并选择本次 2FA 来源：粘贴 Base32 密钥／otpauth 链接、选择当前用户已保存的 2FA 账号，或选择其他验证。套餐默认为 ChatGPT Plus。官网入口固定为 `https://chatgpt.com`。两种登录方式都支持“仅登录窗口”和“自动充值”。
3. 账号密码模式先在本次比特窗口通过官网可见表单提交邮箱、密码；官网要求 TOTP 时，管理端复用现有 2FA 计算／已保存账号功能，取有效时间充足的当期代码，自动发往本机连接器并填入官网。自动取码失败时可重试或手动输入当次代码；邮箱／短信码和真人验证由本人在同一窗口完成。自动取码时须保持充值页面打开。官网会话的邮箱、用户与账户编号核对成功后，连接器才绑定账户并读取原单；邮箱不符立即停止。
4. 填写本次窗口名称、卡资料；地址库自动选中排序靠前的一条未使用地址，可下拉改选，导航返回保留仍可用的选择。核对与银行卡相符的真实账单地址，设定锁定币种和最高付款金额，再明确授权本任务最多发送一次官网付款请求。
5. 设置中的“窗口分组”和“窗口标签”从本机比特浏览器读取为可搜索下拉列表，支持刷新；空列表需在比特浏览器添加后再刷新。点击“连接比特浏览器并执行本次充值”后，连接器重新读取并核对所选名称唯一，创建窗口并加入所选分组，通过标签关联接口绑定所选标签，备注同步使用标签名称。分组／标签已删除、同名不唯一或标签绑定失败时停止，不擅自创建分组或标签。新窗口按已保存的代理模式连接；动态模式是否每次打开重新提取 IP 可单独设置。
6. 连接器核对官网账户、套餐、浏览器出口和当前订单，填写官网账单表单，读取官方最终金额。只有套餐、今日应付、税费、续费、周期、币种和订单绑定都明确，且币种与锁定值一致、金额不超上限时，才允许提交一次付款。
7. 遇到网页真人验证、邮箱／短信验证或银行 3DS 时，原浏览器窗口、IP 和订单保持不变，页面进入“等待本人验证”。本人在原窗口处理后点击“继续原任务”；系统不绕过验证、不新建订单、不重试付款。
8. 如果本机接收回执丢失，页面只查询原任务，不重发。确认未接收时安全结束并保留卡资料；已接收则继续观察原任务。
9. 付款结果不明时只能点击“只读复查原订单”，复查请求不包含卡资料、地址或付款授权；账号密码模式复查前需重新输入密码，并核对仍是原账户。

## 固定设置与付款边界

- 账单地区由现有地址库提供：`US / Portland / OR / 97204`；只有街道地址随本次选择变化。
- 新窗口默认浏览器与界面使用简体中文，时区和定位跟随代理 IP；这些选项以及操作系统、IP 查询服务和同步开关均可在设置抽屉修改。完整清单见 `docs/AUTO_RECHARGE_SETTINGS_PLAN.md`。
- 固定代理支持主机、端口与可选账号密码。账号密码需成对填写并加密保存，留空保留；勾选清除并保存后删除已存凭据。系统固定的官网入口、电脑设备类型、保存密码弹窗与窗口创建规则在抽屉底部显示。
- 账单地址不用于猜测币种；币种以当前官网／Stripe 绑定订单回执为准。与用户锁定币种不一致时安全停止。
- 本地只做通用 PAN 长度和 Luhn 校验，不限制卡组织、卡号开头或信用卡／借记卡。是否可用由官网支付页判断。
- JSON 或账号密码、当次验证码、完整卡号、有效期和安全码由当前页面直接发给 `127.0.0.1` 连接器，不进入生产 API 正文、数据库、审计或日志。临时粘贴的 2FA 密钥仅在管理端内存中用于现有 TOTP 计算，不发往 API 或本机连接器；已保存账号使用现有用户权限和服务端取码接口，接口不回传密钥。密码、临时密钥和验证码使用后清除页面或连接器中的引用；不写入比特浏览器窗口资料。页面离开、用户取消或观察到真实付款请求后清除卡资料；核价失败保留当前页面输入。保留窗口也保留其官网登录态，完成后须按业务需要退出或关闭窗口。
- 第一次真实付款请求前必须先把不可回退的原单标记回传 API；标记成功后才放行请求。此时地址立即标记已使用，包括付款结果未知。
- 付款结果不明时一律视为“原单待核验”，不能再选地址、再建单或再付款。

## 本机连接器

要求：当前电脑已启动比特浏览器并开启 Local API，安装 Python 3.11 或更高版本。连接器只监听 `127.0.0.1:55321`，只接受启动命令中允许的管理端 origin，并使用独立连接密钥。

```sh
npm run auto-recharge:connector -- --allowed-origin=https://管理端域名
```

首次启动会在已忽略的 `.runtime/auto-recharge-connector` 创建独立运行环境和权限为 `0600` 的连接密钥文件。使用该文件中的密钥配置网站设置，不要发送到聊天、提交到 Git 或写入日志。启动日志不再输出密钥。已安装为系统后台服务的连接器继续使用安装目录中原有的密钥文件，不另行生成或覆盖。

## 接口与存储

- `GET/PUT /api/id-business-v2/auto-recharge/bitbrowser-settings`：读取脱敏设置或加密更新设置。
- `GET/PUT /api/id-business-v2/auto-recharge/server-proxy-settings`：管理员读取或保存目录默认代理；写入只接受 `proxyId`（或 `null` 清除），再次校验条目启用状态并写审计，不返回完整链接或代理凭据。
- `GET/POST /api/id-business-v2/auto-recharge/proxies`、`GET /proxies/countries`、`GET/PATCH/DELETE /proxies/:id`、`POST /proxies/import`：管理员管理代理目录；完整链接仅在受审计详情中返回。充值任务提交 `proxyId` 与 `proxyCountryCode`，服务端再次检查国家和启用状态。
- `POST /api/id-business-v2/auto-recharge/bitbrowser-catalog-access`：仅管理员获取当前用户的本机连接凭据用于读取列表，禁止缓存并记录访问审计；不读取动态代理链接。
- 本机 `POST /browser/catalog`：沿用来源与连接密钥校验，仅调用比特 `/group/list` 和 `/browserTag/list`，只返回选项编号与名称。读取列表不创建、打开或修改任何窗口；新窗口标签绑定使用 `/browserTag/updateRelation` 的 `browserId / addTagIds / removeTagIds`。
- 本机 `POST /jobs/:id/code`：仅当前任务确实等待官网登录验证码时接收一次 6–8 位代码；管理端自动取码和手动兜底都使用此接口。代码不回传自动充值 API、日志或任务记录。本机连接器健康协议为第 3 版，增加 `password-login` 和 `login-code` 能力；管理端必须与本机连接器同步更新。
- `POST /api/id-business-v2/auto-recharge/jobs/bitbrowser`：建立脱敏本机任务，只接受套餐、地址编号、窗口名称、锁定币种、付款上限和单次授权。
- `POST /api/id-business-v2/auto-recharge/jobs/bitbrowser-recheck`：只为已尝试付款的原任务建立只读复查，不取新地址、不发付款。
- `POST /api/id-business-v2/auto-recharge/jobs/server-recheck`：只为原服务器任务的结果不明付款创建只读复查，沿用原账号、套餐及代理记录；请求仅含原任务编号和重新授权资料，不含银行卡或付款授权。
- `GET/PUT /api/id-business-v2/auto-recharge/payment-caps`：读取或按套餐与币种设置服务器付款安全上限；未配置时拒绝新任务，配置变更写审计。设置接口的具体路径为 `PUT /payment-caps/:plan/:currencyCode`。
- `POST /api/id-business-v2/auto-recharge/jobs/:id/bitbrowser-unreceived`：只能结束仍处于“等待本机接收”且付款请求为零的任务。
- `POST /api/id-business-v2/auto-recharge/local/:id`：本机连接器使用当任务一次性密钥回传脱敏进度、原单标记和结果。
- `IdBusinessV2RechargeBrowserSetting`：每个管理员的比特默认设置；连接密钥和动态提取链接只保存密文及掩码；窗口参数保存于 `browserOptions`，固定代理凭据只保存加密对象且查询仅返回已配置状态。
- `IdBusinessV2RechargeJob` 和 `IdBusinessV2RechargeRecord`：保存脱敏状态、原单证据和不可重复的付款标记。
- 新 migration：`apps/api/prisma-mysql/migrations/20260912180000_auto_recharge_bitbrowser_settings/migration.sql`，只新增设置表，不修改生产数据。
- 参数编辑新增 migration：`apps/api/prisma-mysql/migrations/20260913100000_auto_recharge_browser_options/migration.sql`，仅增加两个可空字段；旧记录沿用原默认值。迁移已在独立临时 MySQL 验证，生产未执行；发布时需同时更新 API、管理端和本机连接器。
- 分组与标签下拉修复复用已有 `groupName / tagName` 存储，无新增数据库字段和 migration。每次建窗通过当前列表重新解析编号，不以旧名称猜选；标签名称曾作为备注使用的旧设置，需要确认该名称对应真实存在的标签。
