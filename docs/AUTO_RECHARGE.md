# 本机比特浏览器自动充值

自动充值的当前代码主流程是：先只读检测连接器、比特接口及分组／标签，检测通过后管理端才创建脱敏任务，当前电脑上的本机连接器调用比特浏览器 Local API 创建窗口，再通过 Playwright CDP 在该窗口中使用授权 JSON 或账号密码登录并执行官网充值。管理端不再以服务器 Worker 作为新任务的主执行入口；原有记录和原单数据继续兼容，原有服务端接口只供旧记录恢复使用，新页面不再调用。

## 操作流程

1. 点击主页面“修改代理 IP 与窗口设置”，在右侧抽屉保存 Local API 地址与密钥、本机连接密钥、动态 IP 提取或固定代理、窗口分组、标签，以及系统／语言／时区／定位／同步选项。主页面显示当前代理来源脱敏摘要与分组；秘密值留空保留，填写新值替换。设置保存后用于后续新建窗口，运行中的任务保留启动配置。保存失败保留输入，关闭时保护未保存内容。
2. 选择“授权 JSON”或“账号密码”。JSON 自动载入注册邮箱；账号密码模式由本次输入的邮箱填写账单邮箱，并选择本次 2FA 来源：粘贴 Base32 密钥／otpauth 链接、选择当前用户已保存的 2FA 账号，或选择其他验证。套餐默认为 ChatGPT Plus。官网入口固定为 `https://chatgpt.com`。两种登录方式都支持“仅登录窗口”和“自动充值”。
3. 账号密码模式先在本次比特窗口通过官网可见表单提交邮箱、密码；官网要求 TOTP 时，管理端复用现有 2FA 计算／已保存账号功能，取有效时间充足的当期代码，自动发往本机连接器并填入官网。自动取码失败时可重试或手动输入当次代码；邮箱／短信码和真人验证由本人在同一窗口完成。自动取码时须保持充值页面打开。官网会话的邮箱、用户与账户编号核对成功后，连接器才绑定账户并读取原单；邮箱不符立即停止。
4. 填写本次窗口名称、卡资料，选择一条未使用地址，设定锁定币种和最高付款金额，再明确授权本任务最多发送一次官网付款请求。
5. 设置中的“窗口分组”和“窗口标签”从本机比特浏览器读取为可搜索下拉列表，支持刷新；空列表需在比特浏览器添加后再刷新。点击“连接比特浏览器并执行本次充值”后，连接器重新读取并核对所选名称唯一，创建窗口并加入所选分组，通过标签关联接口绑定所选标签，备注同步使用标签名称。分组／标签已删除、同名不唯一或标签绑定失败时停止，不擅自创建分组或标签。新窗口按已保存的代理模式连接；动态模式是否每次打开重新提取 IP 可单独设置。
6. 连接器核对官网账户、套餐、浏览器出口和当前订单，填写官网账单表单，读取官方最终金额。只有套餐、今日应付、税费、续费、周期、币种和订单绑定都明确，且币种与锁定值一致、金额不超上限时，才允许提交一次付款。
7. 遇到网页真人验证、邮箱／短信验证或银行 3DS 时，原浏览器窗口、IP 和订单保持不变，页面进入“等待本人验证”。本人在原窗口处理后点击“继续原任务”；系统不绕过验证、不新建订单、不重试付款。
8. 如果本机接收回执丢失，页面只查询原任务，不重发。确认未接收时安全结束并保留卡资料；已接收则继续观察原任务。
9. 付款结果不明时只能点击“只读复查原订单”，复查请求不包含卡资料、地址或付款授权；账号密码模式复查前需重新输入密码，并核对仍是原账户。

## 固定设置与付款边界

- 账单地区由现有地址库提供：`US / Portland / OR / 97204`；只有街道地址随本次选择变化。
- 新窗口默认浏览器与界面使用简体中文，时区和定位跟随代理 IP；这些选项以及操作系统、IP 查询服务和同步开关均可在设置抽屉修改。完整清单见 `docs/AUTO_RECHARGE_SETTINGS_PLAN.md`。
- 固定代理支持主机、端口与可选账号密码。账号密码需成对填写并加密保存，留空保留；勾选清除并保存后删除已存凭据。系统固定的官网入口、电脑设备类型、保存密码弹窗与窗口创建规则在抽屉底部显示。
- 账单地址不用于猜测币种；币种以当前官网／Stripe 绑定订单回执为准。与用户锁定币种不一致时安全停止。
- 本地只做通用 PAN 长度和 Luhn 校验，不限制卡组织、卡号开头或信用卡／借记卡。是否可用由官网支付页判断。
- JSON 或账号密码、当次验证码、完整卡号、有效期和安全码由当前页面直接发给 `127.0.0.1` 连接器，不进入生产 API 正文、数据库、审计或日志。临时粘贴的 2FA 密钥仅在管理端内存中用于现有 TOTP 计算，不发往 API 或本机连接器；已保存账号使用现有用户权限和服务端取码接口，接口不回传密钥。密码、临时密钥和验证码使用后清除页面或连接器中的引用；不写入比特浏览器窗口资料。页面离开、用户取消或观察到真实付款请求后清除卡资料；核价失败保留当前页面输入。保留窗口也保留其官网登录态，完成后须按业务需要退出或关闭窗口。
- 第一次真实付款请求前必须先把不可回退的原单标记回传 API；标记成功后才放行请求。此时地址立即标记已使用，包括付款结果未知。
- 付款结果不明时一律视为“原单待核验”，不能再选地址、再建单或再付款。

## 本机连接器

要求：当前电脑已启动比特浏览器并开启 Local API，安装 Python 3.11 或更高版本。连接器只监听 `127.0.0.1:55321`，只接受启动命令中允许的管理端 origin，并使用独立连接密钥。

```sh
npm run auto-recharge:connector -- --allowed-origin=https://管理端域名
```

首次启动会在已忽略的 `.runtime/auto-recharge-connector` 创建独立运行环境和权限为 `0600` 的连接密钥文件。使用该文件中的密钥配置网站设置，不要发送到聊天、提交到 Git 或写入日志。启动日志不再输出密钥。已安装为系统后台服务的连接器继续使用安装目录中原有的密钥文件，不另行生成或覆盖。

## 接口与存储

- `GET/PUT /api/id-business-v2/auto-recharge/bitbrowser-settings`：读取脱敏设置或加密更新设置。
- `POST /api/id-business-v2/auto-recharge/bitbrowser-catalog-access`：仅管理员获取当前用户的本机连接凭据用于读取列表，禁止缓存并记录访问审计；不读取动态代理链接。
- 本机 `POST /browser/catalog`：沿用来源与连接密钥校验，仅调用比特 `/group/list` 和 `/browserTag/list`，只返回选项编号与名称。读取列表不创建、打开或修改任何窗口；新窗口标签绑定使用 `/browserTag/updateRelation` 的 `browserId / addTagIds / removeTagIds`。
- 本机 `POST /jobs/:id/code`：仅当前任务确实等待官网登录验证码时接收一次 6–8 位代码；管理端自动取码和手动兜底都使用此接口。代码不回传自动充值 API、日志或任务记录。本机连接器健康协议为第 3 版，增加 `password-login` 和 `login-code` 能力；管理端必须与本机连接器同步更新。
- `POST /api/id-business-v2/auto-recharge/jobs/bitbrowser`：建立脱敏本机任务，只接受套餐、地址编号、窗口名称、锁定币种、付款上限和单次授权。
- `POST /api/id-business-v2/auto-recharge/jobs/bitbrowser-recheck`：只为已尝试付款的原任务建立只读复查，不取新地址、不发付款。
- `POST /api/id-business-v2/auto-recharge/jobs/:id/bitbrowser-unreceived`：只能结束仍处于“等待本机接收”且付款请求为零的任务。
- `POST /api/id-business-v2/auto-recharge/local/:id`：本机连接器使用当任务一次性密钥回传脱敏进度、原单标记和结果。
- `IdBusinessV2RechargeBrowserSetting`：每个管理员的比特默认设置；连接密钥和动态提取链接只保存密文及掩码；窗口参数保存于 `browserOptions`，固定代理凭据只保存加密对象且查询仅返回已配置状态。
- `IdBusinessV2RechargeJob` 和 `IdBusinessV2RechargeRecord`：保存脱敏状态、原单证据和不可重复的付款标记。
- 新 migration：`apps/api/prisma-mysql/migrations/20260912180000_auto_recharge_bitbrowser_settings/migration.sql`，只新增设置表，不修改生产数据。
- 参数编辑新增 migration：`apps/api/prisma-mysql/migrations/20260913100000_auto_recharge_browser_options/migration.sql`，仅增加两个可空字段；旧记录沿用原默认值。迁移已在独立临时 MySQL 验证，生产未执行；发布时需同时更新 API、管理端和本机连接器。
- 分组与标签下拉修复复用已有 `groupName / tagName` 存储，无新增数据库字段和 migration。每次建窗通过当前列表重新解析编号，不以旧名称猜选；标签名称曾作为备注使用的旧设置，需要确认该名称对应真实存在的标签。
