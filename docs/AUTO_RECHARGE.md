# 单账户自动充值

本模块由管理员从左侧“自动充值 → 自动充值”进入。输入获授权的完整 JSON，选择 Plus、Pro 5× 或 Pro 20×，先检查官网会话，再读取所选套餐的官方结算和实际币种。会话未恢复时返回原因并要求新的授权 JSON，不打开账号密码登录流程。

## 付款流程和边界

1. “开始检查”只读核对身份及服务器出口。网页验证或身份不一致会停止。
2. “获取官方报价”通过官网正常入口建单。同一账户和套餐已有本系统原单时只读取原单；官网实际提供的金额和币种决定报价。未知字段显示未知。
3. 填写本次 Visa 和持卡人真实账单资料，点击“填入官网并重新核价”。此时不提交付款。资料仅在 HTTPS 请求及执行器内存中使用，不写入数据库、审计或卡片库。
4. 官方完成地址和税费计算后显示今日应付、税费、续费及卡片尾号。勾选授权并点击包含实际金额的“确认开通”，服务器再次核对报价和账单后只提交一次。
5. 付款结果未知只能查询原订单。只有当前账户官方付款证据和目标套餐都核实，才显示开通成功。Pro 无法确认具体档位时保留待核验。

当前只支持单执行器、单账户、单笔任务，使用 AWS 当前出口，不提供代理、指纹轮换、随机账单、验证码求解或远程浏览器。遇到网页或银行验证会停止并回传原因，不能宣称所有 Visa 都无需验证。真实付款及订阅生效尚未验收，不能把本地测试、官方报价或发布成功当作充值成功。

页面离开后清除 JSON 与卡片资料。确认窗口最长五分钟，任务硬超时十五分钟；API 保留十六分钟租约。刷新或重启不会恢复秘密，也不会自动补扣。重新输入授权 JSON 后可“复查所选套餐原付款”；API 重启导致确认口令失效时先停止等待，再重新准备资料。未知结果不记为失败或零费用。

## 接口与持久化

- 管理员接口：`GET/POST /api/id-business-v2/auto-recharge/jobs`，`POST /jobs/:id/confirm`、`POST /jobs/:id/cancel`。
- 执行器回传：`POST /api/id-business-v2/auto-recharge/internal/:id`，使用独立私网密钥校验，不接受普通登录凭据代替。
- `IdBusinessV2RechargeJob`：操作人、套餐、步骤、受控状态、脱敏结果、确认口令摘要和租约。
- `IdBusinessV2RechargeRecord`：账户散列、归属操作人、原订单标记、付款证据、乐观版本。原单编号、已提交标记、报价摘要不可回退。完整结算链接不保存。
- migration：`apps/api/prisma-mysql/migrations/20260907010000_auto_recharge/migration.sql`，新增两表和数据 scope，不改旧表和人工流水。
- 所有官网建单和扣款请求前，执行器必须先取得 MySQL 标记持久化的确认。回传失败、数据库失败、超时或重复请求不触发自动重发。支出证据保留在独立原单记录，尚未接入人工收支报表或多币种汇总。

历史独立脚本的本机 `.state` 不属于此数据库，不自动复制或覆盖。已在其他执行环境尝试付款的账户不得在空记录的新环境再次付款；应先在原环境完成查单。迁移运行中的任务或历史标记需要单独核对原单及归属。

## 运行与发布

项目：ID 业务管理系统；Vue 3 / NestJS / Prisma MySQL / npm workspaces，沿用根 `package-lock.json`。

执行器位于 `apps/api/src/id-business-v2/auto-recharge/worker`，Python 3.12 容器使用固定 Playwright 1.62.0 及配套 Chromium，依赖锁定在 `requirements.lock.txt`。来源为本次已授权的独立订阅脚本，未修改参考开源项目。

新增环境配置：`AUTO_RECHARGE_WORKER_TOKEN`（至少 32 字符，API 与执行器共用独立密钥）、`AUTO_RECHARGE_WORKER_URL`、执行器内的 `AUTO_RECHARGE_CALLBACK_URL`。示例只含占位值。首次正式安装在新发布目录的既有生产环境文件中生成随机密钥，不输出，不更改旧发布目录。

生产 Compose 的 `auto-recharge` 服务不开放宿主机端口，仅连接独立控制私网和执行器出口网络。非 root、只读文件系统、临时目录 tmpfs、`init`、无额外 capabilities，内存及交换合计限制 640 MB；不增购或调整云实例。私网 `GET /health` 返回 `ok` 和 `busy`，忙碌时发布安装器停止，不打断正在处理的付款。

正式发布沿用 `docs/DEPLOYMENT.md` 的 PR、CI、不可变制品、S3 校验备份、向前迁移、财务门禁和原子切换。制品新增第六个执行器镜像，并记录 digest。回滚复用上一版镜像；上一版没有执行器时停止新增服务。两张新表保留以供查单，不自动删除或回滚数据。

## 验证命令

### 套餐菜单识别与诊断

2026-09-07 在现有 AWS 执行器的同版本浏览器、当前网络中只读核对：官网默认呈现 Business，
个人套餐切换为 `radio`，名称为 `Toggle for switching to Personal plans`；切换后出现
`Upgrade to Plus`、`5x`、`20x` 和 `Upgrade to Pro`。探测期间建单和付款请求均为零。

套餐选择共用菜单开启步骤，Plus 与 Pro 独立定位；支持已观察的个人套餐 radio 及已有中文入口，
识别可见 dialog 或页面 main 内唯一的目标控件。每步最多 30 秒、整体最多 90 秒，只允许重开一次
未加载的菜单；不重试建单、改币种或自动选择其他档位。

现有任务结果新增可选 `diagnostics`，仅含受控的步骤、异常类型、控件角色、匹配数、启用／选中状态
和识别出的套餐枚举。Python 与 API 各自白名单校验，兼容没有该字段的旧记录；不增加接口、数据库
表、migration、依赖或环境配置，不保存异常正文、DOM、凭据或完整网络记录。
页面区分待获取、正在获取、获取失败及报价内的未知字段，并在选套餐、等待结算、读价时回传进度。
“已识别选项”仅表示菜单控件存在；是否能购买仍需成功取得对应账号的官方结算与报价。

```sh
npm run check
npm run acceptance:v2-financial-integrity
npm run acceptance:v2-auto-recharge
npm run git:readiness
```

页面验收只使用本机隔离的合成账户和测试卡，覆盖 1440、768、390 像素、空状态、会话核对、实际报价、资料清除、明确确认一次、未知结果和错误。数据库验收在可丢弃 MySQL 容器中覆盖并发、版本冲突及服务重启后的原单恢复。执行器镜像测试覆盖会话、身份、币种、地址、报价变化、付款请求阻断、验证、拒付、超时与套餐延迟。本轮交付不执行真实扣款，也不打包桌面端。
