# 单账户自动充值

本模块由管理员从左侧“自动充值 → 自动充值”进入。输入获授权的完整 JSON，选择 Plus、Pro 5× 或 Pro 20×，按“获取初始报价 → 填写官网并计算最终金额 → 确认充值”分步执行。粘贴或导入 JSON 只做本地格式校验，不自动启动浏览器。会话未恢复时返回原因并要求新的授权 JSON，不打开账号密码登录流程。

## 付款流程和边界

1. 载入 JSON 只保存在当前页面内存；只有明确点击“获取初始报价”才启动 Worker，核对账户、套餐、服务器出口和官网初始金额。
2. 初始报价可以明确显示“需填写账单地址后确定税费”。Worker 保持同一个浏览器会话等待后续资料，不重新建单或重选套餐。
3. 填写本次银行卡和账单资料，点击“填写官网并计算最终金额”。此时不提交付款。本地只校验卡号格式和 Luhn，信用卡／借记卡及卡组织是否可用由官网支付页决定。资料仅在 HTTPS 请求、当前页面和 Worker 内存中使用，不写入数据库、审计或卡片库。
4. 官网完成地址和税费计算后，只有页面金额连续两次稳定且与当前订单的 Stripe 初始化响应金额、币种一致，才显示今日应付、明确税费（免税为 `0`）、续费、周期、币种和订单编号。账单国家不用于猜测币种。
5. 用户核对完整最终报价后，只能明确点击一次“确认充值”。失焦、字段变化和轮询都不会自动填表或自动付款。
6. 付款结果未知只能查询原订单。只有当前账户官方付款证据和目标套餐都核实，才显示开通成功。Pro 无法确认具体档位时保留待核验。

当前只支持单执行器、单账户、单笔任务，使用 AWS 当前出口，不提供代理、指纹轮换、随机账单、验证码求解或远程浏览器。遇到网页或银行验证会停止并回传原因，不能宣称所有银行卡都能付款或无需验证。真实付款及订阅生效尚未验收，不能把本地测试、官方报价或发布成功当作充值成功。

页面离开后清除 JSON 与卡片资料。卡号、有效期和安全码在 Worker 接收、填写及安全失败后均保留在当前页面；只在官网表单填写成功且最终报价稳定、用户取消，或确认付款已受理后清除。确认凭据由“任务编号＋最终报价”的 HMAC 确定性生成，API 重启后可重建，数据库仍只保存摘要。刷新或重启不会恢复秘密，也不会自动补扣。未知结果不记为失败或零费用。

## 接口与持久化

- 管理员接口：`GET/POST /api/id-business-v2/auto-recharge/jobs`，`POST /jobs/:id/details`、`POST /jobs/:id/confirm`、`POST /jobs/:id/cancel`。
- 执行器回传：`POST /api/id-business-v2/auto-recharge/internal/:id`，使用独立私网密钥校验，不接受普通登录凭据代替。
- `IdBusinessV2RechargeJob`：操作人、套餐、步骤、受控状态、脱敏结果、确认口令摘要和租约。
- `IdBusinessV2RechargeRecord`：账户散列、归属操作人、原订单标记、付款证据、乐观版本。原单编号、已提交标记、报价摘要不可回退。完整结算链接不保存。
- migration：`apps/api/prisma-mysql/migrations/20260907010000_auto_recharge/migration.sql`，新增两表和数据 scope，不改旧表和人工流水。
- 所有官网建单和扣款请求前，执行器必须先取得 MySQL 标记持久化的确认。启动、资料或确认请求超时时，API 只查询 Worker 是否已接收，不重发写请求。第一次官网付款请求发出后立即将地址标记已使用，包括付款结果未知；只填表和核价不消耗地址。支出证据保留在独立原单记录。

历史独立脚本的本机 `.state` 不属于此数据库，不自动复制或覆盖。已在其他执行环境尝试付款的账户不得在空记录的新环境再次付款；应先在原环境完成查单。迁移运行中的任务或历史标记需要单独核对原单及归属。

## 运行与发布

项目：ID 业务管理系统；Vue 3 / NestJS / Prisma MySQL / npm workspaces，沿用根 `package-lock.json`。

执行器位于 `apps/api/src/id-business-v2/auto-recharge/worker`，Python 3.12 容器使用固定 Playwright 1.62.0 及配套 Chromium，依赖锁定在 `requirements.lock.txt`。来源为本次已授权的独立订阅脚本，未修改参考开源项目。

新增环境配置：`AUTO_RECHARGE_WORKER_TOKEN`（至少 32 字符，API 与执行器共用独立密钥）、`AUTO_RECHARGE_WORKER_URL`、执行器内的 `AUTO_RECHARGE_CALLBACK_URL`。示例只含占位值。首次正式安装在新发布目录的既有生产环境文件中生成随机密钥，不输出，不更改旧发布目录。

生产 Compose 的 `auto-recharge` 服务不开放宿主机端口，仅连接独立控制私网和执行器出口网络。非 root、只读文件系统、临时目录 512 MB tmpfs、256 MB shm、`init`、无额外 capabilities；物理内存限制 1 GB，额外 Swap 限制 512 MB，内存与 Swap 总上限 1.5 GB，不增购或调整云实例。私网 `GET /health` 返回 `ok` 和 `busy`，忙碌时发布安装器停止，不打断正在处理的付款。

执行器在每个任务开始和结束时读取 cgroup v2 `memory.events` 的 `oom_kill`。本任务计数增加时统一返回 `browser_memory_exhausted`，保留已有阶段和请求计数，不自动重试、建单或付款。官网 403 或真人验证页统一安全停止，不绕过验证，不接代理、验证码服务或私有结算接口。

两张新表保留以供查单，不自动删除或回滚数据。
